# 1. Was ist eine grafische Benutzeroberfläche?

Bis jetzt liefen viele Programme nach einem ähnlichen Muster:

```text
1. Programm startet.
2. Programm gibt eine Frage aus.
3. Benutzer gibt etwas ein.
4. Programm verarbeitet die Eingabe.
5. Programm gibt ein Ergebnis aus.
6. Programm endet.
```

Zum Beispiel:

```python
name = input("Name: ")

print(f"Hallo {name}!")
```

Das ist eine klassische Konsolenanwendung.

Eine **grafische Benutzeroberfläche** – kurz **GUI** für *Graphical User Interface* – funktioniert anders.

Eine GUI besteht aus grafischen Elementen wie:

- Fenstern,
- Beschriftungen,
- Textfeldern,
- Buttons,
- Checkboxen,
- Listen,
- Menüs,
- Zeichenflächen.

Der Benutzer interagiert mit diesen Elementen.

---

# 2. Von linearer zu ereignisgesteuerter Programmierung

Bei einer Konsolenanwendung bestimmt das Programm meist direkt die Reihenfolge.

```text
Programm fragt
→ Benutzer antwortet
→ Programm verarbeitet
```

Bei einer GUI ist die Reihenfolge viel weniger vorhersehbar.

Der Benutzer kann beispielsweise:

```text
zuerst etwas eingeben,
dann auf einen Button klicken,
danach das Fenster vergrößern,
dann erneut den Text ändern,
anschließend einen anderen Button klicken.
```

Die GUI wartet deshalb auf **Ereignisse**.

Beispiele für Ereignisse:

- Button wird geklickt,
- Taste wird gedrückt,
- Maus wird bewegt,
- Text wird geändert,
- Fenster wird geschlossen,
- Auswahl in einer Liste wird verändert.

Das Programm reagiert auf diese Ereignisse.

Dieses Programmiermodell nennt man **ereignisgesteuerte Programmierung**.

---

# 3. Was ist Tkinter?

`tkinter` ist die Python-Schnittstelle zum GUI-Toolkit **Tk**.

Es gehört bei vielen normalen Python-Installationen zur Standardbibliothek.

Ein zusätzlicher Python-Paket-Import mit `pip` ist daher normalerweise nicht notwendig.

Je nach Betriebssystem und Python-Installation kann es aber vorkommen, dass die Tk-Unterstützung separat installiert werden muss.

Ein schneller Test ist:

```python
import tkinter

print(tkinter.TkVersion)
```

Wenn der Import funktioniert, ist Tkinter grundsätzlich verfügbar.

# 5. Was bedeutet `tk.Tk()`?

```python
root = tk.Tk()
```

erzeugt das **Hauptfenster** der Anwendung.

`root` ist eine Referenz auf ein Objekt der Klasse `Tk`.

Das knüpft direkt an die vorherigen Kapitel an:

```text
tk.Tk
→ Klasse

root
→ Variable

erzeugtes Fenster
→ Objekt / Instanz
```

Das Fenster besitzt Methoden wie:

```python
root.title(...)
root.geometry(...)
root.mainloop()
root.destroy()
```

---

```python
root.title("Meine erste GUI")
```

setzt den Titel des Fensters.

Zum Beispiel:

```python
import tkinter as tk


root = tk.Tk()

root.title("Messwertverwaltung")

root.mainloop()
```

# 7. Die Hauptschleife `mainloop()`

Die Zeile

```python
root.mainloop()
```

ist für eine Tkinter-Anwendung zentral.

Sie startet die **Ereignisschleife**.

Vereinfacht arbeitet Tkinter danach so:

```text
solange das Fenster existiert:

    auf Ereignis warten

    Ereignis erkennen

    passende Callback-Funktion ausführen

    Oberfläche aktualisieren

    wieder auf Ereignis warten
```

Ohne `mainloop()` würde das Programm normalerweise sofort das Ende erreichen und die GUI könnte nicht dauerhaft auf Benutzereingaben reagieren.

# 8. Ein Button

Wir ergänzen einen Button:

```python
import tkinter as tk


def button_click() -> None:
    print("Button wurde geklickt!")


root = tk.Tk()

root.title("Button-Beispiel")

button = tk.Button(
    root,
    text="Klick mich!",
    command=button_click
)

button.pack()

root.mainloop()
```

Nun reagiert das Programm auf einen Klick.

# 10. Parent bzw. übergeordnetes Widget

Beim Erzeugen eines Widgets wird meistens angegeben, **wo** dieses Widget liegen soll.

```python
button = tk.Button(
    root,
    text="Klick mich!"
)
```

Das erste Argument:

```python
root
```

ist das übergeordnete Widget.

Vereinfacht:

```text
root
└── button
```

Später können wir mit `Frame` mehrere Ebenen aufbauen:

```text
root
└── frame
    ├── label
    ├── entry
    └── button
```

# 11. Callback-Funktion

Die Funktion:

```python
def button_click() -> None:
    print("Button wurde geklickt!")
```

wird nicht direkt von unserem linearen Programmcode aufgerufen.

Stattdessen übergeben wir sie an den Button:

```python
command=button_click
```

Wenn der Benutzer später klickt, ruft Tkinter die Funktion auf.

Eine Funktion, die auf ein Ereignis reagiert, nennt man **Callback-Funktion**.

---

# 12. Sehr wichtiger Unterschied: Funktion übergeben oder aufrufen

Richtig:

```python
command=button_click
```

Hier wird die Funktion als Objekt übergeben.

Falsch für diesen Zweck:

```python
command=button_click()
```

Hier wird die Funktion bereits beim Erzeugen des Buttons ausgeführt.

Der Rückgabewert der Funktion würde dann als `command` verwendet.

Merksatz:

```text
command=funktion
→ später beim Ereignis aufrufen

command=funktion()
→ jetzt sofort aufrufen
```

# 16. Was passiert beim Klick?

Der Ablauf:

```text
1. GUI wird aufgebaut.

2. mainloop() startet.

3. Benutzer schreibt beispielsweise:
   Anna

4. Benutzer klickt auf „Begrüßen“.

5. Tkinter ruft begruessen() auf.

6. entry.get() liefert:
   "Anna"

7. label.config(...) verändert den Text.

8. Callback endet.

9. GUI wartet wieder auf das nächste Ereignis.
```

Das Programm endet also nicht nach einem Klick.

Die Ereignisschleife läuft weiter.

# 17. Widgets verändern

Viele Eigenschaften eines Widgets können später verändert werden.

Beispiel:

```python

    text="Neuer Text"
)
```

Auch:

```python
button.config(
    state="disabled"
)
```

kann beispielsweise einen Button deaktivieren.

Man verändert dabei ein bereits existierendes Widget-Objekt.

Das knüpft an Referenzen und mutierbare Objekte an:

```text
label
→ Referenz auf ein Label-Objekt

label.config(...)
→ Zustand des Objekts wird verändert
```

# 20. Layout: Widgets müssen angeordnet werden

Ein Widget existiert nicht automatisch sichtbar an einer sinnvollen Position.

Tkinter verwendet **Geometry Manager**.

Die wichtigsten sind:

```text
pack()
grid()
place()
```

Sie bestimmen die Position und Größe der Widgets innerhalb ihres Parent-Widgets.

---

# 21. `pack()`

`pack()` eignet sich gut für einfache Layouts.

```python
label.pack()
entry.pack()
button.pack()
```

Die Widgets werden hier nacheinander angeordnet.

Optionen:

```python
button.pack(
    padx=10,
    pady=10
)
```

`padx` und `pady` erzeugen Abstand.

---

# 22. `grid()`

Für Formulare ist `grid()` häufig übersichtlicher.

Beispiel:

```python
import tkinter as tk
from tkinter import ttk


root = tk.Tk()

root.title("Person")

ttk.Label(
    root,
    text="Name:"
).grid(
    row=0,
    column=0
)

name_entry = ttk.Entry(root)

name_entry.grid(
    row=0,
    column=1
)

ttk.Label(
    root,
    text="Alter:"
).grid(
    row=1,
    column=0
)

alter_entry = ttk.Entry(root)

alter_entry.grid(
    row=1,
    column=1
)

root.mainloop()
```

Das Layout ist tabellenartig:

```text
Zeile 0:
Name:    [________]

Zeile 1:
Alter:   [________]
```

---

# 23. Abstände mit `grid()`

```python
widget.grid(
    row=0,
    column=0,
    padx=5,
    pady=5
)
```

Für eine bessere Ausrichtung kann zusätzlich verwendet werden:

```python
sticky="w"
```

`w` steht für *west*, also links.

Andere Richtungen:

```text
n
s
e
w
```

können kombiniert werden.

---

# 24. `place()`

`place()` erlaubt eine sehr genaue Positionierung.

Beispiel:

```python
button.place(
    x=100,
    y=50
)
```

Für einfache Demonstrationen ist das möglich.

Bei normalen Anwendungen ist `place()` oft weniger flexibel, weil feste Pixelpositionen schlecht auf:

- andere Fenstergrößen,
- andere Schriftgrößen,
- andere Betriebssysteme

reagieren.

Darum werden meist `pack()` oder `grid()` bevorzugt.

---

# 25. `pack()` und `grid()` nicht im selben Parent mischen

Ein wichtiger Tkinter-Grundsatz:

> Verwende innerhalb desselben Parent-Widgets nicht gleichzeitig `pack()` und `grid()` für dessen direkte Kinder.

Problematisch:

```text
root
├── label  → pack()
└── button → grid()
```

Dagegen ist das hier völlig in Ordnung:

```text
root
└── frame → pack()
    ├── label  → grid()
    └── button → grid()
```

Denn `root` verwaltet nur den `frame` mit `pack()`.

Der `frame` verwaltet seine eigenen Kinder mit `grid()`.

# 27. Durchgehendes Beispiel: Messwert-Rechner

Wir entwickeln nun schrittweise eine kleine Anwendung.

Sie soll:

1. eine Temperatur in Celsius einlesen,
2. sie in Fahrenheit umrechnen,
3. das Ergebnis anzeigen,
4. ungültige Eingaben behandeln.

Die Fachlogik kennen wir bereits.

```python
def celsius_zu_fahrenheit(
    celsius: float
) -> float:
    return celsius * 1.8 + 32
```

Diese Funktion hat nichts mit Tkinter zu tun.

Das ist gut.

# 28. Fachlogik und GUI trennen

Die Berechnung:

```python
def celsius_zu_fahrenheit(
    celsius: float
) -> float:
    return celsius * 1.8 + 32
```

kann unabhängig getestet werden.

Die GUI übernimmt nur:

```text
Eingabe lesen

Eingabe umwandeln

Funktion aufrufen

Ergebnis anzeigen
```

Diese Trennung macht Programme leichter:

- testbar,
- verständlich,
- wartbar.

# 29. Erste Version des Temperatur-Rechners

```python
import tkinter as tk
from tkinter import ttk


def celsius_zu_fahrenheit(
    celsius: float
) -> float:
    return celsius * 1.8 + 32


def umrechnen() -> None:
    celsius = float(
        celsius_entry.get()
    )

    fahrenheit = celsius_zu_fahrenheit(
        celsius
    )

    ergebnis_label.config(
        text=f"{fahrenheit:.1f} °F"
    )


root = tk.Tk()

root.title("Temperatur-Rechner")

frame = ttk.Frame(
    root,
    padding=10
)

frame.pack()

ttk.Label(
    frame,
    text="Celsius:"
).grid(
    row=0,
    column=0,
    padx=5,
    pady=5
)

celsius_entry = ttk.Entry(frame)

celsius_entry.grid(
    row=0,
    column=1,
    padx=5,
    pady=5
)

button = ttk.Button(
    frame,
    text="Umrechnen",
    command=umrechnen
)

button.grid(
    row=1,
    column=0,
    columnspan=2,
    pady=5
)

ergebnis_label = ttk.Label(
    frame,
    text=""
)

ergebnis_label.grid(
    row=2,
    column=0,
    columnspan=2,
    pady=5
)

root.mainloop()
```

# 30. Problem: ungültige Eingabe

Der Benutzer könnte eingeben:

```text
abc
```

Dann schlägt diese Zeile fehl:

```python
float(
    celsius_entry.get()
)
```

Python löst einen:

```text
ValueError
```

aus.

Wenn wir ihn nicht behandeln, entsteht ein Traceback in der Konsole.

Das Fenster selbst kann je nach Situation weiterlaufen, aber für den Benutzer ist das keine gute Fehlerbehandlung.

---

# 31. Exceptions in einer GUI behandeln

Wir können die Exception dort behandeln, wo wir sinnvoll reagieren können:

```python
def umrechnen() -> None:
    try:
        celsius = float(
            celsius_entry.get()
        )

    except ValueError:
        ergebnis_label.config(
            text="Bitte eine gültige Zahl eingeben."
        )

        return

    fahrenheit = celsius_zu_fahrenheit(
        celsius
    )

    ergebnis_label.config(
        text=f"{fahrenheit:.1f} °F"
    )
```

Hier bleibt die Anwendung geöffnet.

Der Benutzer kann seine Eingabe korrigieren.

# 36. Warum Tkinter-Variablen?

Tkinter-Variablen sind besonders nützlich, wenn mehrere Widgets denselben Zustand verwenden.

Beispiel:

```python
import tkinter as tk
from tkinter import ttk


root = tk.Tk()

name_var = tk.StringVar(
    value="Anna"
)

entry = ttk.Entry(
    root,
    textvariable=name_var
)

entry.pack()

label = ttk.Label(
    root,
    textvariable=name_var
)

label.pack()

root.mainloop()
```

Wenn sich der Inhalt der Variable ändert, können verbundene Widgets automatisch aktualisiert werden.

# 41. Tastaturereignisse mit `bind()`

`command=` eignet sich für viele Standardaktionen wie Button-Klicks.

Für allgemeinere Ereignisse gibt es:

```python
widget.bind(...)
```

Beispiel:

```python
import tkinter as tk
from tkinter import ttk


def enter_gedrueckt(event: tk.Event) -> None:
    print("Enter wurde gedrückt.")


root = tk.Tk()

entry = ttk.Entry(root)

entry.pack()

entry.bind(
    "<Return>",
    enter_gedrueckt
)

root.mainloop()
```

---

# 42. Callback bei `bind()` erhält ein Event-Objekt

Bei:

```python
command=callback
```

erhält die Callback-Funktion normalerweise keine Event-Argumente.

Bei:

```python
widget.bind(...)
```

wird ein Event-Objekt übergeben.

Darum:

```python
def enter_gedrueckt(
    event: tk.Event
) -> None:
    ...
```

Das Event-Objekt enthält Informationen über das Ereignis.

---

# 43. Ein Event an mehrere Aktionen binden

Ein Eingabefeld könnte sowohl über:

```text
Button-Klick
```

als auch über:

```text
Enter-Taste
```

ausgewertet werden.

Wir können dafür eine gemeinsame Funktion verwenden:

```python
def umrechnen() -> None:
    ...
```

Beim Button:

```python
command=umrechnen
```

Beim `bind()` braucht die Callback-Funktion aber ein Event-Argument.

Eine kleine Adapterfunktion ist klar:

```python
def enter_gedrueckt(
    event: tk.Event
) -> None:
    umrechnen()
```

# 47. Warum lange Berechnungen problematisch sind

Die Tkinter-Ereignisschleife verarbeitet:

- Klicks,
- Tastatur,
- Fensterupdates,
- Callbacks

normalerweise im selben GUI-Thread.

Angenommen:

```python
def button_click() -> None:
    sehr_lange_berechnung()
```

Solange diese Funktion läuft, kann `mainloop()` keine anderen Ereignisse verarbeiten.

Das Fenster wirkt dann:

```text
eingefroren
```

oder:

```text
reagiert nicht
```

---

# 48. GUI-Callbacks kurz halten

Eine gute Regel:

> Callback-Funktionen sollten möglichst schnell wieder zur Ereignisschleife zurückkehren.

Für sehr lange Berechnungen braucht man später Techniken wie:

- Aufteilen der Arbeit,
- `after()`,
- Threads,
- Prozesse,
- asynchrone Architektur.

Threads mit Tkinter benötigen allerdings besondere Vorsicht, weil GUI-Widgets nicht beliebig aus Hintergrundthreads verändert werden sollten.

Für den Einstieg verwenden wir zunächst `after()`.

---

# 49. Zeitgesteuerte Aktionen mit `after()`

```python
root.after(
    1000,
    funktion
)
```

bedeutet:

```text
Rufe funktion frühestens nach ungefähr 1000 ms auf,
sobald die Ereignisschleife wieder Zeit dafür hat.
```

Beispiel:

```python
import tkinter as tk
from tkinter import ttk


def aktualisieren() -> None:
    label.config(
        text="Eine Sekunde später"
    )


root = tk.Tk()

label = ttk.Label(
    root,
    text="Start"
)

label.pack()

root.after(
    1000,
    aktualisieren
)

root.mainloop()
```

---

# 50. Wiederholte Aktion mit `after()`

```python
import tkinter as tk
from tkinter import ttk
from datetime import datetime


def uhr_aktualisieren() -> None:
    jetzt = datetime.now()

    label.config(
        text=jetzt.strftime("%H:%M:%S")
    )

    root.after(
        1000,
        uhr_aktualisieren
    )


root = tk.Tk()

label = ttk.Label(root)

label.pack()

uhr_aktualisieren()

root.mainloop()
```

Die Funktion plant am Ende ihren nächsten Aufruf.

# 54. Eigene Fensterklasse durch Vererbung

```python
import tkinter as tk
from tkinter import ttk


class GreetingApp(tk.Tk):
    def __init__(self) -> None:
        super().__init__()

        self.title(
            "Begrüßung"
        )

        self.label = ttk.Label(
            self,
            text="Gib deinen Namen ein:"
        )

        self.label.pack(
            padx=10,
            pady=5
        )

        self.entry = ttk.Entry(
            self
        )

        self.entry.pack(
            padx=10,
            pady=5
        )

        self.button = ttk.Button(
            self,
            text="Begrüßen",
            command=self.begruessen
        )

        self.button.pack(
            padx=10,
            pady=5
        )

    def begruessen(self) -> None:
        name = self.entry.get()

        self.label.config(
            text=f"Hallo, {name}!"
        )
```

# 55. Hauptprogramm

```python
if __name__ == "__main__":
    app = GreetingApp()

    app.mainloop()
```

Hier sehen wir wieder bekannte Konzepte:

```text
GreetingApp
→ Unterklasse von tk.Tk

app
→ Instanz von GreetingApp

self.entry
→ Instanzattribut mit Referenz auf Entry-Widget

self.begruessen
→ Callback-Methode
```

# 56. Warum die Widgets Attribute sind

Wenn später eine Methode auf das Eingabefeld zugreifen soll:

```python
self.entry.get()
```

muss die Referenz erhalten bleiben.

Deshalb speichern wir wichtige Widgets als Instanzattribute:

```python
self.entry
self.label
```

Ein Widget, auf das später nie wieder direkt zugegriffen werden muss, kann dagegen auch ohne eigenes Attribut erstellt werden.

---

# 57. Nicht jedes Widget muss `self.` bekommen

Beispiel:

```python
ttk.Label(
    self,
    text="Name:"
).pack()
```

Wenn wir dieses Label später nicht mehr verändern müssen, brauchen wir nicht zwingend:

```python
self.name_label
```

Eine nützliche Regel:

```text
Später Zugriff notwendig?
→ als Attribut speichern

Nur einmal erstellen?
→ lokale Referenz kann genügen
```

# 58. Vererbung von `tk.Tk` oder Komposition?

Eine eigene Klasse kann von `tk.Tk` erben:

```python
class App(tk.Tk):
    ...
```

Das ist für kleine Anwendungen gut verständlich.

Eine Alternative ist Komposition:

```python
class App:
    def __init__(
        self,
        root: tk.Tk
    ) -> None:
        self.root = root
```

Dann ist die Anwendung nicht selbst das Fenster, sondern **hat** ein Fenster.

Beide Varianten sind möglich.

Für dieses Einführungskapitel verwenden wir überwiegend:

```text
class App(tk.Tk)
```

weil damit Vererbung und GUI-Programmierung anschaulich verbunden werden.

# 60. GUI und Fachlogik sauber trennen

Betrachte eine Berechnung:

```python
def berechne_preis(
    einzelpreis: float,
    anzahl: int
) -> float:
    return einzelpreis * anzahl
```

Diese Funktion sollte nicht wissen:

```text
welches Entry verwendet wird,
welches Label das Ergebnis zeigt,
ob eine messagebox geöffnet wird.
```

Die GUI-Methode übernimmt nur die Vermittlung:

```text
Widget
→ Daten
→ Fachfunktion
→ Ergebnis
→ Widget
```

---

# 61. Beispiel für saubere Trennung

```python
def berechne_preis(
    einzelpreis: float,
    anzahl: int
) -> float:
    if einzelpreis < 0:
        raise ValueError(
            "Preis darf nicht negativ sein."
        )

    if anzahl < 0:
        raise ValueError(
            "Anzahl darf nicht negativ sein."
        )

    return einzelpreis * anzahl
```

Die GUI könnte dann:

```python
def berechnen(self) -> None:
    try:
        preis = float(
            self.preis_entry.get()
        )

        anzahl = int(
            self.anzahl_entry.get()
        )

        gesamt = berechne_preis(
            preis,
            anzahl
        )

    except ValueError as e:
        messagebox.showerror(
            "Ungültige Eingabe",
            str(e)
        )

        return

    self.ergebnis_label.config(
        text=f"{gesamt:.2f} €"
    )
```

So bleibt die eigentliche Fachlogik unabhängig von Tkinter.

---

# 62. Warum diese Trennung wichtig ist

Ohne Trennung wäre die Berechnung fest an die GUI gebunden.

Mit Trennung kann dieselbe Funktion später auch verwendet werden in:

```text
Konsolenprogramm
Webanwendung
Unit Test
anderer GUI
API
```

Das ist ein wichtiges Softwaredesign-Prinzip.

# 63. Komplettes Beispiel: Temperatur-App

```python
import tkinter as tk
from tkinter import messagebox, ttk


def celsius_zu_fahrenheit(
    celsius: float
) -> float:
    return celsius * 1.8 + 32


class TemperaturApp(tk.Tk):
    def __init__(self) -> None:
        super().__init__()

        self.title(
            "Temperatur-Rechner"
        )

        self.resizable(
            False,
            False
        )

        frame = ttk.Frame(
            self,
            padding=12
        )

        frame.grid(
            row=0,
            column=0
        )

        ttk.Label(
            frame,
            text="Celsius:"
        ).grid(
            row=0,
            column=0,
            padx=5,
            pady=5,
            sticky="w"
        )

        self.celsius_entry = ttk.Entry(
            frame,
            width=15
        )

        self.celsius_entry.grid(
            row=0,
            column=1,
            padx=5,
            pady=5
        )

        ttk.Button(
            frame,
            text="Umrechnen",
            command=self.umrechnen
        ).grid(
            row=1,
            column=0,
            columnspan=2,
            pady=5
        )

        self.ergebnis_label = ttk.Label(
            frame,
            text="Ergebnis:"
        )

        self.ergebnis_label.grid(
            row=2,
            column=0,
            columnspan=2,
            pady=5
        )

        self.celsius_entry.bind(
            "<Return>",
            self.enter_gedrueckt
        )

        self.celsius_entry.focus_set()

    def umrechnen(self) -> None:
        try:
            celsius = float(
                self.celsius_entry.get()
            )

        except ValueError:
            messagebox.showerror(
                "Ungültige Eingabe",
                "Bitte eine gültige Zahl eingeben."
            )

            return

        fahrenheit = celsius_zu_fahrenheit(
            celsius
        )

        self.ergebnis_label.config(
            text=(
                f"{celsius:.1f} °C = "
                f"{fahrenheit:.1f} °F"
            )
        )

    def enter_gedrueckt(
        self,
        event: tk.Event
    ) -> None:
        self.umrechnen()


if __name__ == "__main__":
    app = TemperaturApp()

    app.mainloop()
```

# 69. Typische Fehler und Missverständnisse

## Callback sofort aufrufen

Falsch:

```python
command=self.umrechnen()
```

Richtig:

```python
command=self.umrechnen
```

Problematisch:

```text
root-Kinder teilweise pack()
```

Besser:

```text
pro Parent einen Geometry Manager
```

Ungünstig:


Ungünstig in wiederverwendbaren Modulen:

## Übung 2 – Rechner mit Exceptions

Erstelle eine GUI für eine Division.

Eingaben:

```text
Dividend
Divisor
```

Nach dem Klick auf `"Berechnen"` soll das Ergebnis angezeigt werden.

Fehler:

- nicht numerische Eingabe,
- Division durch `0`.

Die eigentliche Berechnung soll in einer GUI-unabhängigen Funktion liegen.

### Lösungsschema

Fachfunktion:

```python
def dividieren(
    dividend: float,
    divisor: float
) -> float:
    ...
```

Möglicher Fehler:

```text
divisor == 0
→ ZeroDivisionError
```

GUI-Callback:

```text
1. Entry-Texte lesen
2. float(...) versuchen
3. ValueError behandeln
4. Fachfunktion aufrufen
5. ZeroDivisionError behandeln
6. Ergebnis anzeigen
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

```python
import tkinter as tk
from tkinter import messagebox, ttk


def dividieren(
    dividend: float,
    divisor: float
) -> float:
    if divisor == 0:
        raise ZeroDivisionError(
            "Division durch 0 ist nicht erlaubt."
        )

    return dividend / divisor


class DivisionApp(tk.Tk):
    def __init__(self) -> None:
        super().__init__()

        self.title(
            "Division"
        )

        frame = ttk.Frame(
            self,
            padding=10
        )

        frame.grid(
            row=0,
            column=0
        )

        ttk.Label(
            frame,
            text="Dividend:"
        ).grid(
            row=0,
            column=0,
            padx=5,
            pady=5
        )

        self.dividend_entry = ttk.Entry(
            frame
        )

        self.dividend_entry.grid(
            row=0,
            column=1,
            padx=5,
            pady=5
        )

        ttk.Label(
            frame,
            text="Divisor:"
        ).grid(
            row=1,
            column=0,
            padx=5,
            pady=5
        )

        self.divisor_entry = ttk.Entry(
            frame
        )

        self.divisor_entry.grid(
            row=1,
            column=1,
            padx=5,
            pady=5
        )

        ttk.Button(
            frame,
            text="Berechnen",
            command=self.berechnen
        ).grid(
            row=2,
            column=0,
            columnspan=2,
            pady=5
        )

        self.ergebnis_label = ttk.Label(
            frame,
            text=""
        )

        self.ergebnis_label.grid(
            row=3,
            column=0,
            columnspan=2,
            pady=5
        )

    def berechnen(self) -> None:
        try:
            dividend = float(
                self.dividend_entry.get()
            )

            divisor = float(
                self.divisor_entry.get()
            )

            ergebnis = dividieren(
                dividend,
                divisor
            )

        except ValueError:
            messagebox.showerror(
                "Ungültige Eingabe",
                "Bitte gültige Zahlen eingeben."
            )

            return

        except ZeroDivisionError as e:
            messagebox.showerror(
                "Ungültige Division",
                str(e)
            )

            return

        self.ergebnis_label.config(
            text=f"Ergebnis: {ergebnis:g}"
        )


if __name__ == "__main__":
    app = DivisionApp()

    app.mainloop()
```

## Übung 3 – Liste verwalten

Erstelle eine kleine Aufgabenliste.

Die GUI enthält:

- ein `Entry`,
- einen Button `"Hinzufügen"`,
- eine `Listbox`,
- einen Button `"Entfernen"`.

Regeln:

- Leere Aufgaben dürfen nicht hinzugefügt werden.
- Beim Entfernen muss eine Aufgabe ausgewählt sein.
- Nach dem Hinzufügen wird das Eingabefeld geleert.

### Lösungsschema

Widgets:

```text
Entry
Button
Listbox
Button
```

Hinzufügen:

```text
1. get()
2. strip()
3. leer?
4. listbox.insert(tk.END, text)
5. Entry leeren
```

Entry leeren:

```python
entry.delete(
    0,
    tk.END
)
```

Entfernen:

```text
1. curselection()
2. keine Auswahl?
3. sonst Index nehmen
4. listbox.delete(index)
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

```python
import tkinter as tk
from tkinter import messagebox, ttk


class AufgabenApp(tk.Tk):
    def __init__(self) -> None:
        super().__init__()

        self.title(
            "Aufgabenliste"
        )

        frame = ttk.Frame(
            self,
            padding=10
        )

        frame.pack()

        self.entry = ttk.Entry(
            frame,
            width=30
        )

        self.entry.grid(
            row=0,
            column=0,
            padx=5,
            pady=5
        )

        ttk.Button(
            frame,
            text="Hinzufügen",
            command=self.hinzufuegen
        ).grid(
            row=0,
            column=1,
            padx=5,
            pady=5
        )

        self.listbox = tk.Listbox(
            frame,
            width=40,
            height=8
        )

        self.listbox.grid(
            row=1,
            column=0,
            columnspan=2,
            padx=5,
            pady=5
        )

        ttk.Button(
            frame,
            text="Entfernen",
            command=self.entfernen
        ).grid(
            row=2,
            column=0,
            columnspan=2,
            pady=5
        )

        self.entry.bind(
            "<Return>",
            self.enter_gedrueckt
        )

    def hinzufuegen(self) -> None:
        aufgabe = self.entry.get().strip()

        if aufgabe == "":
            messagebox.showwarning(
                "Leere Aufgabe",
                "Bitte eine Aufgabe eingeben."
            )

            return

        self.listbox.insert(
            tk.END,
            aufgabe
        )

        self.entry.delete(
            0,
            tk.END
        )

    def entfernen(self) -> None:
        auswahl = self.listbox.curselection()

        if not auswahl:
            messagebox.showwarning(
                "Keine Auswahl",
                "Bitte zuerst eine Aufgabe auswählen."
            )

            return

        self.listbox.delete(
            auswahl[0]
        )

    def enter_gedrueckt(
        self,
        event: tk.Event
    ) -> None:
        self.hinzufuegen()


if __name__ == "__main__":
    app = AufgabenApp()

    app.mainloop()
```

</details>

# Zusammenfassung

## GUI

Eine grafische Benutzeroberfläche ermöglicht Interaktion über grafische Elemente.

---

## Tkinter

```python
import tkinter as tk
```

Tkinter ist Pythons Standard-Schnittstelle zum Tk-GUI-Toolkit.

---

## Hauptfenster

```python
root = tk.Tk()
```

erzeugt das Hauptfenster.

---

## Ereignisschleife

```python
root.mainloop()
```

startet die Ereignisverarbeitung.

---

## Widget

Ein Widget ist ein GUI-Element.

Beispiele:

```text
Label
Entry
Button
Checkbutton
Radiobutton
Listbox
Frame
Canvas
```

---

## Callback

```python
command=callback
```

übergibt eine Funktion oder Methode, die später bei einem Ereignis aufgerufen wird.

---

## Eingabe lesen

```python
text = entry.get()
```

---

## Widget verändern

```python
label.config(
    text="Neuer Text"
)
```

---

## Layout

```text
pack()
grid()
place()
```

Für normale Anwendungen werden meist `pack()` und `grid()` verwendet.

---

## Frame

Ein `Frame` gruppiert Widgets und ermöglicht übersichtlichere Layouts.

---

## Tkinter-Variablen

```text
StringVar
IntVar
DoubleVar
BooleanVar
```

können Widget-Zustände verbinden.

---

## Dialoge

```python
messagebox.showerror(...)
```

zeigt beispielsweise eine Fehlermeldung.

---

## Ereignisbindung

```python
widget.bind(
    "<Return>",
    callback
)
```

reagiert auf allgemeinere Ereignisse.

---

## Zeitgesteuerte Aktion

```python
root.after(
    1000,
    callback
)
```

plant einen späteren Callback.

---

## Objektorientierte GUI

```python
class App(tk.Tk):
    ...
```

kann Widget-Referenzen und Callback-Methoden in einer Klasse bündeln.

## Merksätze

```text
Tk()
→ Hauptfenster erzeugen.

mainloop()
→ auf Ereignisse warten und sie verarbeiten.

Widget
→ grafisches Element der Oberfläche.

command=funktion
→ Funktion später beim Ereignis ausführen.

Entry.get()
→ Text aus einem Eingabefeld lesen.

config(...)
→ bestehendes Widget verändern.

pack() / grid()
→ Widgets anordnen.

Frame
→ Widgets gruppieren.

messagebox
→ Dialogmeldung anzeigen.

after(...)
→ Callback später ausführen.
```

Der wichtigste Gedanke:

> Eine GUI ist kein lineares Programm, das den Benutzer Schritt für Schritt abfragt. Nach dem Aufbau der Oberfläche übernimmt die Ereignisschleife die Kontrolle. Das Programm reagiert mit Callbacks auf Benutzeraktionen. Gute GUI-Programme trennen dabei möglichst klar zwischen Darstellung, Benutzerinteraktion und eigentlicher Fachlogik.
