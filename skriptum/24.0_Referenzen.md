# 1. Vom „Variablen-Behälter“ zum genaueren Modell

Beim ersten Lernen von Variablen ist folgende Vorstellung hilfreich:

```text
Eine Variable ist ein Behälter,
in dem ein Wert gespeichert wird.
```

Für einfache Programme funktioniert dieses Bild recht gut.

Mit Listen, Dictionaries und eigenen Klassen wird es aber zu ungenau.

Das passendere Modell in Python lautet:

> Eine Variable ist ein **Name**, der auf ein Objekt verweist.

Beispiel:

```python
name = "Anna"
```

Vereinfacht:

```text
name ─────► "Anna"
```

`name` ist der Variablenname.

`"Anna"` ist ein String-Objekt.

Die Verbindung vom Namen zum Objekt ist eine **Referenz**.

---

# 2. Objekte besitzen Typ und Identität

Jedes Objekt besitzt unter anderem:

- einen Typ,
- einen Wert bzw. Zustand,
- eine Identität.

Beispiel:

```python
zahl = 42

print(type(zahl))
```

Ausgabe:

```text
<class 'int'>
```

Die Variable `zahl` verweist auf ein Objekt der Klasse `int`.

Für die Identität eines Objekts stellt Python die Funktion `id()` bereit:

```python
zahl = 42

print(id(zahl))
```

Die konkrete Zahl hängt vom laufenden Python-Prozess ab.

Wichtig ist nicht der Zahlenwert selbst, sondern:

> Zwei Namen, die auf dasselbe Objekt verweisen, liefern während der Lebensdauer dieses Objekts dieselbe `id()`.

`id()` ist vor allem ein Werkzeug zum Untersuchen von Objektidentität. Man sollte nicht davon ausgehen, dass die Zahl in jedem Python-System direkt als Speicheradresse interpretiert werden kann.

---

# 3. Zuweisung kopiert normalerweise nicht das Objekt

Betrachte:

```python
a = [1, 2, 3]
b = a
```

Ein häufiger Denkfehler wäre:

```text
b erhält eine Kopie der Liste von a.
```

Das passiert nicht.

Stattdessen erhält `b` eine weitere Referenz auf dasselbe Objekt:

```text
a ──┐
    ├────► [1, 2, 3]
b ──┘
```

Es existieren:

```text
2 Namen
1 Listenobjekt
```

Wir können das mit `is` überprüfen:

```python
a = [1, 2, 3]
b = a

print(a is b)
```

Ausgabe:

```text
True
```

---

# 4. Eine Änderung ist über alle Referenzen sichtbar

Listen sind veränderliche Objekte.

```python
a = [1, 2, 3]
b = a

b.append(4)

print(a)
print(b)
```

Ausgabe:

```text
[1, 2, 3, 4]
[1, 2, 3, 4]
```

Es wurde nicht „die Variable `a` verändert“.

Genauer:

> Das gemeinsame Listenobjekt wurde verändert.

Sowohl `a` als auch `b` verweisen weiterhin auf dieses eine Objekt.

```text
a ──┐
    ├────► [1, 2, 3, 4]
b ──┘
```

---

# 5. Zuweisung und Mutation sind unterschiedliche Dinge

Dieser Unterschied ist zentral.

## Zuweisung

```python
a = [1, 2, 3]
```

Der Name `a` wird an ein Objekt gebunden.

Später:

```python
a = [10, 20]
```

Nun verweist `a` auf ein anderes Objekt.

Das ursprüngliche Objekt wurde dadurch nicht verändert.

---

## Mutation

```python
a = [1, 2, 3]

a.append(4)
```

Hier bleibt `a` mit demselben Listenobjekt verbunden.

Der **Zustand des Objekts** wird verändert.

Vereinfacht:

```text
Zuweisung
→ Welches Objekt referenziert der Name?

Mutation
→ Wie verändert sich das bereits vorhandene Objekt?
```

---

# 6. Neuzuweisung trennt eine Referenz

Betrachte:

```python
a = [1, 2, 3]
b = a

b = [10, 20]
```

Nach der ersten Zuweisung:

```text
a ──┐
    ├────► [1, 2, 3]
b ──┘
```

Nach:

```python
b = [10, 20]
```

gilt:

```text
a ─────► [1, 2, 3]

b ─────► [10, 20]
```

Die Variable `b` wurde an ein neues Objekt gebunden.

Das ursprüngliche Listenobjekt wurde nicht verändert.

---

# 7. Veränderliche und unveränderliche Objekte

Objekte unterscheiden sich darin, ob ihr Zustand nach der Erzeugung verändert werden kann.

Dafür gibt es zwei wichtige Begriffe:

```text
mutable
→ veränderlich

immutable
→ unveränderlich
```

---

# 8. Typische unveränderliche Objekte

Zu den häufig verwendeten unveränderlichen Typen gehören:

- `int`
- `float`
- `bool`
- `str`
- `tuple`
- `frozenset`

Beispiel:

```python
a = 5
b = a
```

Vereinfacht:

```text
a ──┐
    ├────► 5
b ──┘
```

Nun:

```python
b = b + 1
```

Die Zahl `5` wird nicht in `6` umgebaut.

Stattdessen entsteht bzw. wird ein anderes `int`-Objekt verwendet und `b` wird daran gebunden:

```text
a ─────► 5

b ─────► 6
```

Ausgabe:

```python
a = 5
b = a

b = b + 1

print(a)
print(b)
```

```text
5
6
```

---

# 9. Strings sind unveränderlich

Beispiel:

```python
txt1 = "Hallo"
txt2 = txt1

txt2 = txt2 + " Welt"

print(txt1)
print(txt2)
```

Ausgabe:

```text
Hallo
Hallo Welt
```

`"Hallo"` wurde nicht verändert.

`txt2` verweist nach der Verkettung auf ein anderes String-Objekt.

Das erklärt auch, warum Methoden wie

```python
text.upper()
```

den ursprünglichen String nicht verändern:

```python
text = "Hallo"

gross = text.upper()

print(text)
print(gross)
```

Ausgabe:

```text
Hallo
HALLO
```

# 10. Typische veränderliche Objekte

Zu den häufig verwendeten veränderlichen Typen gehören:

- `list`
- `dict`
- `set`
- die meisten Instanzen eigener Klassen

Beispiel mit einem Dictionary:

```python
person = {
    "name": "Anna"
}

zweite_referenz = person

zweite_referenz["alter"] = 16

print(person)
```

Ausgabe:

```text
{'name': 'Anna', 'alter': 16}
```

Beide Namen verweisen auf dasselbe Dictionary.

# 11. Eigene Klassen sind normalerweise veränderlich

Betrachte:

```python
class Person:
    def __init__(self, name: str) -> None:
        self.name: str = name
```

Nun:

```python
anna = Person("Anna")
person = anna

person.name = "Anna Berger"

print(anna.name)
```

Ausgabe:

```text
Anna Berger
```

Auch hier gibt es nur ein `Person`-Objekt:

```text
anna ────┐
         ├────► Person-Objekt
person ──┘      name = "Anna Berger"
```

# 12. `is` und `==`

Die Operatoren `is` und `==` beantworten unterschiedliche Fragen.

## `is`

`is` prüft die **Identität**:

> Sind das exakt dieselben Objekte?

```python
a = [1, 2, 3]
b = a

print(a is b)
```

Ausgabe:

```text
True
```

---

## `==`

`==` prüft die **Gleichheit nach den Regeln des Datentyps**:

> Gelten die Werte als gleich?

```python
a = [1, 2, 3]
b = [1, 2, 3]

print(a == b)
print(a is b)
```

Ausgabe:

```text
True
False
```

Die beiden Listen besitzen denselben Inhalt, sind aber zwei verschiedene Objekte.

---

# 13. Objektidentität mit `id()` untersuchen

```python
a = [1, 2, 3]
b = a
c = [1, 2, 3]

print(id(a))
print(id(b))
print(id(c))
```

Dabei gilt:

```text
id(a) == id(b)
```

weil `a` und `b` auf dasselbe Objekt zeigen.

Für `c` gilt während der gleichzeitigen Lebensdauer der Objekte:

```text
id(c) != id(a)
```

weil `c` auf eine andere Liste zeigt.

Für die eigentliche Prüfung der Identität sollte man im Code normalerweise `is` verwenden.

---

# 14. `is` besonders bei `None`

Bei `None` verwendet man in Python üblicherweise `is`:

```python
if wert is None:
    print("Kein Wert vorhanden.")
```

und:

```python
if wert is not None:
    print("Ein Wert ist vorhanden.")
```

Nicht empfohlen ist:

```python
if wert == None:
    ...
```

`None` ist ein einzelnes spezielles Objekt, daher passt die Identitätsprüfung hier besonders gut.

---

# 15. Vorsicht: Bei kleinen Zahlen kann `is` verwirrend sein

Manchmal sieht man:

```python
a = 5
b = 5

print(a is b)
```

und erhält möglicherweise:

```text
True
```

Python darf bestimmte unveränderliche Objekte intern wiederverwenden.

Darauf sollte man sich aber nicht verlassen.

Für Wertevergleiche gilt:

```python
a == b
```

Für die Frage nach exakt demselben Objekt gilt:

```python
a is b
```

> Verwende `is` nicht als Ersatz für `==`, nur weil es bei einem Beispiel zufällig dasselbe Ergebnis liefert.

# 16. Eine echte Kopie einer Liste erzeugen

Wenn zwei unabhängige Listen benötigt werden, muss eine neue Liste erzeugt werden.

Zum Beispiel mit `list()`:

```python
a = [1, 2, 3]
b = list(a)

b.append(4)

print(a)
print(b)
```

Ausgabe:

```text
[1, 2, 3]
[1, 2, 3, 4]
```

Nun gilt:

```python
print(a == b)
print(a is b)
```

Nach dem Anhängen:

```text
False
False
```

Vor dem Anhängen wären die Inhalte gleich, die Objekte aber trotzdem verschieden.

# 17. Weitere Möglichkeiten für eine Listenkopie

Eine einfache Liste kann unter anderem so kopiert werden:

```python
a = [1, 2, 3]

b = list(a)
c = a.copy()
d = a[:]
```

Alle drei Varianten erzeugen neue Listenobjekte.

```python
print(a is b)
print(a is c)
print(a is d)
```

Ausgabe:

```text
False
False
False
```

Aber:

> Diese Kopien sind nur **flache Kopien**.

Dieser Begriff wird bei verschachtelten Daten wichtig.

---

# 18. Was ist eine flache Kopie?

Betrachte eine verschachtelte Liste:

```python
original = [
    [1, 2],
    [3, 4]
]
```

Vereinfacht besteht sie nicht nur aus Zahlen.

Die äußere Liste enthält Referenzen auf innere Listen:

```text
original
   │
   ▼
äußere Liste
   │
   ├────► [1, 2]
   │
   └────► [3, 4]
```

Nun erzeugen wir eine flache Kopie:

```python
kopie = original.copy()
```

Es entstehen zwei äußere Listen.

Die inneren Listen werden aber nicht kopiert:

```text
original ─────► äußere Liste A ──┐
                                 ├────► [1, 2]
                                 └────► [3, 4]

kopie ────────► äußere Liste B ──┘
```

Beide äußeren Listen enthalten Referenzen auf dieselben inneren Listen.

---

# 19. Überraschung bei verschachtelten Listen

```python
original = [
    [1, 2],
    [3, 4]
]

kopie = original.copy()

kopie[0].append(99)

print(original)
print(kopie)
```

Ausgabe:

```text
[[1, 2, 99], [3, 4]]
[[1, 2, 99], [3, 4]]
```

Warum?

`kopie[0]` und `original[0]` verweisen auf dieselbe innere Liste.

Wir können das prüfen:

```python
print(original is kopie)
print(original[0] is kopie[0])
```

Ausgabe:

```text
False
True
```

Also:

```text
äußere Listen
→ verschieden

innere Listen
→ gemeinsam
```

---

# 20. Flache Kopie bedeutet: nur die oberste Ebene wird kopiert

Das ist der wichtigste Merksatz:

> Bei einer flachen Kopie wird das äußere Objekt neu erzeugt. Referenzen auf enthaltene Objekte werden übernommen.

Das gilt nicht nur für Listen.

Auch:

```python
dict.copy()
```

und:

```python
set.copy()
```

erzeugen flache Kopien.

---

# 21. Tiefe Kopie mit `copy.deepcopy()`

Wenn auch verschachtelte veränderliche Objekte unabhängig kopiert werden sollen, kann `deepcopy()` verwendet werden.

```python
from copy import deepcopy


original = [
    [1, 2],
    [3, 4]
]

kopie = deepcopy(original)

kopie[0].append(99)

print(original)
print(kopie)
```

Ausgabe:

```text
[[1, 2], [3, 4]]
[[1, 2, 99], [3, 4]]
```

Nun sind auch die inneren Listen getrennte Objekte:

```python
print(original[0] is kopie[0])
```

Ausgabe:

```text
False
```

---

# 22. `copy.copy()` und `copy.deepcopy()`

Das Modul `copy` bietet zwei wichtige Funktionen:

```python
from copy import copy, deepcopy
```

## `copy()`

```python
flach = copy(original)
```

erzeugt eine flache Kopie.

## `deepcopy()`

```python
tief = deepcopy(original)
```

versucht auch enthaltene Objekte rekursiv zu kopieren.

`deepcopy()` sollte nicht automatisch überall verwendet werden.

Bei großen Objektstrukturen kann eine tiefe Kopie teuer sein, und manchmal sollen bestimmte Teilobjekte absichtlich gemeinsam verwendet werden.

Die entscheidende Frage lautet:

> Welche Objekte sollen gemeinsam bleiben und welche sollen wirklich unabhängig werden?

# 23. Kopieren bei eigenen Klassen

Auch eigene Objekte können kopiert werden.

```python
from copy import copy


class Person:
    def __init__(self, name: str) -> None:
        self.name: str = name
        self.hobbys: list[str] = []


anna = Person("Anna")
anna.hobbys.append("Lesen")

kopie = copy(anna)
```

`anna` und `kopie` sind verschiedene `Person`-Objekte:

```python
print(anna is kopie)
```

Ausgabe:

```text
False
```

Aber die Liste `hobbys` wird bei einer flachen Kopie gemeinsam verwendet:

```python
print(anna.hobbys is kopie.hobbys)
```

Ausgabe:

```text
True
```

Wenn die Hobbyliste ebenfalls getrennt sein soll, wäre eine tiefe Kopie nötig oder eine gezielte eigene Kopierlogik.

# 24. Tupel sind unveränderlich – enthaltene Objekte müssen es nicht sein

Ein Tupel kann nach seiner Erzeugung nicht an einer Position neu belegt werden.

```python
werte = (10, 20, 30)
```

Folgendes ist nicht erlaubt:

```python
werte[0] = 99
```

Ein Tupel kann aber Referenzen auf veränderliche Objekte enthalten:

```python
daten = (
    [1, 2],
    "Messung"
)

daten[0].append(3)

print(daten)
```

Ausgabe:

```text
([1, 2, 3], 'Messung')
```

Das Tupel selbst wurde nicht strukturell verändert.

Die darin referenzierte Liste wurde verändert.

Das zeigt:

> „Immutable“ bedeutet nicht automatisch, dass alles, was über das Objekt erreichbar ist, ebenfalls unveränderlich sein muss.

# 25. Referenzen bei Funktionsaufrufen

Referenzen spielen auch beim Aufruf von Funktionen eine zentrale Rolle.

Betrachte:

```python
def fuege_wert_hinzu(zahlen: list[int]) -> None:
    zahlen.append(99)


werte = [1, 2, 3]

fuege_wert_hinzu(werte)

print(werte)
```

Ausgabe:

```text
[1, 2, 3, 99]
```

Warum ist die Änderung außerhalb der Funktion sichtbar?

Beim Aufruf erhält der Parameter `zahlen` eine Referenz auf dasselbe Listenobjekt:

```text
werte ──┐
        ├────► [1, 2, 3]
zahlen ─┘
```

Die Methode `append()` verändert dieses gemeinsame Objekt.

---

# 26. Python übergibt nicht „die Variable selbst“

Man hört manchmal:

```text
Python übergibt alles per Referenz.
```

Das ist leicht missverständlich.

Genauer ist:

> Beim Funktionsaufruf wird der lokale Parametername an dasselbe Objekt gebunden, das als Argument übergeben wurde.

Dieses Verhalten wird oft als **call by sharing** oder **object sharing** beschrieben.

Die Funktion erhält nicht die Variable des Aufrufers selbst.

Sie erhält einen neuen lokalen Namen, der zunächst auf dasselbe Objekt zeigt.

---

# 27. Neuzuweisung eines Parameters verändert die Variable außerhalb nicht

Vergleiche:

```python
def ersetze_liste(zahlen: list[int]) -> None:
    zahlen = [100, 200]


werte = [1, 2, 3]

ersetze_liste(werte)

print(werte)
```

Ausgabe:

```text
[1, 2, 3]
```

Innerhalb der Funktion wurde nur der lokale Name `zahlen` an ein neues Objekt gebunden.

Vereinfacht vor der Neuzuweisung:

```text
werte ──┐
        ├────► [1, 2, 3]
zahlen ─┘
```

Danach innerhalb der Funktion:

```text
werte ─────► [1, 2, 3]

zahlen ────► [100, 200]
```

Die Bindung des Namens `werte` außerhalb der Funktion wurde nicht verändert.

# 28. Mutation und Neuzuweisung bei Funktionen vergleichen

## Mutation

```python
def veraendere(liste: list[int]) -> None:
    liste.append(4)
```

Die Änderung ist außen sichtbar.

## Neuzuweisung

```python
def ersetze(liste: list[int]) -> None:
    liste = [4]
```

Die Variable außerhalb wird nicht neu gebunden.

Merksatz:

```text
Objekt verändern
→ kann außerhalb sichtbar sein

lokalen Parameternamen neu zuweisen
→ bindet nur den lokalen Namen neu
```

# 29. Rückgabewerte sind oft klarer als versteckte Änderungen

Eine Funktion kann ein übergebenes Objekt absichtlich verändern:

```python
def sortiere_in_place(zahlen: list[int]) -> None:
    zahlen.sort()
```

Das kann sinnvoll sein.

Manchmal ist eine Funktion mit Rückgabewert aber leichter zu verstehen:

```python
def sortierte_kopie(zahlen: list[int]) -> list[int]:
    return sorted(zahlen)
```

Verwendung:

```python
werte = [3, 1, 2]

neu = sortierte_kopie(werte)

print(werte)
print(neu)
```

Ausgabe:

```text
[3, 1, 2]
[1, 2, 3]
```

Beim Entwurf einer Funktion sollte klar sein:

> Verändert die Funktion ein vorhandenes Objekt oder liefert sie ein neues Objekt?

# 30. `+=` kann je nach Typ unterschiedlich wirken

Ein besonders interessantes Beispiel ist `+=`.

## Liste

```python
a = [1, 2]
b = a

b += [3]

print(a)
print(b)
```

Ausgabe:

```text
[1, 2, 3]
[1, 2, 3]
```

Bei Listen verändert `+=` typischerweise das vorhandene Listenobjekt.

---

## Tupel

```python
a = (1, 2)
b = a

b += (3,)

print(a)
print(b)
```

Ausgabe:

```text
(1, 2)
(1, 2, 3)
```

Tupel sind immutable.

Deshalb entsteht für `b` ein neues Tupelobjekt.

> Ob eine Operation mutiert oder ein neues Objekt erzeugt, hängt vom Datentyp und von der jeweiligen Operation ab.

# 31. Objektgraphen

Bei mehreren Klassen reicht das Bild einer einzelnen Referenz oft nicht mehr.

Dann ist es hilfreich, einen **Objektgraphen** zu zeichnen.

Ein Objektgraph zeigt:

- konkrete Objekte,
- Referenzen zwischen ihnen,
- gemeinsame Teilobjekte.

Das ist besonders nützlich beim Debuggen.

---

# 32. Beispiel: Stammbaum

Wir modellieren Personen mit Eltern und Kindern.

Da die Klasse in ihren Type Hints auf sich selbst verweist, verwenden wir:

```python
from __future__ import annotations
```

Dann können wir innerhalb der Klasse `Person` direkt wieder den Typ `Person` verwenden.

```python
from __future__ import annotations


class Person:
    def __init__(self, name: str) -> None:
        self.name: str = name
        self.mutter: Person | None = None
        self.vater: Person | None = None
        self.kinder: list[Person] = []
```

Nun erzeugen wir konkrete Personen:

```python
susi = Person("Susi")
fritz = Person("Fritz")
erika = Person("Erika")
```

---

# 33. Mehrere Wege zum selben Objekt

Wir setzen die Beziehungen:

```python
erika.mutter = susi
susi.kinder.append(erika)

susi.vater = fritz
fritz.kinder.append(susi)
```

Nun ist das `Person`-Objekt `"Susi"` über mehrere Wege erreichbar.

Vereinfacht:

```text
susi ──────────────────────────────┐
                                   │
erika ─► Person "Erika"            │
          │                        │
          └── mutter ──────────────┤
                                   ▼
                              Person "Susi"
                                   ▲
                                   │
fritz ─► Person "Fritz"            │
          │                        │
          └── kinder[0] ───────────┘
```

Es existiert nicht für jede Referenz eine eigene Kopie von Susi.

Es gibt ein einziges Objekt und mehrere Referenzen darauf.

---

# 34. Identität im Stammbaum prüfen

```python
print(susi is erika.mutter)
print(susi is fritz.kinder[0])
```

Ausgabe:

```text
True
True
```

Die Variable `susi`, das Attribut `erika.mutter` und der Listeneintrag `fritz.kinder[0]` führen alle zum selben Objekt.

---

# 35. Änderung über einen Weg ist über alle Wege sichtbar

```python
erika.mutter.name = "Susanne"

print(susi.name)
print(fritz.kinder[0].name)
```

Ausgabe:

```text
Susanne
Susanne
```

Es wurde nur ein `Person`-Objekt verändert.

Da alle Referenzen auf dieses Objekt zeigen, ist der neue Zustand überall sichtbar.

---

# 36. Der Stammbaum ist eine Objektstruktur aus Referenzen

Die Klasse:

```python
class Person:
    ...
```

beschreibt nur den Datentyp.

Die konkreten Instanzen und ihre Referenzen bilden zur Laufzeit eine Objektstruktur.

Diese Struktur kann sich verändern:

```python
neues_kind = Person("Lena")

susi.kinder.append(neues_kind)
```

Dadurch entsteht eine neue Referenz im Objektgraphen.

---

# 37. Das Attribut `kinder` ist nicht automatisch eine Aggregation

Aus dem vorherigen Kapitel kennen wir Assoziationen, Aggregation und Komposition.

Wichtig ist:

```python
self.kinder: list[Person] = []
```

bedeutet zunächst nur:

> Ein `Person`-Objekt kann Referenzen auf mehrere andere `Person`-Objekte speichern.

Die Tatsache, dass eine Liste verwendet wird, macht die Beziehung nicht automatisch zu einer Aggregation.

Im Stammbaum handelt es sich fachlich vor allem um eine **Assoziation zwischen Personen**:

```text
Person
  │
  ├── mutter → Person
  ├── vater  → Person
  └── kinder → mehrere Person-Objekte
```

Eltern „besitzen“ ihre Kinder nicht als Lebenszyklusbestandteile.

Deshalb ist eine normale Assoziation hier die passendere Beschreibung.

---

# 38. Beidseitige Beziehungen und Referenzen

Wenn wir schreiben:

```python
erika.mutter = susi
```

wird nur eine Richtung gesetzt.

Susi kennt Erika dadurch nicht automatisch als Kind.

Deshalb benötigen wir zusätzlich:

```python
susi.kinder.append(erika)
```

Nun existieren Referenzen in beide Richtungen:

```text
Erika ──mutter────► Susi

Susi ───kinder────► Erika
```

Das ist eine bidirektionale Assoziation.

Wie im vorherigen Kapitel gilt:

> Werden beide Richtungen gespeichert, müssen beide Seiten konsistent gehalten werden.

---

# 39. Eine Methode kann beide Seiten gleichzeitig setzen

Statt Beziehungen überall manuell zu verändern, können Methoden die Konsistenz sichern.

```python
from __future__ import annotations


class Person:
    def __init__(self, name: str) -> None:
        self.name: str = name
        self.mutter: Person | None = None
        self.vater: Person | None = None
        self.kinder: list[Person] = []

    def setze_mutter(self, mutter: Person) -> None:
        self.mutter = mutter

        if self not in mutter.kinder:
            mutter.kinder.append(self)
```

Verwendung:

```python
susi = Person("Susi")
erika = Person("Erika")

erika.setze_mutter(susi)

print(erika.mutter is susi)
print(susi.kinder[0] is erika)
```

Ausgabe:

```text
True
True
```

Die Methode verwaltet beide Referenzen gemeinsam.

---

# 40. Referenzzyklen

Bei bidirektionalen Beziehungen können Zyklen entstehen:

```text
Susi ──kinder──► Erika
  ▲               │
  └────mutter─────┘
```

Das ist kein Fehler.

Objektgraphen dürfen Zyklen besitzen.

Python besitzt eine automatische Speicherverwaltung und kann auch mit vielen solchen Referenzzyklen umgehen.

Man muss Objekte normalerweise nicht manuell aus dem Speicher löschen.

---

# 41. Wann kann ein Objekt freigegeben werden?

Ein Objekt wird für das Programm uninteressant, wenn es nicht mehr erreichbar ist.

Beispiel:

```python
a = [1, 2, 3]
b = a
```

Das Objekt ist über zwei Namen erreichbar.

Nun:

```python
a = None
```

Die Liste ist weiterhin über `b` erreichbar.

Erst wenn keine relevanten Referenzen mehr auf das Objekt führen, kann Python den belegten Speicher später automatisch wiederverwenden.

Die genaue Speicherverwaltung übernimmt Python.

> Referenzen bestimmen also nicht nur, wie Objekte zusammenhängen, sondern auch, welche Objekte noch erreichbar sind.

---

# 42. `del` löscht einen Namen oder eine Referenz – nicht zwingend das Objekt

Betrachte:

```python
a = [1, 2, 3]
b = a

del a

print(b)
```

Ausgabe:

```text
[1, 2, 3]
```

`del a` entfernt die Bindung des Namens `a`.

Das Listenobjekt bleibt erhalten, weil `b` weiterhin darauf verweist.

Deshalb ist die Aussage

```text
del löscht das Objekt
```

zu ungenau.

Genauer:

> `del` entfernt an dieser Stelle eine Referenz bzw. Bindung. Ob das Objekt danach noch existiert, hängt davon ab, ob es weiterhin erreichbar ist.

---

# 43. Referenzen in Listen und Dictionaries

Nicht nur Variablen können Referenzen speichern.

Auch Sammlungen enthalten Referenzen auf Objekte.

Beispiel:

```python
anna = Person("Anna")

personen = [anna]

lookup = {
    "klassensprecherin": anna
}
```

Vereinfacht:

```text
anna ─────────────────────┐
                          │
personen[0] ───────────────┼────► Person "Anna"
                          │
lookup["klassensprecherin"] ┘
```

Wieder gibt es nur ein `Person`-Objekt.

---

# 44. Entfernen aus einer Sammlung löscht nicht automatisch das Objekt

```python
anna = Person("Anna")

personen = [anna]

personen.remove(anna)
```

Das `Person`-Objekt existiert weiterhin, weil die Variable `anna` noch darauf verweist.

```python
print(anna.name)
```

Ausgabe:

```text
Anna
```

Ein Objekt ist nicht an genau einen Behälter oder genau eine Variable gebunden.

---

# 45. Referenzen erklären viele frühere Python-Effekte

Viele Themen aus früheren Kapiteln werden durch Referenzen verständlicher.

## Listenmethoden

```python
liste.append(...)
```

verändern ein vorhandenes Listenobjekt.

## `sorted()`

```python
neu = sorted(liste)
```

erzeugt eine neue Liste.

## `list.sort()`

```python
liste.sort()
```

verändert die vorhandene Liste.

## Klassenattribute auf Instanzen

```python
objekt.attribut = wert
```

verändert den Zustand des referenzierten Objekts.

## Assoziationen

```python
self.person: Person = person
```

speichert eine Referenz auf ein anderes Objekt.

All diese Konzepte hängen mit Objektidentität und Referenzen zusammen.

---

# 46. Eine Entscheidungshilfe beim Lesen von Code

Wenn Referenzen unübersichtlich werden, stelle dir bei jeder Zeile drei Fragen.

## Frage 1: Wird ein neuer Name gebunden?

Beispiel:

```python
b = a
```

Dann entsteht eine neue Referenz auf ein vorhandenes Objekt.

---

## Frage 2: Wird ein neues Objekt erzeugt?

Beispiel:

```python
b = [1, 2, 3]
```

oder:

```python
b = list(a)
```

Dann gibt es ein neues Listenobjekt.

---

## Frage 3: Wird ein vorhandenes Objekt verändert?

Beispiel:

```python
b.append(4)
```

Dann wird das von `b` referenzierte Listenobjekt mutiert.

Dieses Denkmodell hilft bei fast allen Referenzproblemen.

---

# 47. Typische Fehler und Missverständnisse

## Denken, dass `b = a` eine Kopie erzeugt

```python
b = a
```

kopiert normalerweise nur die Referenz.

---

## `is` für Wertevergleiche verwenden

Falsch als allgemeiner Wertevergleich:

```python
if name is "Anna":
    ...
```

Richtig:

```python
if name == "Anna":
    ...
```

`is` ist für Identität gedacht.

---

## Flache Kopien mit tiefen Kopien verwechseln

```python
kopie = original.copy()
```

kopiert bei verschachtelten Strukturen nicht automatisch alle enthaltenen Objekte.

---

## Immutable mit „enthält nur immutable Werte“ verwechseln

Ein Tupel ist immutable, kann aber eine veränderliche Liste referenzieren.

---

## Änderungen in Funktionen nicht erwarten

```python
def funktion(liste: list[int]) -> None:
    liste.append(5)
```

verändert das gemeinsam referenzierte Listenobjekt.

---

## Neuzuweisung in einer Funktion mit Mutation verwechseln

```python
def funktion(liste: list[int]) -> None:
    liste = []
```

bindet nur den lokalen Parameternamen neu.

---

## Denken, dass `del` immer sofort das Objekt zerstört

Andere Referenzen können das Objekt weiterhin erreichbar halten.

---

## Jede Liste von Objekten als Aggregation interpretieren

Eine Sammlung speichert zunächst Referenzen.

Die UML-Bedeutung hängt vom fachlichen Modell ab.

## Übung 1 – Referenzen vorhersagen

Gegeben ist:

```python
a = [1, 2]
b = a
c = a.copy()

b.append(3)
c.append(4)

print(a)
print(b)
print(c)

print(a is b)
print(a is c)
```

Bestimme die vollständige Ausgabe, ohne den Code auszuführen.

### Lösungsschema

Nach:

```python
b = a
```

gilt:

```text
a ──┐
    ├────► Liste A
b ──┘
```

Nach:

```python
c = a.copy()
```

gilt:

```text
a ──┐
    ├────► Liste A
b ──┘

c ─────► Liste B
```

Nun getrennt prüfen:

```text
b.append(3)
→ Welche Liste wird verändert?

c.append(4)
→ Welche Liste wird verändert?

a is b
→ dasselbe Objekt?

a is c
→ dasselbe Objekt?
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

Die Ausgabe lautet:

```text
[1, 2, 3]
[1, 2, 3]
[1, 2, 4]
True
False
```

`a` und `b` referenzieren dieselbe Liste.

`c` referenziert eine neue, flach kopierte Liste.

</details>

## Übung 2 – Flache Kopie verstehen

Gegeben ist:

```python
original = [
    ["Anna", 10],
    ["Ben", 12]
]

kopie = original.copy()

kopie[0][1] = 15
kopie.append(["Clara", 9])

print(original)
print(kopie)
```

Bestimme die Ausgabe.

### Lösungsschema

Zeichne zuerst zwei Ebenen.

Die äußeren Listen sind verschieden:

```text
original ─────► äußere Liste A

kopie ────────► äußere Liste B
```

Aber die bereits vorhandenen inneren Listen werden geteilt:

```text
beide ─────► ["Anna", 10]
beide ─────► ["Ben", 12]
```

Nun prüfen:

```text
kopie[0][1] = 15
→ verändert eine gemeinsame innere Liste

kopie.append(...)
→ verändert nur die äußere Liste B
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

Ausgabe:

```text
[['Anna', 15], ['Ben', 12]]
[['Anna', 15], ['Ben', 12], ['Clara', 9]]
```

Die Änderung an

```python
kopie[0][1]
```

ist auch in `original` sichtbar, weil die erste innere Liste gemeinsam verwendet wird.

Das Anhängen von `["Clara", 9]` verändert dagegen nur die äußere Liste `kopie`.

</details>

## Übung 3 – Referenzen bei Funktionen und Objekten

Gegeben ist:

```python
class Konto:
    def __init__(self, inhaber: str, saldo: float) -> None:
        self.inhaber: str = inhaber
        self.saldo: float = saldo


def einzahlen(konto: Konto, betrag: float) -> None:
    konto.saldo += betrag


def ersetzen(konto: Konto) -> None:
    konto = Konto("Neu", 0.0)


mein_konto = Konto("Anna", 100.0)
zweite_referenz = mein_konto

einzahlen(zweite_referenz, 50.0)
ersetzen(mein_konto)

print(mein_konto.inhaber)
print(mein_konto.saldo)
print(mein_konto is zweite_referenz)
```

Bestimme die Ausgabe und begründe sie.

### Lösungsschema

Zuerst:

```text
mein_konto ───────┐
                  ├────► Konto-Objekt
zweite_referenz ──┘      inhaber = "Anna"
                         saldo = 100.0
```

Bei:

```python
einzahlen(zweite_referenz, 50.0)
```

wird das gemeinsame Konto-Objekt mutiert.

Bei:

```python
ersetzen(mein_konto)
```

wird innerhalb der Funktion nur der lokale Parameter `konto` neu gebunden.

Die Variable `mein_konto` außerhalb bleibt unverändert an das ursprüngliche Objekt gebunden.

<details>
<summary>Vollständige Lösung anzeigen</summary>

Die Ausgabe lautet:

```text
Anna
150.0
True
```

`einzahlen()` verändert den Zustand des vorhandenen Konto-Objekts.

`ersetzen()` erzeugt zwar intern ein neues Konto, bindet aber nur den lokalen Parameternamen `konto` daran.

`mein_konto` und `zweite_referenz` zeigen weiterhin auf dasselbe ursprüngliche Objekt.

</details>

# Zusammenfassung

## Variable

Eine Variable ist in Python ein Name.

```python
a = [1, 2, 3]
```

`a` verweist auf ein Objekt.

---

## Referenz

Eine Referenz verbindet einen Namen oder ein Attribut mit einem Objekt.

```text
a ─────► Objekt
```

Mehrere Referenzen können auf dasselbe Objekt zeigen:

```text
a ──┐
    ├────► Objekt
b ──┘
```

---

## Zuweisung

```python
b = a
```

erzeugt normalerweise keine Kopie des Objekts.

Der Name `b` wird an dasselbe Objekt gebunden.

---

## Mutation

Eine Mutation verändert den Zustand eines vorhandenen Objekts.

```python
liste.append(4)
```

Alle Referenzen auf dieses Objekt sehen danach denselben neuen Zustand.

---

## Immutable

Unveränderliche Objekte können nach ihrer Erzeugung nicht in ihrem eigenen Zustand verändert werden.

Typische Beispiele:

```text
int
float
bool
str
tuple
```

---

## Mutable

Veränderliche Objekte können ihren Zustand ändern.

Typische Beispiele:

```text
list
dict
set
Instanzen vieler eigener Klassen
```

---

## Identität

```python
a is b
```

prüft, ob `a` und `b` auf dasselbe Objekt verweisen.

---

## Gleichheit

```python
a == b
```

prüft Gleichheit nach den Regeln des Datentyps.

---

## Flache Kopie

```python
kopie = original.copy()
```

erzeugt ein neues äußeres Objekt.

Enthaltene Objekte können weiterhin gemeinsam verwendet werden.

---

## Tiefe Kopie

```python
from copy import deepcopy

kopie = deepcopy(original)
```

versucht auch verschachtelte Objekte unabhängig zu kopieren.

---

## Funktionsparameter

Beim Aufruf wird der lokale Parametername an dasselbe übergebene Objekt gebunden.

```text
Argumentname ──┐
               ├────► Objekt
Parameter ─────┘
```

Mutation kann daher außerhalb sichtbar sein.

Eine Neuzuweisung des lokalen Parameternamens verändert dagegen nicht die Variable des Aufrufers.

## Merksätze

```text
a = objekt
→ a verweist auf ein Objekt.

b = a
→ b verweist normalerweise auf dasselbe Objekt.

a is b
→ Sind es exakt dieselben Objekte?

a == b
→ Gelten die Werte als gleich?

Mutation
→ Ein vorhandenes Objekt ändert seinen Zustand.

Neuzuweisung
→ Ein Name verweist danach auf ein anderes Objekt.

copy()
→ neue äußere Struktur, enthaltene Objekte können geteilt bleiben.

deepcopy()
→ versucht auch verschachtelte Objekte zu kopieren.
```

Der wichtigste Gedanke:

> Variablen, Attribute und Sammlungen speichern in Python keine unabhängigen Kopien komplexer Objekte, nur weil ein neuer Name auftaucht. Sie können Referenzen auf dieselben Objekte enthalten. Wer Referenzen versteht, versteht damit auch Mutation, Kopieren, Funktionsargumente, Assoziationen und große Teile der objektorientierten Programmierung deutlich besser.
