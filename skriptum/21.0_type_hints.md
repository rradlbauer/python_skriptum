# 21.0 Type Hints

## Lernziele

Nach diesem Kapitel kannst du ...

- den Unterschied zwischen **dynamischer Typisierung** und **Type Hints** erklären.
- Type Hints für Funktionsparameter und Rückgabewerte schreiben.
- Variablen mit Typinformationen versehen.
- Sammlungen wie Listen, Sets, Dictionaries und Tupel typisieren.
- Funktionen so typisieren, dass sie nicht unnötig auf einen einzigen konkreten Datentyp eingeschränkt sind.
- mit `None` und optionalen Werten umgehen.
- Typen aus importierten Modulen in Type Hints verwenden.
- erklären, was ein statischer Type Checker macht.
- `mypy` verwenden, um mögliche Typfehler zu finden.
- Type Hints als Teil einer verständlichen Funktionsschnittstelle einsetzen.

> Die Beispiele in diesem Kapitel verwenden die moderne Type-Hint-Syntax von **Python 3.10 oder neuer**.

---

# 1. Python kennt Datentypen – Variablen haben aber keinen fest eingebauten Typ

Du kennst bereits verschiedene Datentypen:

```python
int
float
str
bool
list
dict
set
tuple
```

Außerdem weißt du:

> Eine Variable ist in Python ein Name, der auf ein Objekt verweist.

Der Datentyp gehört dabei zum **Objekt**, nicht dauerhaft zum Variablennamen.

Deshalb ist Folgendes in Python möglich:

```python
wert = 42
wert = "Hallo"
```

Zuerst verweist `wert` auf ein `int`-Objekt, danach auf ein `str`-Objekt.

Python ist eine **dynamisch typisierte** Programmiersprache.

Das bedeutet unter anderem, dass Typen während der Programmausführung eine Rolle spielen und ein Variablenname nicht vorab dauerhaft auf einen bestimmten Typ festgelegt werden muss.

Andere Programmiersprachen verwenden statische Typsysteme. Dort werden Typinformationen bereits vor der Programmausführung geprüft. Dabei müssen Typen nicht immer ausdrücklich hingeschrieben werden – manche statisch typisierten Sprachen können Typen auch automatisch ableiten.

Python geht einen anderen Weg:

```python
x = 5
```

Das reicht aus.

Wir müssen nicht schreiben:

```text
x ist eine Variable vom Typ int
```

Python erkennt zur Laufzeit, dass das Objekt `5` vom Typ `int` ist.

---

# 2. Warum Type Hints?

Mit zunehmender Größe eines Programms entsteht ein Problem:

```python
def anzahl_gerade(l):
    return len([x for x in l if x % 2 == 0])
```

Was soll `l` sein?

Vielleicht:

- eine Liste von Ganzzahlen,
- ein Tupel,
- ein `range`-Objekt,
- etwas ganz anderes?

Und was gibt die Funktion zurück?

Man kann es aus dem Code erschließen, aber die Schnittstelle der Funktion erklärt es nicht deutlich.

Außerdem ist der Name `l` wenig aussagekräftig.

Eine verständlichere Variante ist:

```python
def anzahl_gerade(zahlen: list[int]) -> int:
    return len([zahl for zahl in zahlen if zahl % 2 == 0])
```

Nun sieht man direkt:

```text
zahlen: list[int]
```

bedeutet:

> `zahlen` soll eine Liste von Ganzzahlen sein.

Und:

```text
-> int
```

bedeutet:

> Die Funktion soll eine Ganzzahl zurückgeben.

Die Typinformationen hinter `:` und `->` nennt man **Type Hints** oder **Type Annotations**.

---

# 3. Type Hints verändern Python nicht in eine statisch typisierte Sprache

Das ist einer der wichtigsten Punkte dieses Kapitels.

Betrachte:

```python
def verdoppeln(zahl: int) -> int:
    return zahl * 2
```

Der Type Hint sagt:

> Die Funktion ist dafür gedacht, einen `int` zu erhalten und einen `int` zurückzugeben.

Trotzdem überprüft der Python-Interpreter diese Angabe normalerweise **nicht automatisch**.

Zum Beispiel kann dieser Aufruf ausgeführt werden:

```python
print(verdoppeln("Hallo"))
```

Die Ausgabe ist:

```text
HalloHallo
```

Warum?

Der Ausdruck

```python
"Hallo" * 2
```

ist in Python gültig.

Der Type Hint verhindert den Aufruf also nicht.

Type Hints sind vor allem Informationen für:

- Menschen, die den Code lesen,
- Entwicklungsumgebungen,
- statische Type Checker wie `mypy`,
- Analysewerkzeuge und Dokumentationssysteme.

> Type Hints beschreiben, wie der Code **verwendet werden soll**. Der Python-Interpreter erzwingt diese Typen normalerweise nicht.

---

# 4. Type Hints bei Funktionen

Die wichtigste Anwendung von Type Hints sind Funktionen.

Die allgemeine Form lautet:

```python
def funktionsname(parameter: typ) -> rueckgabetyp:
    ...
```

Beispiel:

```python
def quadrat(zahl: int) -> int:
    return zahl ** 2
```

Hier bedeutet:

```text
zahl: int
```

Der Parameter `zahl` soll eine Ganzzahl sein.

```text
-> int
```

Die Funktion soll eine Ganzzahl zurückgeben.

---

## Mehrere Parameter

```python
def berechne_flaeche(breite: float, hoehe: float) -> float:
    return breite * hoehe
```

Die Funktion erwartet zwei `float`-Werte und liefert einen `float`-Wert zurück.

---

## Ein Rückgabewert vom Typ `bool`

```python
def ist_gerade(zahl: int) -> bool:
    return zahl % 2 == 0
```

Beispiel:

```python
print(ist_gerade(8))
```

Ausgabe:

```text
True
```

---

# 5. Eine Funktion ohne Rückgabewert: `None`

Nicht jede Funktion liefert einen Wert zurück, mit dem weitergerechnet werden soll.

Beispiel:

```python
def begruessung(name: str) -> None:
    print(f"Hallo {name}!")
```

`-> None` bedeutet:

> Diese Funktion gibt keinen eigentlichen Nutzwert zurück.

Der implizite Rückgabewert einer solchen Funktion ist `None`.

Ein typisches Beispiel ist eine Funktion, die nur etwas ausgibt:

```python
def zeige_temperatur(temperatur: float) -> None:
    print(f"Temperatur: {temperatur} °C")
```

---

# 6. Type Hints bei Variablen

Auch Variablen können mit Type Hints versehen werden.

```python
anzahl: int = 5
name: str = "Anna"
temperatur: float = 21.5
aktiv: bool = True
```

Die allgemeine Schreibweise lautet:

```python
variable: typ = wert
```

Eine Annotation kann auch ohne sofortige Zuweisung geschrieben werden:

```python
ergebnis: float
```

Später kann ein Wert zugewiesen werden:

```python
ergebnis = 12.5
```

Im normalen Python-Code ist es aber oft nicht notwendig, jede lokale Variable zu annotieren.

Zum Beispiel ist hier der Typ bereits sehr deutlich:

```python
anzahl = 5
name = "Anna"
```

Ein Type Checker kann diese Typen meist selbst ableiten.

> Type Hints sollen den Code verständlicher machen. Sie müssen nicht an jede einzelne Variable geschrieben werden.

---

# 7. Schleifenvariablen müssen normalerweise nicht extra annotiert werden

Eine Konstruktion wie diese ist möglich:

```python
i: int

for i in range(10):
    print(i)
```

Sie ist aber normalerweise unnötig.

Aus

```python
for i in range(10):
    ...
```

können Type Checker bereits erkennen, dass `i` hier ein `int` ist.

Deshalb genügt:

```python
for i in range(10):
    print(i)
```

Auch bei anderen Schleifen kann der Typ häufig aus dem Iterable abgeleitet werden:

```python
namen: list[str] = ["Anna", "Ben", "Clara"]

for name in namen:
    print(name.upper())
```

Aus `list[str]` folgt, dass `name` ein `str` ist.

# 8. Sammlungsdatentypen

Bei Sammlungen ist oft nicht nur interessant, **welche Art von Sammlung** verwendet wird, sondern auch, **welche Elemente darin enthalten sind**.

---

## `list`

Eine Liste von Ganzzahlen:

```python
zahlen: list[int] = [1, 2, 3, 4]
```

Eine Liste von Strings:

```python
namen: list[str] = ["Anna", "Ben", "Clara"]
```

Eine Liste von Gleitkommazahlen:

```python
temperaturen: list[float] = [18.5, 20.1, 17.8]
```

Eine passende Funktion:

```python
def mittelwert(werte: list[float]) -> float:
    return sum(werte) / len(werte)
```

---

## `set`

Ein Set von Strings:

```python
faecher: set[str] = {"Mathematik", "Informatik", "Physik"}
```

Eine Funktion könnte beispielsweise so aussehen:

```python
def enthaelt_fach(faecher: set[str], gesucht: str) -> bool:
    return gesucht in faecher
```

---

## `dict`

Bei einem Dictionary werden zwei Typen angegeben:

```text
dict[typ_der_schluessel, typ_der_werte]
```

Beispiel:

```python
temperaturen: dict[str, float] = {
    "08:00": 4.2,
    "10:00": 7.8,
    "12:00": 11.5
}
```

Hier sind:

- die Schlüssel vom Typ `str`,
- die Werte vom Typ `float`.

Eine Funktion könnte so typisiert werden:

```python
def hoechste_temperatur(daten: dict[str, float]) -> float:
    return max(daten.values())
```

---

## `tuple`

Bei Tupeln kann für jede Position ein eigener Typ angegeben werden.

```python
messung: tuple[str, float] = ("08:00", 4.2)
```

Das bedeutet:

```text
Position 1 → str
Position 2 → float
```

Ein Tupel aus genau zwei Ganzzahlen:

```python
punkt: tuple[int, int] = (4, 7)
```

Wenn ein Tupel beliebig viele Elemente desselben Typs enthalten darf, wird `...` verwendet:

```python
werte: tuple[int, ...] = (1, 2, 3, 4, 5)
```

# 9. Verschachtelte Typen lesen

Type Hints können ineinander verschachtelt werden.

Beispiel:

```python
messreihen: list[list[float]] = [
    [12.5, 13.1, 14.0],
    [10.8, 11.4, 12.2]
]
```

Lies den Typ von innen nach außen:

```text
float
↓
list[float]
↓
list[list[float]]
```

Also:

> eine Liste, deren Elemente Listen von `float`-Werten sind.

Ein weiteres Beispiel:

```python
messungen: dict[str, list[float]]
```

Das bedeutet:

> ein Dictionary mit Strings als Schlüsseln und Listen von Gleitkommazahlen als Werten.

---

# 10. Nicht unnötig auf `list` einschränken

Betrachte noch einmal:

```python
def anzahl_gerade(zahlen: list[int]) -> int:
    return len([zahl for zahl in zahlen if zahl % 2 == 0])
```

Die Funktion verändert die Liste nicht.

Sie durchläuft lediglich die enthaltenen Zahlen.

Eigentlich würde sie auch mit einem Tupel funktionieren:

```python
anzahl_gerade((1, 2, 3, 4))
```

Oder mit einem `range`-Objekt:

```python
anzahl_gerade(range(10))
```

Der Type Hint `list[int]` behauptet aber, dass ausdrücklich eine Liste erwartet wird.

Wenn eine Funktion nur verlangt, dass Zahlen **durchlaufen** werden können, ist ein allgemeinerer Typ oft passender.

Dafür können wir `Iterable` verwenden:

```python
from collections.abc import Iterable


def anzahl_gerade(zahlen: Iterable[int]) -> int:
    return len([
        zahl
        for zahl in zahlen
        if zahl % 2 == 0
    ])
```

Nun beschreibt der Type Hint genauer, was die Funktion wirklich benötigt:

> ein Iterable, das `int`-Werte liefert.

Dadurch sind beispielsweise gültig:

```python
print(anzahl_gerade([1, 2, 3, 4]))
print(anzahl_gerade((1, 2, 3, 4)))
print(anzahl_gerade(range(10)))
```

Das knüpft direkt an die bereits bekannten Iterables an.

---

# 11. Mehrere mögliche Typen

Manchmal darf ein Wert mehr als einen Typ haben.

Zum Beispiel könnte eine Funktion sowohl ganze Zahlen als auch Gleitkommazahlen akzeptieren.

In modernem Python kann dafür `|` verwendet werden:

```python
def verdoppeln(zahl: int | float) -> int | float:
    return zahl * 2
```

Der Typ

```python
int | float
```

bedeutet:

> `int` **oder** `float`

Beispiele:

```python
print(verdoppeln(4))
print(verdoppeln(2.5))
```

Ausgabe:

```text
8
5.0
```

Eine solche Kombination mehrerer Typen wird als **Union Type** bezeichnet.

# 12. Optionale Werte und `None`

Ein häufiger Fall ist:

> Die Funktion liefert entweder einen bestimmten Wert oder `None`.

Angenommen, wir suchen den ersten Frostwert:

```python
def erster_frost(temperaturen: list[float]) -> float | None:
    for temperatur in temperaturen:
        if temperatur < 0:
            return temperatur

    return None
```

Der Rückgabetyp lautet:

```python
float | None
```

Das bedeutet:

> Die Funktion liefert entweder einen `float` oder `None`.

Beispiel:

```python
temperaturen = [4.2, 3.1, -1.5, 2.0]

frost = erster_frost(temperaturen)

if frost is not None:
    print(f"Erster Frostwert: {frost}")
else:
    print("Kein Frostwert gefunden.")
```

---

## `None` ist nicht dasselbe wie ein optionaler Parameter

Betrachte:

```python
def wiederhole(text: str, anzahl: int = 1) -> str:
    return text * anzahl
```

`anzahl` ist beim Aufruf optional, weil ein Standardwert existiert.

Der Typ ist trotzdem einfach:

```python
int
```

Denn `None` ist kein erlaubter Wert.

Erst wenn `None` tatsächlich erlaubt sein soll, braucht man beispielsweise:

```python
def begruessung(name: str | None) -> str:
    if name is None:
        return "Hallo!"

    return f"Hallo {name}!"
```

# 13. Typen aus importierten Modulen

Type Hints können auch Klassen und Typen aus importierten Modulen verwenden.

Beispiel mit `datetime`:

```python
from datetime import datetime


def formatiere_datum(zeitpunkt: datetime) -> str:
    return zeitpunkt.strftime("%Y-%m-%d")
```

Verwendung:

```python
jetzt = datetime.now()

print(formatiere_datum(jetzt))
```

Der Type Hint

```python
zeitpunkt: datetime
```

zeigt, dass ein `datetime`-Objekt erwartet wird.

# 14. Type Hints erklären eine Funktionsschnittstelle

Wir entwickeln nun eine kleine Auswertung für die Messdaten einer Wetterstation.

Die Daten sind:

```python
temperaturen: list[float] = [
    4.2,
    -1.5,
    7.8,
    11.3,
    5.1
]
```

Wir möchten eine Funktion schreiben, die alle Werte unter einer bestimmten Grenze auswählt:

```python
def werte_unter_grenze(
    werte: list[float],
    grenze: float
) -> list[float]:
    return [
        wert
        for wert in werte
        if wert < grenze
    ]
```

Schon die erste Zeile der Funktion beantwortet mehrere Fragen:

```text
werte
→ Liste von float-Werten

grenze
→ float

Rückgabewert
→ Liste von float-Werten
```

Ein Aufruf:

```python
frostwerte = werte_unter_grenze(temperaturen, 0.0)

print(frostwerte)
```

Ausgabe:

```text
[-1.5]
```

Type Hints sind damit ein Teil der **Schnittstelle** einer Funktion.

Sie helfen dabei zu verstehen:

- Welche Daten muss ich übergeben?
- Welche Art von Ergebnis bekomme ich zurück?
- Wie ist die Funktion gedacht?

# 15. Type Hints finden Fehler früher

Ohne Type Hints:

```python
def addiere(a, b):
    return a + b
```

Ein Leser weiß nicht sofort, ob die Funktion für

- Zahlen,
- Strings,
- Listen
- oder andere Objekte

gedacht ist.

Mit Type Hints:

```python
def addiere(a: int, b: int) -> int:
    return a + b
```

ist die Absicht klar.

Nun betrachten wir:

```python
ergebnis = addiere(10, "20")
```

Python selbst entdeckt das Problem erst, wenn diese Stelle tatsächlich ausgeführt wird.

Ein statischer Type Checker kann dagegen bereits vorher erkennen:

```text
Für b wird ein int erwartet,
aber ein str wird übergeben.
```

Genau dabei helfen Werkzeuge wie `mypy`.

---

# 16. Was ist statische Typprüfung?

Bei einer **statischen Typprüfung** wird Programmcode untersucht, ohne dass alle betreffenden Programmteile ausgeführt werden müssen.

Ein Type Checker vergleicht unter anderem:

- Type Hints von Parametern,
- übergebene Argumente,
- erwartete Rückgabewerte,
- Zuweisungen zu annotierten Variablen.

Beispiel:

```python
def quadrat(zahl: int) -> int:
    return zahl ** 2


wert: int = quadrat(5)
```

Das passt zusammen.

Hier dagegen:

```python
wert: str = quadrat(5)
```

soll laut Type Hint ein `str` gespeichert werden, aber `quadrat()` liefert laut seiner Annotation einen `int`.

Ein Type Checker kann auf diesen Widerspruch hinweisen.

---

# 17. `mypy`

`mypy` ist ein statischer Type Checker für Python.

Er ist nicht Bestandteil der Python-Standardbibliothek und muss normalerweise zusätzlich installiert werden.

Eine robuste Installationsvariante ist:

```bash
python -m pip install mypy
```

Je nach System kann auch ein Befehl wie `python3` verwendet werden.

Danach kann eine Datei geprüft werden:

```bash
mypy mein_script.py
```

`mypy` analysiert den Code und meldet mögliche Typfehler.

Dabei wird das Programm nicht einfach normal ausgeführt, um diese Fehler zu finden.

---

## Beispiel

Speichere folgenden Code beispielsweise als `type_test.py`:

```python
def berechne_alter(geburtsjahr: int, aktuelles_jahr: int) -> int:
    return aktuelles_jahr - geburtsjahr


alter: int = berechne_alter("2008", 2026)

print(alter)
```

Python würde beim Ausführen an der Subtraktion scheitern, weil ein String und ein Integer nicht subtrahiert werden können.

`mypy` kann bereits bei der statischen Prüfung erkennen, dass beim Funktionsaufruf der falsche Typ verwendet wird:

```bash
mypy type_test.py
```

Sinngemäß meldet der Type Checker:

```text
Argument 1 hat den Typ str,
erwartet wird int.
```

Die genaue Formulierung einer Fehlermeldung kann sich je nach `mypy`-Version unterscheiden.

# 18. Type Checker und Entwicklungsumgebung

Viele moderne Entwicklungsumgebungen und Editoren können Type Hints auswerten.

Dadurch können sie beispielsweise:

- problematische Funktionsaufrufe markieren,
- bessere Autovervollständigung anbieten,
- erwartete Parameter anzeigen,
- Rückgabetypen ableiten.

Wichtig ist die Unterscheidung:

```text
Python-Interpreter
→ führt das Programm aus

Type Checker
→ untersucht Typinformationen

IDE / Editor
→ kann Type Hints für Hinweise und Unterstützung verwenden
```

Eine Warnung der Entwicklungsumgebung ist daher nicht automatisch dasselbe wie ein Laufzeitfehler von Python.

---

# 19. Type Hints ersetzen keine Prüfung von Benutzereingaben

Angenommen:

```python
def verdoppeln(zahl: int) -> int:
    return zahl * 2
```

Nun lesen wir eine Eingabe ein:

```python
eingabe = input("Zahl: ")
```

`input()` liefert immer einen String.

Der Type Hint der Funktion wandelt diesen String nicht automatisch in einen Integer um.

Wir müssen weiterhin selbst konvertieren:

```python
zahl = int(eingabe)

print(verdoppeln(zahl))
```

Ebenso verhindern Type Hints keine ungültigen Werte.

Eine Annotation

```python
alter: int
```

sagt nur, dass ein Integer erwartet wird.

Sie sagt nicht automatisch:

```text
0 <= alter <= 130
```

Solche **inhaltlichen Bedingungen** müssen weiterhin mit normalem Programmcode geprüft werden.

---

# 20. Gute Type Hints statt möglichst vieler Type Hints

Type Hints sind besonders wertvoll an Stellen, an denen Code von anderen Programmteilen verwendet wird.

Vor allem bei Funktionen:

```python
def berechne_mittelwert(werte: list[float]) -> float:
    return sum(werte) / len(werte)
```

Weniger hilfreich ist es, jede offensichtliche lokale Variable zusätzlich zu annotieren:

```python
summe: float = 0.0
anzahl: int = len(werte)
```

Das kann sinnvoll sein, ist aber nicht automatisch besser.

Als einfache Regel:

> Annotiere vor allem **Funktionsparameter und Rückgabewerte**. Ergänze Variablenannotationen dort, wo sie zusätzliche Klarheit schaffen.

# 21. Häufige Fehler und Missverständnisse

## Type Hints für Laufzeitkontrollen halten

Falsch ist die Vorstellung:

```text
Wenn ich x: int schreibe,
verhindert Python automatisch jeden anderen Typ.
```

Das tut Python normalerweise nicht.

Type Hints sind keine automatische Laufzeitvalidierung.

---

## Nur den äußeren Sammlungstyp angeben

Wenig aussagekräftig:

```python
werte: list = [1, 2, 3]
```

Besser:

```python
werte: list[int] = [1, 2, 3]
```

Dadurch wird auch der Typ der Elemente beschrieben.

---

## Eine Funktion unnötig auf `list` beschränken

Wenn nur durch Werte iteriert wird:

```python
def summe(zahlen: list[int]) -> int:
    return sum(zahlen)
```

kann ein allgemeiner Typ sinnvoller sein:

```python
from collections.abc import Iterable


def summe(zahlen: Iterable[int]) -> int:
    return sum(zahlen)
```

Dann passen beispielsweise auch Tupel und `range`-Objekte zur beschriebenen Schnittstelle.

---

## `None` im Rückgabetyp vergessen

Wenn eine Funktion tatsächlich `None` liefern kann:

```python
def finde_negativ(zahlen: list[int]) -> int | None:
    for zahl in zahlen:
        if zahl < 0:
            return zahl

    return None
```

Dann sollte der Type Hint diese Möglichkeit auch ausdrücken.

---

## Type Hints mit Dokumentation verwechseln

Ein Type Hint kann zeigen:

```python
def rabatt(preis: float, prozent: float) -> float:
    ...
```

Er erklärt aber noch nicht:

- ob `prozent` zwischen `0` und `100` liegen soll,
- ob negative Preise erlaubt sind,
- wie gerundet wird.

Type Hints ergänzen guten Code und Dokumentation, ersetzen sie aber nicht vollständig.

# Übungen

Bei Type Hints ist es besonders wichtig, zuerst die **Schnittstelle** einer Funktion zu verstehen und erst danach den Code zu annotieren.

---

## Übung 1 – Eine vorhandene Funktion typisieren

Gegeben ist:

```python
def anzahl_positive(zahlen):
    return len([
        zahl
        for zahl in zahlen
        if zahl > 0
    ])
```

Ergänze passende Type Hints.

Die Funktion soll Listen von Ganzzahlen erhalten.

### Lösungsschema

Frage zuerst:

```text
Was erhält die Funktion?
→ eine Liste

Was befindet sich in der Liste?
→ int

Welchen Wert liefert len(...)?
→ int
```

Damit entsteht die Schnittstelle:

```text
zahlen: list[int]

Rückgabewert:
int
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

```python
def anzahl_positive(zahlen: list[int]) -> int:
    return len([
        zahl
        for zahl in zahlen
        if zahl > 0
    ])
```

Eine allgemeinere Variante wäre:

```python
from collections.abc import Iterable


def anzahl_positive(zahlen: Iterable[int]) -> int:
    return len([
        zahl
        for zahl in zahlen
        if zahl > 0
    ])
```

Diese Variante ist passend, wenn die Funktion nicht ausdrücklich eine Liste benötigt, sondern jedes Iterable von Ganzzahlen akzeptieren soll.

</details>

---

## Übung 2 – Eine Schnittstelle aus einer Aufgabenstellung entwickeln

Schreibe eine Funktion `suche_name()`.

Sie erhält:

- eine Liste von Namen,
- einen gesuchten Namen.

Wenn der Name vorhanden ist, soll er zurückgegeben werden.

Wenn er nicht vorhanden ist, soll `None` zurückgegeben werden.

### Lösungsschema

Bestimme zuerst die Typen:

```text
Liste von Namen
→ list[str]

gesuchter Name
→ str
```

Nun der Rückgabewert:

```text
gefunden
→ str

nicht gefunden
→ None
```

Also:

```text
Rückgabetyp
→ str | None
```

Die Schnittstelle lautet damit schematisch:

```python
def suche_name(
    namen: list[str],
    gesucht: str
) -> str | None:
    ...
```

Erst danach wird die eigentliche Suchlogik ergänzt.

<details>
<summary>Vollständige Lösung anzeigen</summary>

```python
def suche_name(
    namen: list[str],
    gesucht: str
) -> str | None:
    for name in namen:
        if name == gesucht:
            return name

    return None
```

Beispiel:

```python
namen = ["Anna", "Ben", "Clara"]

ergebnis = suche_name(namen, "Ben")

if ergebnis is not None:
    print(f"Gefunden: {ergebnis}")
else:
    print("Name nicht gefunden.")
```

</details>

## Übung 3 – Typfehler finden

Gegeben ist:

```python
def celsius_zu_fahrenheit(celsius: float) -> float:
    return celsius * 1.8 + 32


temperatur: float = "18.5"

ergebnis: str = celsius_zu_fahrenheit(temperatur)
```

Finde die Typfehler, ohne den Code auszuführen.

### Lösungsschema

Prüfe Zeile für Zeile:

```text
temperatur: float
→ Welcher Typ wird tatsächlich zugewiesen?

celsius_zu_fahrenheit(...)
→ Welchen Rückgabetyp verspricht die Funktion?

ergebnis: str
→ Passt dieser Typ zum Rückgabetyp?
```

Es gibt zwei Widersprüche.

<details>
<summary>Vollständige Lösung anzeigen</summary>

Problem 1:

```python
temperatur: float = "18.5"
```

`"18.5"` ist ein `str`, kein `float`.

Korrekt:

```python
temperatur: float = 18.5
```

Problem 2:

```python
ergebnis: str = celsius_zu_fahrenheit(temperatur)
```

Die Funktion liefert laut Type Hint einen `float`.

Korrekt:

```python
ergebnis: float = celsius_zu_fahrenheit(temperatur)
```

Die korrigierte Version:

```python
def celsius_zu_fahrenheit(celsius: float) -> float:
    return celsius * 1.8 + 32


temperatur: float = 18.5

ergebnis: float = celsius_zu_fahrenheit(temperatur)

print(ergebnis)
```

</details>

# Zusammenfassung

Python ist eine **dynamisch typisierte** Programmiersprache.

Type Hints ergänzen den Code um Typinformationen, ändern aber das grundlegende Laufzeitverhalten von Python nicht.

# Wichtige Begriffe

### Dynamische Typisierung

Der Typ gehört in Python zum Objekt. Variablennamen sind nicht dauerhaft auf einen Typ festgelegt.

### Type Hint

Eine Typinformation im Quellcode, die beschreibt, welcher Typ erwartet wird.

### Type Annotation

Die konkrete Schreibweise eines Type Hints im Code, beispielsweise:

```python
zahl: int
```

### Rückgabetyp

Der Typ hinter `->`:

```python
def funktion() -> int:
    ...
```

### Union Type

Mehrere erlaubte Typen:

```python
int | float
```

### Statische Typprüfung

Analyse der Typinformationen eines Programms, ohne alle betreffenden Codepfade normal auszuführen.

### `mypy`

Ein externer statischer Type Checker für Python.

# Das sollst du können

Nach diesem Kapitel solltest du ...

- erklären können, warum Python trotz Type Hints dynamisch typisiert bleibt.
- Type Hints für Parameter schreiben können.
- Rückgabetypen mit `->` angeben können.
- `None` als Rückgabetyp korrekt verwenden können.
- Listen, Sets, Dictionaries und Tupel typisieren können.
- verschachtelte Type Hints lesen können.
- mehrere mögliche Typen mit `|` angeben können.
- `T | None` für möglicherweise fehlende Werte verwenden können.
- erkennen können, wann `Iterable[T]` passender als `list[T]` ist.
- Typen aus importierten Modulen verwenden können.
- erklären können, warum Type Hints keine Laufzeitvalidierung ersetzen.
- `mypy` installieren und auf eine Python-Datei anwenden können.
- Type-Hint-Fehler in einfachen Programmen erkennen können.

## Merksätze

```text
parameter: typ
→ Welchen Typ soll ein Parameter haben?

-> typ
→ Welchen Typ soll die Funktion zurückgeben?

list[int]
→ Liste von Ganzzahlen

dict[str, float]
→ Dictionary mit str-Schlüsseln und float-Werten

int | float
→ int oder float

str | None
→ String oder kein Wert

Iterable[int]
→ etwas Durchlaufbares, das int-Werte liefert
```

Der wichtigste Gedanke:

> Type Hints sind ein Vertrag für die beabsichtigte Verwendung des Codes – keine automatische Laufzeitsperre.

Type Hints sind besonders nützlich, wenn Funktionen eine klare Schnittstelle bekommen sollen.

Ab diesem Kapitel sollten daher bei neu geschriebenen Funktionen grundsätzlich Type Hints für **Parameter und Rückgabewerte** verwendet werden.
