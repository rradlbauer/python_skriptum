# 1. Was sind spezielle Methoden?

In Python können Klassen sogenannte **spezielle Methoden** definieren.

Diese Methoden besitzen besondere Namen wie:

```text
__init__
__str__
__repr__
__add__
__eq__
__len__
```

Sie beginnen und enden normalerweise mit zwei Unterstrichen.

Darum werden sie häufig **Dunder Methods** genannt:

```text
double underscore
→ dunder
```

Manchmal findet man auch die Bezeichnung:

```text
Magic Methods
```

Der Ausdruck „Dunder Methods“ ist meist genauer, weil an diesen Methoden nichts Magisches passiert.

Sie bilden eine definierte Schnittstelle zwischen unseren Klassen und der Python-Sprache.

---

# 2. Python übersetzt viele Operationen in spezielle Methoden

Wenn du schreibst:

```python
a + b
```

verwendet Python sinngemäß eine spezielle Methode wie:

```text
a.__add__(b)
```

Wenn du schreibst:

```python
str(objekt)
```

wird typischerweise verwendet:

```text
objekt.__str__()
```

Bei:

```python
len(objekt)
```

spielt:

```text
objekt.__len__()
```

eine Rolle.

Und:

```python
a == b
```

führt zu einem Vergleich über:

```text
__eq__()
```

Damit können eigene Klassen an normalen Python-Operationen teilnehmen.

# 3. Das Python Data Model

Diese Regeln gehören zum **Python Data Model**.

Es beschreibt unter anderem:

- wie Objekte erzeugt werden,
- wie sie als Text dargestellt werden,
- wie Operatoren funktionieren,
- wie Vergleiche durchgeführt werden,
- wie Objekte iterierbar werden,
- wie Indexzugriffe funktionieren,
- wie Wahrheitswerte bestimmt werden.

Spezielle Methoden sind daher nicht nur Zusatzfunktionen.

> Sie legen fest, wie sich Instanzen einer eigenen Klasse als Python-Objekte verhalten.

# 4. `__init__()` kennst du bereits

Beispiel:

```python
class Person:
    def __init__(
        self,
        name: str,
        alter: int
    ) -> None:
        self.name: str = name
        self.alter: int = alter
```

Beim Erzeugen:

```python
person = Person(
    "Anna",
    30
)
```

wird die neue Instanz initialisiert.

---

# 5. Ist `__init__()` wirklich der Konstruktor?

Im Unterricht wird `__init__()` häufig vereinfachend als **Konstruktor** bezeichnet.

Technisch genauer ist:

- `__new__()` ist für die eigentliche Erzeugung einer Instanz zuständig.
- `__init__()` initialisiert die bereits erzeugte Instanz.

Für normale eigene Klassen musst du `__new__()` fast nie selbst definieren.

Darum genügt in der Praxis meist:

> `__init__()` legt den Anfangszustand eines neu erzeugten Objekts fest.

Wichtig:

```python
def __init__(self) -> None:
    ...
```

`__init__()` darf keinen anderen Rückgabewert als `None` liefern.

# 6. String-Darstellung mit `__str__()`

Ohne eigene String-Darstellung:

```python
class Person:
    def __init__(
        self,
        name: str,
        alter: int
    ) -> None:
        self.name: str = name
        self.alter: int = alter


person = Person(
    "Anna",
    30
)

print(person)
```

Die Ausgabe sieht typischerweise technisch aus.

Zum Beispiel sinngemäß:

```text
<__main__.Person object at 0x...>
```

Das ist für Benutzer wenig hilfreich.

# 7. `__str__()` definieren

```python
class Person:
    def __init__(
        self,
        name: str,
        alter: int
    ) -> None:
        self.name: str = name
        self.alter: int = alter

    def __str__(self) -> str:
        return (
            f"{self.name}, "
            f"{self.alter} Jahre alt"
        )
```

Nun:

```python
person = Person(
    "Anna",
    30
)

print(person)
```

Ausgabe:

```text
Anna, 30 Jahre alt
```

---

# 8. Wann wird `__str__()` verwendet?

Unter anderem bei:

```python
str(person)
```

und:

```python
print(person)
```

Beispiel:

```python
text = str(person)

print(text)
```

`__str__()` sollte eine gut lesbare Darstellung für Menschen liefern.

---

# 9. `__str__()` muss einen String zurückgeben

Falsch:

```python
class Person:
    def __str__(self) -> str:
        return 42
```

Richtig:

```python
class Person:
    def __str__(self) -> str:
        return self.name
```

Die Rückgabe muss ein Objekt vom Typ `str` sein.

---

# 10. `__repr__()` – Darstellung für Entwickler

Neben `__str__()` gibt es:

```python
__repr__()
```

Diese Darstellung ist vor allem für:

- Debugging,
- Entwicklungswerkzeuge,
- interaktive Python-Sitzungen

gedacht.

Beispiel:

```python
class Person:
    def __init__(
        self,
        name: str,
        alter: int
    ) -> None:
        self.name: str = name
        self.alter: int = alter

    def __str__(self) -> str:
        return (
            f"{self.name}, "
            f"{self.alter} Jahre alt"
        )

    def __repr__(self) -> str:
        return (
            f"Person("
            f"name={self.name!r}, "
            f"alter={self.alter!r}"
            f")"
        )
```

---

# 11. `str()` und `repr()` vergleichen

```python
person = Person(
    "Anna",
    30
)

print(str(person))
print(repr(person))
```

Mögliche Ausgabe:

```text
Anna, 30 Jahre alt
Person(name='Anna', alter=30)
```

Vereinfacht:

```text
__str__()
→ gut lesbar für Benutzer

__repr__()
→ informationsreiche Darstellung für Entwickler
```

---

# 12. Warum steht in `__repr__()` oft `!r`?

In einem f-String:

```python
f"{self.name!r}"
```

bedeutet `!r`, dass `repr()` für den Wert verwendet wird.

Bei Strings werden dadurch beispielsweise Anführungszeichen sichtbar.

```python
name = "Anna"

print(f"{name}")
print(f"{name!r}")
```

Ausgabe:

```text
Anna
'Anna'
```

Das ist für Debugging-Darstellungen oft nützlich.

---

# 13. Fallback von `__str__()` auf `__repr__()`

Wenn eine Klasse `__repr__()`, aber kein eigenes `__str__()` definiert, verwendet Python für die normale String-Darstellung typischerweise ebenfalls die `__repr__()`-Darstellung.

Darum ist `__repr__()` eine besonders wichtige grundlegende Darstellung.

In einfachen Schülerprogrammen reicht zunächst häufig `__str__()`.

# 14. Operator Overloading

Eigene Objekte können auf Operatoren reagieren.

Beispiel:

```python
v1 + v2
```

Für eine eigene Klasse können wir festlegen, was `+` bedeutet.

Das nennt man:

```text
Operator Overloading
```

oder:

```text
Operatorüberladung
```

Dabei wird ein bereits existierender Operator für einen eigenen Datentyp sinnvoll definiert.

---

# 15. Beispielklasse `Vektor`

```python
class Vektor:
    def __init__(
        self,
        x: float,
        y: float
    ) -> None:
        self.x: float = x
        self.y: float = y

    def __str__(self) -> str:
        return (
            f"Vektor({self.x}, {self.y})"
        )
```

Nun möchten wir schreiben können:

```python
v1 + v2
```

---

# 16. Addition mit `__add__()`

```python
class Vektor:
    def __init__(
        self,
        x: float,
        y: float
    ) -> None:
        self.x: float = x
        self.y: float = y

    def __add__(
        self,
        other: "Vektor"
    ) -> "Vektor":
        return Vektor(
            self.x + other.x,
            self.y + other.y
        )

    def __str__(self) -> str:
        return (
            f"Vektor({self.x}, {self.y})"
        )
```

Verwendung:

```python
v1 = Vektor(2, 3)
v2 = Vektor(4, 5)

v3 = v1 + v2

print(v3)
```

Ausgabe:

```text
Vektor(6, 8)
```

---

# 17. Was passiert bei `v1 + v2`?

Vereinfacht:

```text
v1 + v2
```

führt zu:

```text
v1.__add__(v2)
```

Dabei ist:

```text
self
→ v1

other
→ v2
```

Die Methode erzeugt einen neuen Vektor.

Der ursprüngliche `v1` und `v2` bleiben unverändert.

---

# 18. Subtraktion mit `__sub__()`

```python
def __sub__(
    self,
    other: "Vektor"
) -> "Vektor":
    return Vektor(
        self.x - other.x,
        self.y - other.y
    )
```

Dann:

```python
v3 = v1 - v2
```

verwendet die definierte Subtraktion.

# 19. Multiplikation mit einem Skalar

Für einen Vektor ist beispielsweise sinnvoll:

```text
Vektor * Zahl
```

```python
def __mul__(
    self,
    scalar: float
) -> "Vektor":
    return Vektor(
        self.x * scalar,
        self.y * scalar
    )
```

Nun:

```python
v = Vektor(2, 3)

print(v * 2)
```

Ausgabe:

```text
Vektor(4, 6)
```

---

# 20. Aber was ist mit `2 * v`?

Unsere Methode:

```python
__mul__()
```

behandelt:

```text
v * 2
```

Nicht automatisch:

```text
2 * v
```

Für die umgekehrte Reihenfolge gibt es reflektierte Operatoren.

Bei Multiplikation:

```python
__rmul__()
```

---

# 21. Reflektierter Operator `__rmul__()`

```python
def __rmul__(
    self,
    scalar: float
) -> "Vektor":
    return self * scalar
```

Dann funktionieren beide Varianten:

```python
v = Vektor(2, 3)

print(v * 2)
print(2 * v)
```

Beide können liefern:

```text
Vektor(4, 6)
```

# 22. Division mit `__truediv__()`

Der Operator:

```text
/
```

wird durch:

```python
__truediv__()
```

unterstützt.

```python
def __truediv__(
    self,
    scalar: float
) -> "Vektor":
    if scalar == 0:
        raise ZeroDivisionError(
            "Vektor kann nicht durch 0 dividiert werden."
        )

    return Vektor(
        self.x / scalar,
        self.y / scalar
    )
```

# 23. Weitere mathematische Operatoren

Einige wichtige Zuordnungen:

| Operator | Spezielle Methode |
|---|---|
| `a + b` | `__add__()` |
| `a - b` | `__sub__()` |
| `a * b` | `__mul__()` |
| `a / b` | `__truediv__()` |
| `a // b` | `__floordiv__()` |
| `a % b` | `__mod__()` |
| `a ** b` | `__pow__()` |
| `-a` | `__neg__()` |
| `+a` | `__pos__()` |
| `abs(a)` | `__abs__()` |

Nicht jede Klasse braucht diese Methoden.

Sie sollten nur definiert werden, wenn die Operation fachlich sinnvoll ist.

# 24. `NotImplemented` bei nicht unterstützten Operanden

Unsere erste Version von:

```python
__add__()
```

geht davon aus, dass `other` wirklich ein `Vektor` ist.

Was passiert bei:

```python
v + "Hallo"
```

Eine saubere Implementierung prüft den Operandentyp.

```python
def __add__(
    self,
    other: object
) -> "Vektor":
    if not isinstance(
        other,
        Vektor
    ):
        return NotImplemented

    return Vektor(
        self.x + other.x,
        self.y + other.y
    )
```

---

# 25. Warum `NotImplemented`?

`NotImplemented` bedeutet:

> Diese Methode unterstützt diese Kombination von Operanden nicht.

Python kann dann gegebenenfalls eine alternative passende Methode prüfen.

Wenn keine passende Operation existiert, entsteht schließlich typischerweise ein `TypeError`.

Wichtig:

```text
NotImplemented
```

ist nicht dasselbe wie:

```text
NotImplementedError
```

`NotImplemented` ist ein spezieller Rückgabewert.

`NotImplementedError` ist eine Exception.

# 26. Vollständigere Vektorklasse

```python
class Vektor:
    def __init__(
        self,
        x: float,
        y: float
    ) -> None:
        self.x: float = x
        self.y: float = y

    def __add__(
        self,
        other: object
    ) -> "Vektor":
        if not isinstance(
            other,
            Vektor
        ):
            return NotImplemented

        return Vektor(
            self.x + other.x,
            self.y + other.y
        )

    def __sub__(
        self,
        other: object
    ) -> "Vektor":
        if not isinstance(
            other,
            Vektor
        ):
            return NotImplemented

        return Vektor(
            self.x - other.x,
            self.y - other.y
        )

    def __mul__(
        self,
        scalar: float
    ) -> "Vektor":
        if not isinstance(
            scalar,
            int | float
        ):
            return NotImplemented

        return Vektor(
            self.x * scalar,
            self.y * scalar
        )

    def __rmul__(
        self,
        scalar: float
    ) -> "Vektor":
        return self * scalar

    def __truediv__(
        self,
        scalar: float
    ) -> "Vektor":
        if not isinstance(
            scalar,
            int | float
        ):
            return NotImplemented

        if scalar == 0:
            raise ZeroDivisionError(
                "Division durch 0."
            )

        return Vektor(
            self.x / scalar,
            self.y / scalar
        )

    def __str__(self) -> str:
        return (
            f"Vektor({self.x}, {self.y})"
        )
```

# 27. Objekte vergleichen

Ohne eigenes `__eq__()`:

```python
v1 = Vektor(2, 3)
v2 = Vektor(2, 3)

print(v1 == v2)
```

liefert bei normalen eigenen Klassen typischerweise:

```text
False
```

obwohl beide dieselben Komponenten besitzen.

Warum?

Weil sie zwei verschiedene Objekte sind und die Standard-Gleichheitslogik von `object` im Ergebnis auf Objektidentität basiert.

---

# 28. Gleichheit mit `__eq__()`

Für Vektoren ist folgende Regel sinnvoll:

```text
Zwei Vektoren sind gleich,
wenn ihre x- und y-Komponenten gleich sind.
```

Implementierung:

```python
def __eq__(
    self,
    other: object
) -> bool:
    if not isinstance(
        other,
        Vektor
    ):
        return NotImplemented

    return (
        self.x == other.x
        and self.y == other.y
    )
```

---

# 29. Warum bei fremdem Typ nicht einfach `False`?

Man könnte schreiben:

```text
if not isinstance(other, Vektor):
    return False
```

Sauberer ist bei Vergleichsmethoden häufig:

```text
return NotImplemented
```

Damit signalisiert die Methode:

> Ich kann diesen Vergleich nicht beurteilen.

Python kann dann gegebenenfalls die Vergleichslogik des anderen Operanden berücksichtigen.

---

# 30. Gleichheit verwenden

```python
v1 = Vektor(2, 3)
v2 = Vektor(2, 3)
v3 = Vektor(3, 4)

print(v1 == v2)
print(v1 == v3)
```

Ausgabe:

```text
True
False
```

Nun beschreibt `==` fachliche Gleichheit und nicht nur Identität.

---

# 31. `==` und `is` bleiben verschieden

Auch nach eigenem `__eq__()`:

```python
v1 = Vektor(2, 3)
v2 = Vektor(2, 3)

print(v1 == v2)
print(v1 is v2)
```

Ausgabe:

```text
True
False
```

Das knüpft direkt an Kapitel 24 an:

```text
==
→ Gleichheit

is
→ Identität
```

---

# 32. Muss `__ne__()` selbst definiert werden?

In älteren Beispielen sieht man häufig:

```python
def __ne__(self, other):
    return not self.__eq__(other)
```

Das ist normalerweise nicht notwendig.

Für normale eigene Klassen kann Python `!=` auf Basis von `__eq__()` behandeln.

Deshalb genügt häufig:

```text
def __eq__(...):
    ...
```

und:

```python
v1 != v2
```

funktioniert entsprechend.

# 34. Nach welcher Regel sind Vektoren größer?

Bei Vektoren gibt es keine natürliche universelle Größenordnung.

Für unser Beispiel legen wir ausdrücklich fest:

> Wir vergleichen Vektoren nach ihrer Länge.

Die Länge berechnet sich nach Pythagoras.

```python
from math import hypot


def laenge(self) -> float:
    return hypot(
        self.x,
        self.y
    )
```

---

# 35. `<` mit `__lt__()`

```python
def __lt__(
    self,
    other: object
) -> bool:
    if not isinstance(
        other,
        Vektor
    ):
        return NotImplemented

    return (
        self.laenge()
        < other.laenge()
    )
```

Dann:

```python
v1 = Vektor(2, 3)
v2 = Vektor(3, 4)

print(v1 < v2)
```

Ausgabe:

```text
True
```

---

# 36. Nicht automatisch alle Vergleichsoperatoren ableiten

Wenn wir nur:

```python
__eq__()
```

und:

```python
__lt__()
```

definieren, erzeugt Python nicht automatisch alle anderen Größenvergleiche.

Eine Möglichkeit wäre, alle gewünschten Methoden selbst zu definieren.

Eine bequemere Alternative ist:

```python
functools.total_ordering
```

---

# 37. `@total_ordering`

```python
from functools import total_ordering


@total_ordering
class Vektor:
    ...
```

Die Klasse benötigt:

- `__eq__()`
- mindestens eine Ordnungsvergleichsmethode, beispielsweise `__lt__()`

Dann ergänzt `total_ordering` die übrigen Größenvergleichsoperationen.

---

# 38. Beispiel mit `total_ordering`

```python
from functools import total_ordering
from math import hypot


@total_ordering
class Vektor:
    def __init__(
        self,
        x: float,
        y: float
    ) -> None:
        self.x: float = x
        self.y: float = y

    def laenge(self) -> float:
        return hypot(
            self.x,
            self.y
        )

    def __eq__(
        self,
        other: object
    ) -> bool:
        if not isinstance(
            other,
            Vektor
        ):
            return NotImplemented

        return (
            self.x == other.x
            and self.y == other.y
        )

    def __lt__(
        self,
        other: object
    ) -> bool:
        if not isinstance(
            other,
            Vektor
        ):
            return NotImplemented

        return (
            self.laenge()
            < other.laenge()
        )
```

Nun funktionieren auch weitere Größenvergleiche.

# 39. Vorsicht: Gleichheit und Ordnung sollten zusammenpassen

Im vorigen Beispiel gilt:

```text
Gleichheit
→ gleiche Komponenten

Ordnung
→ Länge
```

Das ist als Demonstration möglich, kann aber überraschend sein.

Beispielsweise:

```text
Vektor(3, 4)
Vektor(0, 5)
```

haben dieselbe Länge, sind aber nicht gleich.

Bei echten Fachklassen sollte man genau überlegen:

> Welche mathematische oder fachliche Bedeutung sollen Gleichheit und Ordnung besitzen?

Spezielle Methoden sollten konsistente Regeln ausdrücken.

# 40. Sortieren eigener Objekte

Wenn `__lt__()` vorhanden ist, können Objekte beispielsweise sortiert werden.

```python
vektoren = [
    Vektor(3, 4),
    Vektor(1, 1),
    Vektor(10, 0)
]

sortiert = sorted(
    vektoren
)
```

Da unsere Ordnung die Länge verwendet, werden die Vektoren entsprechend sortiert.

Oft ist aber eine explizite `key`-Funktion verständlicher:

```python
sortiert = sorted(
    vektoren,
    key=lambda v: v.laenge()
)
```

Nicht jede Klasse braucht deshalb eigene Größenvergleichsmethoden.

# 41. `__hash__()` – ein wichtiger Zusammenhang mit `__eq__()`

Hashwerte werden unter anderem verwendet für:

```text
dict-Schlüssel
set-Elemente
```

Abruf:

```python
hash(objekt)
```

# 42. Was passiert, wenn `__eq__()` definiert wird?

Wenn eine Klasse ein eigenes `__eq__()` definiert, aber kein passendes `__hash__()`, werden ihre Instanzen normalerweise **nicht hashbar**.

Beispiel:

```python
class Punkt:
    def __init__(
        self,
        x: int,
        y: int
    ) -> None:
        self.x: int = x
        self.y: int = y

    def __eq__(
        self,
        other: object
    ) -> bool:
        if not isinstance(
            other,
            Punkt
        ):
            return NotImplemented

        return (
            self.x == other.x
            and self.y == other.y
        )
```

Dann kann:

```python
punkt = Punkt(1, 2)

hash(punkt)
```

einen `TypeError` auslösen.

---

# 43. Warum ist das sinnvoll?

Für hashbare Objekte muss gelten:

> Wenn zwei Objekte gleich sind, müssen sie denselben Hashwert besitzen.

Außerdem darf sich der für den Hash relevante Zustand nicht verändern, während das Objekt als Schlüssel in einem Dictionary oder Element in einem Set verwendet wird.

Eine veränderliche Klasse wie unser `Vektor` sollte deshalb normalerweise **nicht einfach selbst hashbar gemacht werden**.

---

# 44. `__hash__()` nur bewusst implementieren

Für geeignete unveränderliche Wertobjekte kann man einen Hash beispielsweise aus denselben Bestandteilen bilden, die auch für `__eq__()` verwendet werden:

```text
return hash((self.x, self.y))
```

Aber:

> Definiere `__hash__()` nicht nur deshalb, weil Python es erlaubt.

Für veränderliche Klassen ist es häufig richtig, dass die Objekte nicht hashbar sind.

---

Python verwendet Objekte häufig in Bedingungen:

```python

    ...
```

```python
__bool__()
```

```python
        self,

```

```python

```

# 51. `__iter__()` delegiert an eine interne Liste

```python
from collections.abc import Iterator


class Wiedergabeliste:
    def __init__(self) -> None:
        self.titel: list[str] = []

    def hinzufuegen(
        self,
        titel: str

        self

        return iter(
            self.titel
```


Unsere Klasse speichert intern bereits eine Liste:

Die eigene Klasse muss die Iterationslogik nicht neu erfinden.

# 61. Nicht jede mögliche Methode implementieren

Nur weil eine spezielle Methode existiert, heißt das nicht, dass jede Klasse sie verwenden sollte.

Beispiel:

```text

```

Was soll das bedeuten?

Vielleicht gar nichts Sinnvolles.

Dann sollte `Person` auch kein `__add__()` besitzen.

Dagegen ist:

```text
Vektor + Vektor
```

mathematisch sinnvoll.

Merksatz:

> Definiere eine spezielle Methode nur dann, wenn die entsprechende Python-Operation für deinen Datentyp eine klare fachliche Bedeutung besitzt.

# 62. Python-Erwartungen nicht überraschend brechen

Wenn du:


definierst, erwarten Leser eine Art Anzahl oder Größe.

Wenn du:

```python

```

definierst, erwarten Leser eine sinnvolle Gleichheitsbeziehung.

Wenn du:

```python
a + b
```

definierst, sollte das Ergebnis zur Bedeutung des Datentyps passen.

Technisch ungewöhnliche Definitionen sind zwar manchmal möglich, machen Programme aber schwer verständlich.

# 63. Vollständiges Beispiel: `Vektor`

```python
from functools import total_ordering
from math import hypot


@total_ordering
class Vektor:
    def __init__(
        self,
        x: float,
        y: float
    ) -> None:
        self.x: float = x
        self.y: float = y

    def laenge(self) -> float:
        return hypot(
            self.x,
            self.y
        )

    def __str__(self) -> str:
        return (
            f"({self.x}, {self.y})"
        )

    def __repr__(self) -> str:
        return (
            f"Vektor("
            f"x={self.x!r}, "
            f"y={self.y!r}"
            f")"
        )

    def __add__(
        self,
        other: object
    ) -> "Vektor":
        if not isinstance(
            other,
            Vektor
        ):
            return NotImplemented

        return Vektor(
            self.x + other.x,
            self.y + other.y
        )

    def __sub__(
        self,
        other: object
    ) -> "Vektor":
        if not isinstance(
            other,
            Vektor
        ):
            return NotImplemented

        return Vektor(
            self.x - other.x,
            self.y - other.y
        )

    def __mul__(
        self,
        scalar: float
    ) -> "Vektor":
        if not isinstance(
            scalar,
            int | float
        ):
            return NotImplemented

        return Vektor(
            self.x * scalar,
            self.y * scalar
        )

    def __rmul__(
        self,
        scalar: float
    ) -> "Vektor":
        return self * scalar

    def __truediv__(
        self,
        scalar: float
    ) -> "Vektor":
        if not isinstance(
            scalar,
            int | float
        ):
            return NotImplemented

        if scalar == 0:
            raise ZeroDivisionError(
                "Division durch 0."
            )

        return Vektor(
            self.x / scalar,
            self.y / scalar
        )

    def __abs__(self) -> float:
        return self.laenge()

    def __eq__(
        self,
        other: object
    ) -> bool:
        if not isinstance(
            other,
            Vektor
        ):
            return NotImplemented

        return (
            self.x == other.x
            and self.y == other.y
        )

    def __lt__(
        self,
        other: object
    ) -> bool:
        if not isinstance(
            other,
            Vektor
        ):
            return NotImplemented

        return (
            self.laenge()
            < other.laenge()
        )
```

# 66. Typische Fehler und Missverständnisse

## `__init__()` als eigentliche Objekterzeugung verstehen

Für den Einstieg wird `__init__()` oft Konstruktor genannt.

Technisch initialisiert es jedoch die bereits erzeugte Instanz.

---

## In `__str__()` keinen String zurückgeben

Falsch:

```text
return 42
```

Richtig:

```text
return "42"
```

---

## Nicht unterstützte Operanden einfach verwenden

Problematisch:

```python
def __add__(self, other):
    return Vektor(
        self.x + other.x,
        self.y + other.y
    )
```

Bei einem fremden Typ entsteht dann möglicherweise ein unverständlicher Folgefehler.

Besser:

```text
Typ prüfen
→ gegebenenfalls NotImplemented
```

---

## `NotImplemented` mit `NotImplementedError` verwechseln

```text
NotImplemented
→ spezieller Rückgabewert

NotImplementedError
→ Exception
```

---

## Für fremde Typen in `__eq__()` immer `False` zurückgeben

Sauberer ist häufig:

```text
return NotImplemented
```

damit Python die Vergleichsregeln korrekt weiter anwenden kann.

---

## `__ne__()` unnötig duplizieren

Wenn `__eq__()` korrekt definiert ist, muss `__ne__()` normalerweise nicht zusätzlich geschrieben werden.

---

## `__hash__()` bei veränderlichen Objekten unüberlegt definieren

Wenn sich Werte ändern können, die Gleichheit und Hash bestimmen, kann ein Objekt als Dictionary-Schlüssel problematisch werden.

---

## Operatoren ohne sinnvolle Bedeutung definieren

Nur weil `__add__()` existiert, muss nicht jede Klasse addierbar sein.

---

## Spezielle Methoden direkt aufrufen

Statt:

```python
v1.__add__(v2)
```

schreibt man im normalen Anwendungscode:

```python
v1 + v2
```

Die speziellen Methoden definieren das Sprachverhalten; sie werden gewöhnlich indirekt über die entsprechende Python-Operation verwendet.

## Übung 1 – Geldbetrag darstellen und addieren

Definiere eine Klasse:

```text
Geldbetrag
```

mit den Attributen:

```text
betrag: float
waehrung: str
```

Anforderungen:

- `str(objekt)` soll beispielsweise `"12.50 EUR"` liefern.
- `repr(objekt)` soll eine entwicklerfreundliche Darstellung liefern.
- Zwei Geldbeträge dürfen nur addiert werden, wenn sie dieselbe Währung besitzen.
- Bei unterschiedlichen Währungen soll ein `ValueError` ausgelöst werden.
- Bei einem anderen Operandentyp soll `NotImplemented` zurückgegeben werden.
- Das Ergebnis der Addition soll ein neues Objekt sein.

### Lösungsschema

Benötigte Methoden:

```text
__init__()
__str__()
__repr__()
__add__()
```

Addition:

```text
1. Ist other ein Geldbetrag?
   nein → NotImplemented

2. Gleiche Währung?
   nein → ValueError

3. Neues Geldbetrag-Objekt erzeugen
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

```python
class Geldbetrag:
    def __init__(
        self,
        betrag: float,
        waehrung: str
    ) -> None:
        self.betrag: float = betrag
        self.waehrung: str = waehrung

    def __str__(self) -> str:
        return (
            f"{self.betrag:.2f} "
            f"{self.waehrung}"
        )

    def __repr__(self) -> str:
        return (
            f"Geldbetrag("
            f"betrag={self.betrag!r}, "
            f"waehrung={self.waehrung!r}"
            f")"
        )

    def __add__(
        self,
        other: object
    ) -> "Geldbetrag":
        if not isinstance(
            other,
            Geldbetrag
        ):
            return NotImplemented

        if (
            self.waehrung
            != other.waehrung
        ):
            raise ValueError(
                "Währungen stimmen nicht überein."
            )

        return Geldbetrag(
            self.betrag + other.betrag,
            self.waehrung
        )


a = Geldbetrag(
    10.50,
    "EUR"
)

b = Geldbetrag(
    2.00,
    "EUR"
)

print(a + b)
print(repr(a))
```

Mögliche Ausgabe:

```text
12.50 EUR
Geldbetrag(betrag=10.5, waehrung='EUR')
```

## Übung 3 – Messwert vergleichen

Definiere eine Klasse:

```text
Messwert
```

mit:

```text
wert: float
einheit: str
```

Regeln:

- Zwei Messwerte sind nur vergleichbar, wenn sie dieselbe Einheit besitzen.
- `==` soll Wert und Einheit vergleichen.
- `<` soll die Werte vergleichen.
- Verwende `@total_ordering`, damit weitere Größenvergleiche möglich werden.
- Bei einem fremden Objekttyp soll `NotImplemented` zurückgegeben werden.
- Bei unterschiedlichen Einheiten soll für Größenvergleiche ein `ValueError` entstehen.

### Lösungsschema

Benötigt:

```text
@total_ordering

__eq__()
__lt__()
```

`__eq__()`:

```text
fremder Typ
→ NotImplemented

sonst:
wert und einheit vergleichen
```

`__lt__()`:

```text
fremder Typ
→ NotImplemented

andere Einheit
→ ValueError

sonst:
werte vergleichen
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

```python
from functools import total_ordering


@total_ordering
class Messwert:
    def __init__(
        self,
        wert: float,
        einheit: str
    ) -> None:
        self.wert: float = wert
        self.einheit: str = einheit

    def __eq__(
        self,
        other: object
    ) -> bool:
        if not isinstance(
            other,
            Messwert
        ):
            return NotImplemented

        return (
            self.wert == other.wert
            and self.einheit == other.einheit
        )

    def __lt__(
        self,
        other: object
    ) -> bool:
        if not isinstance(
            other,
            Messwert
        ):
            return NotImplemented

        if (
            self.einheit
            != other.einheit
        ):
            raise ValueError(
                "Messwerte haben unterschiedliche Einheiten."
            )

        return (
            self.wert
            < other.wert
        )


a = Messwert(
    36.5,
    "°C"
)

b = Messwert(
    38.2,
    "°C"
)

print(a < b)
print(a <= b)
print(a == b)
print(a >= b)
```

</details>

# Zusammenfassung

## Spezielle Methoden

Spezielle Methoden verbinden eigene Klassen mit Python-Sprachoperationen.

Sie besitzen Namen wie:

```text
__str__
__add__
__eq__
__len__
```

---

## `__str__()`

Definiert eine gut lesbare String-Darstellung.

```python
str(objekt)
print(objekt)
```

---

## `__repr__()`

Definiert eine informationsreiche Darstellung für Entwicklung und Debugging.

```python
repr(objekt)
```

---

## Operator Overloading

Eigene Klassen können Operatoren unterstützen.

```text
+  → __add__
-  → __sub__
*  → __mul__
/  → __truediv__
```

---

## Reflektierte Operatoren

Für die umgekehrte Operandenseite gibt es beispielsweise:

```text
__rmul__
```

Damit kann etwa zusätzlich zu:

```text
vektor * 2
```

auch:

```text
2 * vektor
```

unterstützt werden.

---

## `NotImplemented`

Bei einer nicht unterstützten Kombination von Operanden kann eine spezielle Methode:

```text
return NotImplemented
```

verwenden.

Das ist kein Fehlerobjekt und nicht dasselbe wie `NotImplementedError`.

---

## Vergleich

```text
== → __eq__
<  → __lt__
<= → __le__
>  → __gt__
>= → __ge__
```

Für fremde Vergleichspartner ist `NotImplemented` häufig die passende Rückgabe.

---

## `total_ordering`

Mit:

```text
@total_ordering
```

können aus `__eq__()` und einer Ordnungsvergleichsmethode weitere Vergleichsoperationen ergänzt werden.

---

## `__hash__()`

`__hash__()` hängt eng mit `__eq__()` zusammen.

Gleiche Objekte müssen denselben Hashwert besitzen.

Veränderliche Objekte sollten nicht unüberlegt hashbar gemacht werden.

---

## Container-Verhalten

```text
len(objekt)
→ __len__()

wert in objekt
→ __contains__()

for wert in objekt
→ __iter__()

objekt[index]
→ __getitem__()
```

---

## Aufrufbares Objekt

```text
objekt()
→ __call__()
```

Damit kann eine Instanz ähnlich wie eine Funktion verwendet werden.

# Das sollst du können

Nach diesem Kapitel solltest du ...

- erklären können, warum spezielle Methoden existieren.
- erklären können, was „Dunder Method“ bedeutet.
- `__init__()` technisch korrekt einordnen können.
- `__str__()` für benutzerfreundliche Darstellungen definieren können.
- `__repr__()` für Debugging-Darstellungen definieren können.
- erklären können, wie Python Operatoren auf spezielle Methoden abbildet.
- `__add__()`, `__sub__()`, `__mul__()` und `__truediv__()` verwenden können.
- mit `__rmul__()` die umgekehrte Multiplikationsreihenfolge unterstützen können.
- `NotImplemented` bei nicht unterstützten Operandentypen einsetzen können.
- `NotImplemented` und `NotImplementedError` unterscheiden können.
- `__eq__()` korrekt implementieren können.
- `==` und `is` weiterhin unterscheiden können.
- wissen, dass `__ne__()` normalerweise nicht separat nötig ist.
- Größenvergleiche mit speziellen Methoden definieren können.
- `@total_ordering` grundsätzlich verwenden können.
- erklären können, warum Gleichheit und Ordnung fachlich sinnvoll zusammenpassen sollten.
- den Zusammenhang zwischen `__eq__()` und `__hash__()` erklären können.
- `__len__()`, `__bool__()`, `__contains__()`, `__iter__()` und `__getitem__()` einordnen können.
- eine eigene Klasse wie eine Sammlung verwendbar machen können.
- mit `__call__()` ein Objekt aufrufbar machen können.
- entscheiden können, wann eine spezielle Methode für einen Datentyp sinnvoll ist.
- typische Fehler bei speziellen Methoden erkennen können.

## Merksätze

```text
Dunder Method
→ spezielle Schnittstelle zwischen eigener Klasse und Python.

str(objekt)
→ __str__()

repr(objekt)
→ __repr__()

a + b
→ __add__()

a == b
→ __eq__()

len(objekt)
→ __len__()

wert in objekt
→ __contains__()

for x in objekt
→ __iter__()

objekt[index]
→ __getitem__()

objekt()
→ __call__()
```

Der wichtigste Gedanke:

> Spezielle Methoden ermöglichen es, eigene Klassen so in Python zu integrieren, dass ihre Instanzen natürliche Sprachoperationen unterstützen. Eine gute spezielle Methode bildet dabei keine beliebige technische Möglichkeit ab, sondern eine klare und erwartbare Bedeutung des eigenen Datentyps.
