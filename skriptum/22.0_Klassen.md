# 1. Warum brauchen wir eigene Klassen?

Bisher hast du mit vielen verschiedenen Datentypen gearbeitet:

```python
anzahl: int = 5
temperatur: float = 21.5
name: str = "Anna"
zahlen: list[int] = [1, 2, 3]
```

Diese Datentypen wurden bereits von Python definiert.

Auch aus Modulen hast du schon Klassen verwendet:

```python
from datetime import date

heute: date = date.today()
```

`date` ist eine Klasse aus dem Modul `datetime`.

`heute` verweist auf ein Objekt dieser Klasse.

Aber was ist, wenn wir Daten modellieren möchten, für die Python keinen fertigen Datentyp besitzt?

Stell dir vor, wir programmieren eine kleine Schulbibliothek.

Zu jedem Buch möchten wir speichern:

- Titel
- Autor
- Erscheinungsjahr
- ob das Buch ausgeliehen ist
- an wen das Buch ausgeliehen ist

Zusätzlich soll ein Buch bestimmte Dinge **können**:

- ausgeliehen werden,
- zurückgegeben werden,
- seine Verfügbarkeit melden,
- eine Beschreibung liefern.

Man könnte versuchen, all diese Informationen in einzelnen Variablen zu speichern:

```python
titel1 = "Der Hobbit"
autor1 = "J. R. R. Tolkien"
jahr1 = 1937
ausgeliehen_an1 = None
```

Für ein zweites Buch bräuchten wir weitere Variablen:

```python
titel2 = "Momo"
autor2 = "Michael Ende"
jahr2 = 1973
ausgeliehen_an2 = None
```

Bei zehn, hundert oder tausend Büchern wird dieses Vorgehen schnell unübersichtlich.

Wir möchten daher einen eigenen Datentyp definieren:

```text
Buch
```

Jedes konkrete Buch soll dann ein eigenes Objekt dieses Typs sein.

Genau dafür gibt es **Klassen**.

# 2. Das wichtigste Denkmodell

Für dieses Kapitel ist folgendes Modell besonders wichtig:

```text
Variable / Name
      │
      ▼
  Referenz
      │
      ▼
   Objekt
      │
      ▼
    Klasse
```

Ein Beispiel:

```python
zahl = 5
```

Dabei ist:

```text
zahl
→ ein Variablenname

5
→ ein Objekt

int
→ die Klasse bzw. der Datentyp dieses Objekts
```

Wir können das überprüfen:

```python
zahl = 5

print(type(zahl))
```

Ausgabe:

```text
<class 'int'>
```

Das Objekt `5` ist also eine **Instanz** der Klasse `int`.

Dasselbe Prinzip gilt später für unsere eigenen Klassen.

```python
buch = Buch(...)
```

Dann ist:

```text
buch
→ ein Variablenname

das erzeugte Buch
→ ein Objekt / eine Instanz

Buch
→ die Klasse des Objekts
```

# 3. Die wichtigsten Begriffe

Bevor wir eine eigene Klasse programmieren, klären wir die Begriffe genau.

---

## Variable

Eine Variable ist in Python ein **Name**, der auf ein Objekt verweist.

```python
name = "Anna"
```

`name` ist der Variablenname.

Der String `"Anna"` ist das Objekt.

---

## Referenz

Die Verbindung von einem Namen zu einem Objekt nennt man eine **Referenz**.

Vereinfacht dargestellt:

```text
name ─────────► "Anna"
```

Die Variable enthält also nicht einfach „das Objekt selbst“, sondern verweist auf dieses Objekt.

Diese Idee wird besonders wichtig, sobald wir mit veränderbaren Objekten arbeiten.

---

## Objekt

Ein Objekt ist ein konkreter Wert zur Laufzeit.

Beispiele:

```python
42
3.14
"Hallo"
[1, 2, 3]
```

Auch Objekte selbst definierter Klassen sind ganz normale Python-Objekte.

---

## Klasse

Eine Klasse beschreibt eine **Art von Objekten**.

Sie legt fest, welche Daten und welches Verhalten ihre Objekte besitzen sollen.

Man kann sich eine Klasse zunächst wie einen Bauplan vorstellen:

```text
Klasse Buch
│
├── Attribute
│   ├── titel
│   ├── autor
│   ├── erscheinungsjahr
│   └── ausgeliehen_an
│
└── Methoden
    ├── ist_verfuegbar()
    ├── ausleihen()
    └── zurueckgeben()
```

Die Klasse beschreibt also, wie Buch-Objekte aufgebaut sind und was sie tun können.

---

## Instanz

Ein konkretes Objekt einer Klasse nennt man **Instanz** dieser Klasse.

```text
Klasse:
Buch

Instanzen:
"Der Hobbit"
"Momo"
"1984"
```

Alle drei Objekte gehören zur gleichen Klasse, besitzen aber unterschiedliche Daten.

---

## Attribut

Ein Attribut ist eine Information, die zu einem Objekt gehört.

Ein Buch könnte beispielsweise besitzen:

```text
titel
autor
erscheinungsjahr
ausgeliehen_an
```

Diese Attribute beschreiben den **Zustand** des Objekts.

---

## Methode

Eine Methode ist eine Funktion, die zu einer Klasse gehört.

Sie beschreibt typischerweise, was ein Objekt tun kann.

Beispiele:

```text
ausleihen()
zurueckgeben()
ist_verfuegbar()
```

Methoden beschreiben also das **Verhalten** eines Objekts.

---

## Zustand und Verhalten

Diese beiden Begriffe sind für objektorientiertes Programmieren besonders wichtig:

```text
Attribute → Zustand
Methoden  → Verhalten
```

Ein Buch besitzt beispielsweise den Zustand:

```text
titel = "Momo"
ausgeliehen_an = None
```

Nach dem Ausleihen verändert sich der Zustand:

```text
titel = "Momo"
ausgeliehen_an = "Anna"
```

Die Methode `ausleihen()` sorgt für diese Zustandsänderung.

---

# 4. Eigene Klasse definieren

Eine Klasse wird mit dem Schlüsselwort `class` definiert.

Wir beginnen mit einer sehr einfachen Version:

```python
class Buch:
    pass
```

`pass` bedeutet:

> Hier steht absichtlich noch kein weiterer Code.

Damit existiert bereits ein neuer Datentyp namens `Buch`.

Wir können sogar schon ein Objekt erzeugen:

```python
class Buch:
    pass


buch = Buch()

print(type(buch))
```

Ausgabe:

```text
<class '__main__.Buch'>
```

Das Objekt `buch` ist eine Instanz der Klasse `Buch`.

Allerdings besitzt unsere Klasse noch keine sinnvollen Attribute oder Methoden.

Das ändern wir jetzt.

---

# 5. `__init__()` – ein neues Objekt initialisieren

Beim Erzeugen eines Buchs möchten wir sofort Titel, Autor und Erscheinungsjahr angeben.

Dafür definieren wir die spezielle Methode `__init__()`:

```python
class Buch:
    def __init__(
        self,
        titel: str,
        autor: str,
        erscheinungsjahr: int
    ) -> None:
        self.titel: str = titel
        self.autor: str = autor
        self.erscheinungsjahr: int = erscheinungsjahr
        self.ausgeliehen_an: str | None = None
```

Nun können wir ein Buch erzeugen:

```python
buch = Buch(
    "Momo",
    "Michael Ende",
    1973
)
```

Beim Aufruf

```python
Buch("Momo", "Michael Ende", 1973)
```

wird eine neue Instanz der Klasse `Buch` erzeugt und anschließend mit `__init__()` initialisiert.

Für dieses Kapitel kannst du dir merken:

> `__init__()` legt den Anfangszustand eines neuen Objekts fest.

---

## Ist `__init__()` der Konstruktor?

Im Unterricht und in vielen vereinfachten Erklärungen wird `__init__()` häufig als **Konstruktor** bezeichnet.

Technisch genauer ist:

- Python erzeugt die Instanz bereits vor dem Aufruf von `__init__()`.
- `__init__()` **initialisiert** die bereits erzeugte Instanz.
- Die eigentliche Erzeugung wird intern unter anderem über `__new__()` gesteuert.

Für normale eigene Klassen musst du `__new__()` fast nie selbst schreiben.

Deshalb genügt für den praktischen Einstieg:

> Beim Aufruf der Klasse wird ein neues Objekt erzeugt; `__init__()` richtet seinen Anfangszustand ein.

# 6. Parameter und Attribute sind nicht dasselbe

Betrachte diese Zeile:

```python
self.titel = titel
```

Links und rechts steht zwar fast derselbe Name, aber die beiden Dinge haben unterschiedliche Bedeutungen.

```text
titel
→ Parameter von __init__()

self.titel
→ Attribut des aktuellen Objekts
```

Beim Aufruf:

```python
buch = Buch("Momo", "Michael Ende", 1973)
```

enthält der Parameter `titel` während des Aufrufs:

```text
"Momo"
```

Mit

```python
self.titel = titel
```

wird dieser Wert im Objekt gespeichert.

Vereinfacht:

```text
Parameter titel
      │
      ▼
    "Momo"
      │
      ▼
self.titel im Objekt
```

Nach dem Ende von `__init__()` existiert der lokale Parameter `titel` nicht mehr.

Das Attribut `self.titel` bleibt jedoch Teil des Objekts.

---

# 7. Was bedeutet `self`?

`self` ist eine Referenz auf das **aktuelle Objekt**, für das eine Methode ausgeführt wird.

Betrachte:

```python
class Buch:
    def __init__(self, titel: str) -> None:
        self.titel: str = titel
```

Wir erzeugen zwei Objekte:

```python
buch1 = Buch("Momo")
buch2 = Buch("Der Hobbit")
```

Beim Initialisieren von `buch1` verweist `self` auf `buch1`.

Beim Initialisieren von `buch2` verweist `self` auf `buch2`.

Vereinfacht:

```text
Buch("Momo")
    │
    ▼
self ──► Objekt 1
         titel = "Momo"


Buch("Der Hobbit")
    │
    ▼
self ──► Objekt 2
         titel = "Der Hobbit"
```

Dadurch weiß Python, **welches konkrete Objekt** verändert werden soll.

---

## `self` ist kein besonderes Schlüsselwort

`self` ist in Python kein reserviertes Schlüsselwort wie `if`, `for` oder `class`.

Theoretisch könnte man einen anderen Namen verwenden.

Das sollte man aber nicht tun.

In Python ist `self` die feste Konvention für den ersten Parameter einer normalen Instanzmethode.

> Verwende für Instanzmethoden immer `self`.

---

# 8. Mehrere Instanzen derselben Klasse

Eine Klasse kann beliebig viele Objekte erzeugen.

```python
class Buch:
    def __init__(
        self,
        titel: str,
        autor: str,
        erscheinungsjahr: int
    ) -> None:
        self.titel: str = titel
        self.autor: str = autor
        self.erscheinungsjahr: int = erscheinungsjahr
        self.ausgeliehen_an: str | None = None
```

Nun erstellen wir drei Bücher:

```python
buch1 = Buch("Momo", "Michael Ende", 1973)
buch2 = Buch("Der Hobbit", "J. R. R. Tolkien", 1937)
buch3 = Buch("1984", "George Orwell", 1949)
```

Alle drei Objekte besitzen dieselben **Arten von Attributen**:

```text
titel
autor
erscheinungsjahr
ausgeliehen_an
```

Aber die Werte dieser Attribute gehören jeweils zur einzelnen Instanz.

```text
buch1
└── titel = "Momo"

buch2
└── titel = "Der Hobbit"

buch3
└── titel = "1984"
```

Das ist eine zentrale Idee von Klassen:

> Eine Klasse beschreibt die gemeinsame Struktur.  
> Jede Instanz besitzt ihren eigenen Zustand.

---

# 9. Auf Attribute zugreifen

Auf Attribute wird mit dem Punktoperator `.` zugegriffen:

```python
print(buch1.titel)
print(buch2.autor)
print(buch3.erscheinungsjahr)
```

Man kann Attribute grundsätzlich auch verändern:

```python
buch1.titel = "Momo – Jubiläumsausgabe"
```

Danach besitzt nur `buch1` den neuen Titel.

Die anderen Buch-Objekte bleiben unverändert.

```python
print(buch1.titel)
print(buch2.titel)
```

# 10. Methoden definieren

Nun soll jedes Buch selbst sagen können, ob es verfügbar ist.

```python
class Buch:
    def __init__(
        self,
        titel: str,
        autor: str,
        erscheinungsjahr: int
    ) -> None:
        self.titel: str = titel
        self.autor: str = autor
        self.erscheinungsjahr: int = erscheinungsjahr
        self.ausgeliehen_an: str | None = None

    def ist_verfuegbar(self) -> bool:
        return self.ausgeliehen_an is None
```

Aufruf:

```python
buch = Buch("Momo", "Michael Ende", 1973)

print(buch.ist_verfuegbar())
```

Ausgabe:

```text
True
```

Die Methode greift über

```python
self.ausgeliehen_an
```

auf den Zustand des aktuellen Objekts zu.

# 11. Methoden können den Zustand verändern

Ein Buch soll ausgeliehen werden können.

```python
class Buch:
    def __init__(
        self,
        titel: str,
        autor: str,
        erscheinungsjahr: int
    ) -> None:
        self.titel: str = titel
        self.autor: str = autor
        self.erscheinungsjahr: int = erscheinungsjahr
        self.ausgeliehen_an: str | None = None

    def ist_verfuegbar(self) -> bool:
        return self.ausgeliehen_an is None

    def ausleihen(self, name: str) -> bool:
        if not self.ist_verfuegbar():
            return False

        self.ausgeliehen_an = name
        return True

    def zurueckgeben(self) -> None:
        self.ausgeliehen_an = None
```

Verwendung:

```python
buch = Buch("Momo", "Michael Ende", 1973)

print(buch.ist_verfuegbar())

erfolgreich = buch.ausleihen("Anna")

print(erfolgreich)
print(buch.ist_verfuegbar())
print(buch.ausgeliehen_an)
```

Ausgabe:

```text
True
True
False
Anna
```

Die Methode

```python
buch.ausleihen("Anna")
```

verändert den Zustand dieses Buch-Objekts.

Vorher:

```text
ausgeliehen_an = None
```

Nachher:

```text
ausgeliehen_an = "Anna"
```

---

# 12. Methoden können andere Methoden desselben Objekts aufrufen

In `ausleihen()` haben wir geschrieben:

```python
if not self.ist_verfuegbar():
    ...
```

Damit ruft eine Methode eine andere Methode desselben Objekts auf.

Das ist ein wichtiger Bestandteil objektorientierter Programme.

Ein Objekt kann seine eigene Logik wiederverwenden:

```text
ausleihen()
    │
    └── verwendet ist_verfuegbar()
```

Dadurch müssen wir die Prüfung

```python
self.ausgeliehen_an is None
```

nicht an mehreren Stellen wiederholen.

---

# 13. Warum muss beim Methodenaufruf `self` nicht angegeben werden?

Die Methode ist so definiert:

```python
def ausleihen(self, name: str) -> bool:
    ...
```

Beim Aufruf schreiben wir aber:

```python
buch.ausleihen("Anna")
```

und nicht:

```python
buch.ausleihen(buch, "Anna")
```

Python übergibt das Objekt vor dem Punkt automatisch als erstes Argument.

Vereinfacht kann man sich folgenden Aufruf

```python
buch.ausleihen("Anna")
```

so vorstellen:

```python
Buch.ausleihen(buch, "Anna")
```

Dabei wird also

```text
buch
```

an

```text
self
```

übergeben.

Das erklärt, warum jede normale Instanzmethode als ersten Parameter `self` besitzt.

# 14. Funktion und Methode

Eine **Funktion** steht unabhängig von einem konkreten Objekt:

```python
def verdoppeln(zahl: int) -> int:
    return zahl * 2
```

Aufruf:

```python
verdoppeln(5)
```

Eine **Methode** ist in einer Klasse definiert und wird typischerweise über ein Objekt aufgerufen:

```python
buch.ist_verfuegbar()
```

Vergleich:

```text
Funktion
→ verdoppeln(5)

Methode
→ buch.ausleihen("Anna")
```

Eine Instanzmethode erhält über `self` Zugriff auf den Zustand des Objekts.

Das ist der entscheidende Unterschied.

# 15. Zustand gehört zum Objekt

Wir erzeugen zwei Bücher:

```python
buch1 = Buch("Momo", "Michael Ende", 1973)
buch2 = Buch("Der Hobbit", "J. R. R. Tolkien", 1937)
```

Nun leihen wir nur `buch1` aus:

```python
buch1.ausleihen("Anna")
```

Dann gilt:

```python
print(buch1.ausgeliehen_an)
print(buch2.ausgeliehen_an)
```

Ausgabe:

```text
Anna
None
```

Obwohl beide Objekte aus derselben Klasse stammen, besitzen sie unabhängige Zustände.

```text
buch1 ──► Buch-Objekt
          titel = "Momo"
          ausgeliehen_an = "Anna"

buch2 ──► Buch-Objekt
          titel = "Der Hobbit"
          ausgeliehen_an = None
```

> Attribute wie `self.titel` oder `self.ausgeliehen_an` sind **Instanzattribute**.  
> Jede Instanz besitzt ihre eigenen Werte.

# 16. Referenzen: Zwei Variablen können auf dasselbe Objekt zeigen

Dieser Punkt ist besonders wichtig.

Betrachte:

```python
buch1 = Buch("Momo", "Michael Ende", 1973)
buch2 = buch1
```

Es wurden hier **nicht zwei Buch-Objekte erzeugt**.

Es gibt nur ein Objekt und zwei Namen, die darauf verweisen:

```text
buch1 ──┐
        ├────► Buch-Objekt
buch2 ──┘      titel = "Momo"
```

Wir können das mit `is` überprüfen:

```python
print(buch1 is buch2)
```

Ausgabe:

```text
True
```

Wenn wir das Objekt über `buch2` verändern:

```python
buch2.ausleihen("Ben")
```

sehen wir die Änderung auch über `buch1`:

```python
print(buch1.ausgeliehen_an)
```

Ausgabe:

```text
Ben
```

Warum?

Weil beide Variablen auf dasselbe Objekt verweisen.

---

## Zwei echte Instanzen

Wenn wir dagegen zweimal die Klasse aufrufen:

```python
buch1 = Buch("Momo", "Michael Ende", 1973)
buch2 = Buch("Momo", "Michael Ende", 1973)
```

werden zwei unterschiedliche Objekte erzeugt.

```python
print(buch1 is buch2)
```

Ausgabe:

```text
False
```

Obwohl beide Objekte dieselben Attributwerte besitzen können, sind es zwei verschiedene Instanzen.

---

# 17. `is` und `==` sind nicht dasselbe

`is` prüft:

> Sind das genau dieselben Objekte?

```python
buch1 is buch2
```

`==` prüft grundsätzlich:

> Gelten die beiden Werte nach den für ihren Typ definierten Regeln als gleich?

Bei eingebauten Typen kennst du das bereits:

```python
a = [1, 2, 3]
b = [1, 2, 3]

print(a == b)
print(a is b)
```

Ausgabe:

```text
True
False
```

Die Listen haben denselben Inhalt, sind aber zwei verschiedene Objekte.

Bei eigenen Klassen muss man später bei Bedarf selbst festlegen, wann zwei Instanzen als inhaltlich gleich gelten sollen.

Für den Anfang ist wichtig:

```text
is
→ Identität

==
→ Gleichheit nach den Regeln des Datentyps
```

# 18. Objekte können als Argumente an Funktionen übergeben werden

Ein Objekt kann wie jeder andere Wert an eine Funktion übergeben werden.

```python
def zeige_buch(buch: Buch) -> None:
    print(buch.titel)
    print(buch.autor)
```

Aufruf:

```python
buch = Buch("Momo", "Michael Ende", 1973)

zeige_buch(buch)
```

Die Funktion erhält dabei eine Referenz auf dasselbe Objekt.

Das bedeutet:

Wenn eine Funktion ein veränderbares Objekt verändert, ist diese Änderung auch außerhalb der Funktion sichtbar.

```python
def leihe_an_anna_aus(buch: Buch) -> None:
    buch.ausleihen("Anna")
```

Danach:

```python
buch = Buch("Momo", "Michael Ende", 1973)

leihe_an_anna_aus(buch)

print(buch.ausgeliehen_an)
```

Ausgabe:

```text
Anna
```

Es wurde kein neues Buch erzeugt.

Die Funktion arbeitete mit einer Referenz auf das vorhandene Objekt.

# 19. Warum Methoden statt direkter Attributänderungen?

Technisch könnten wir schreiben:

```python
buch.ausgeliehen_an = "Anna"
```

Warum brauchen wir dann überhaupt:

```python
buch.ausleihen("Anna")
```

Weil eine Methode Regeln kontrollieren kann.

Zum Beispiel darf ein bereits ausgeliehenes Buch nicht noch einmal ausgeliehen werden:

```python
def ausleihen(self, name: str) -> bool:
    if not self.ist_verfuegbar():
        return False

    self.ausgeliehen_an = name
    return True
```

Der Methodenaufruf

```python
buch.ausleihen("Anna")
```

bedeutet nicht nur:

> Setze ein Attribut.

Sondern:

> Führe die Regeln für das Ausleihen eines Buches aus.

Damit liegen Daten und die zugehörige Logik an einer gemeinsamen Stelle.

Diese Idee nennt man häufig **Kapselung**:

> Ein Objekt verwaltet seinen Zustand möglichst über klar definierte Methoden.

Python erzwingt vollständige Kapselung allerdings nicht. Attribute sind grundsätzlich zugänglich, solange man nicht zusätzliche Techniken verwendet.

---

# 20. Attribute sollten einen gültigen Zustand beschreiben

Ein gut entworfenes Objekt sollte möglichst immer einen sinnvollen Zustand besitzen.

Bei unserem Buch bedeutet:

```text
ausgeliehen_an = None
→ verfügbar

ausgeliehen_an = "Anna"
→ ausgeliehen
```

Ungünstig wäre beispielsweise:

```python
buch.ausgeliehen_an = ""
```

Was bedeutet ein leerer String?

Ist das Buch verfügbar oder ausgeliehen?

Durch klar definierte Regeln können wir solche unklaren Zustände vermeiden.

Eine wichtige Idee beim Klassendesign lautet daher:

> Welche Zustände sind gültig und welche Methoden dürfen diese Zustände verändern?

# 21. Ein vollständiger erster Entwurf der Klasse `Buch`

Nun fassen wir die bisherigen Ideen zusammen:

```python
class Buch:
    def __init__(
        self,
        titel: str,
        autor: str,
        erscheinungsjahr: int
    ) -> None:
        self.titel: str = titel
        self.autor: str = autor
        self.erscheinungsjahr: int = erscheinungsjahr
        self.ausgeliehen_an: str | None = None

    def ist_verfuegbar(self) -> bool:
        return self.ausgeliehen_an is None

    def ausleihen(self, name: str) -> bool:
        if not self.ist_verfuegbar():
            return False

        self.ausgeliehen_an = name
        return True

    def zurueckgeben(self) -> None:
        self.ausgeliehen_an = None

    def beschreibung(self) -> str:
        status: str

        if self.ist_verfuegbar():
            status = "verfügbar"
        else:
            status = f"ausgeliehen an {self.ausgeliehen_an}"

        return (
            f"{self.titel} von {self.autor} "
            f"({self.erscheinungsjahr}) – {status}"
        )
```

Verwendung:

```python
buch = Buch(
    "Momo",
    "Michael Ende",
    1973
)

print(buch.beschreibung())

buch.ausleihen("Anna")

print(buch.beschreibung())

buch.zurueckgeben()

print(buch.beschreibung())
```

Mögliche Ausgabe:

```text
Momo von Michael Ende (1973) – verfügbar
Momo von Michael Ende (1973) – ausgeliehen an Anna
Momo von Michael Ende (1973) – verfügbar
```

Hier sieht man bereits das zentrale Zusammenspiel:

```text
Attribute
→ speichern den Zustand

Methoden
→ lesen oder verändern den Zustand

self
→ verweist auf das konkrete Objekt

Klasse
→ beschreibt die gemeinsame Struktur aller Buch-Objekte
```

# 22. Ein Objekt kann andere Objekte enthalten

Eine Bibliothek besteht nicht nur aus einem Buch.

Sie verwaltet viele Buch-Objekte.

Wir definieren deshalb eine zweite Klasse:

```python
class Bibliothek:
    def __init__(self, name: str) -> None:
        self.name: str = name
        self.buecher: list[Buch] = []

    def buch_aufnehmen(self, buch: Buch) -> None:
        self.buecher.append(buch)
```

Nun können wir eine Bibliothek und mehrere Bücher erzeugen:

```python
bibliothek = Bibliothek("Schulbibliothek")

buch1 = Buch("Momo", "Michael Ende", 1973)
buch2 = Buch("Der Hobbit", "J. R. R. Tolkien", 1937)

bibliothek.buch_aufnehmen(buch1)
bibliothek.buch_aufnehmen(buch2)
```

Die Bibliothek enthält keine Kopien der Bücher.

Die Liste speichert Referenzen auf die Buch-Objekte:

```text
bibliothek
│
└── buecher
    │
    ├────► buch1 ──► Buch-Objekt "Momo"
    │
    └────► buch2 ──► Buch-Objekt "Der Hobbit"
```

Das ist ein wichtiges Beispiel für das **Zusammenspiel von Objekten**.

# 23. Objekte können Methoden anderer Objekte aufrufen

Die Bibliothek soll alle verfügbaren Bücher liefern.

```python
class Bibliothek:
    def __init__(self, name: str) -> None:
        self.name: str = name
        self.buecher: list[Buch] = []

    def buch_aufnehmen(self, buch: Buch) -> None:
        self.buecher.append(buch)

    def verfuegbare_buecher(self) -> list[Buch]:
        return [
            buch
            for buch in self.buecher
            if buch.ist_verfuegbar()
        ]
```

Beachte diese Stelle:

```python
buch.ist_verfuegbar()
```

Die Methode der `Bibliothek` ruft eine Methode eines `Buch`-Objekts auf.

Das Zusammenspiel sieht so aus:

```text
Bibliothek-Objekt
      │
      │ enthält Referenzen auf
      ▼
   Buch-Objekte
      │
      │ bieten Methoden an
      ▼
ist_verfuegbar()
```

Objektorientierte Programme bestehen oft nicht aus einer riesigen Klasse.

Stattdessen gibt es mehrere Klassen mit klaren Aufgaben, deren Objekte miteinander zusammenarbeiten.

# 24. Ein vollständigeres Zusammenspiel

Wir erweitern die Bibliothek:

```python
class Bibliothek:
    def __init__(self, name: str) -> None:
        self.name: str = name
        self.buecher: list[Buch] = []

    def buch_aufnehmen(self, buch: Buch) -> None:
        self.buecher.append(buch)

    def suche_nach_titel(self, titel: str) -> Buch | None:
        for buch in self.buecher:
            if buch.titel == titel:
                return buch

        return None

    def verfuegbare_buecher(self) -> list[Buch]:
        return [
            buch
            for buch in self.buecher
            if buch.ist_verfuegbar()
        ]
```

Verwendung:

```python
bibliothek = Bibliothek("Schulbibliothek")

bibliothek.buch_aufnehmen(
    Buch("Momo", "Michael Ende", 1973)
)

bibliothek.buch_aufnehmen(
    Buch("Der Hobbit", "J. R. R. Tolkien", 1937)
)

gefunden = bibliothek.suche_nach_titel("Momo")

if gefunden is not None:
    gefunden.ausleihen("Anna")
    print(gefunden.beschreibung())
```

Hier arbeiten mehrere Konzepte zusammen:

```text
Bibliothek
→ kennt mehrere Buch-Objekte

suche_nach_titel()
→ liefert eine Referenz auf ein Buch zurück

gefunden
→ verweist auf dasselbe Buch-Objekt,
  das auch in bibliothek.buecher gespeichert ist

gefunden.ausleihen("Anna")
→ verändert daher genau dieses Buch in der Bibliothek
```

Das ist eine der wichtigsten Ideen dieses Kapitels.

# 25. Eine zurückgegebene Referenz zeigt auf dasselbe Objekt

Betrachte:

```python
gefunden = bibliothek.suche_nach_titel("Momo")
```

Angenommen, die Methode findet das Buch.

Dann entsteht **kein neues Buch**.

`gefunden` erhält eine weitere Referenz auf das bereits vorhandene Objekt.

Vereinfacht:

```text
bibliothek.buecher[0] ──┐
                        ├────► Buch-Objekt "Momo"
gefunden ────────────────┘
```

Wenn wir schreiben:

```python
gefunden.ausleihen("Anna")
```

ändert sich damit auch das Objekt, das in der Bibliotheksliste liegt.

```python
print(bibliothek.buecher[0].ausgeliehen_an)
```

Ausgabe:

```text
Anna
```

Es gibt nur **ein** Buch-Objekt.

Es existieren lediglich mehrere Referenzen darauf.

# 26. Objektbeziehungen: „hat ein“ statt „ist ein“

Unsere Bibliothek besitzt Bücher:

```text
Bibliothek hat Bücher
```

Im Code:

```python
self.buecher: list[Buch] = []
```

Eine solche Beziehung wird häufig als **Hat-ein-Beziehung** beschrieben:

```text
Bibliothek hat Buch-Objekte.
```

Das ist eine Form von **Komposition bzw. Aggregation**: Ein Objekt arbeitet mit anderen Objekten als Bestandteilen oder zugeordneten Elementen.

Die genaue Unterscheidung dieser Beziehungsarten wird später bei UML noch genauer betrachtet.

Für dieses Kapitel genügt:

> Ein Attribut muss kein einfacher Datentyp sein.  
> Ein Attribut kann auch auf ein anderes selbst definiertes Objekt oder auf eine Sammlung solcher Objekte verweisen.

# 27. Objekte können auch direkt auf einzelne andere Objekte verweisen

Nicht immer braucht man eine Liste.

Beispielsweise könnte ein Ausleihvorgang später als eigenes Objekt modelliert werden:

```python
class Person:
    def __init__(self, name: str) -> None:
        self.name: str = name


class Ausleihe:
    def __init__(
        self,
        buch: Buch,
        person: Person
    ) -> None:
        self.buch: Buch = buch
        self.person: Person = person
```

Dann verweist ein `Ausleihe`-Objekt auf genau ein `Buch`-Objekt und ein `Person`-Objekt:

```text
Ausleihe
├────► Buch
└────► Person
```

So entstehen größere objektorientierte Programme:

> Objekte speichern Referenzen auf andere Objekte und rufen deren Methoden auf.

# 28. Klassenattribute und Instanzattribute

Bisher haben wir ausschließlich Instanzattribute verwendet:

```python
self.titel
self.autor
self.ausgeliehen_an
```

Diese gehören jeweils zu einer einzelnen Instanz.

Es gibt zusätzlich **Klassenattribute**.

Beispiel:

```python
class Buch:
    medientyp: str = "Buch"

    def __init__(self, titel: str) -> None:
        self.titel: str = titel
```

`medientyp` wird direkt im Klassenrumpf definiert.

Man kann darauf über die Klasse zugreifen:

```python
print(Buch.medientyp)
```

Ausgabe:

```text
Buch
```

Auch Instanzen können den Wert lesen:

```python
buch1 = Buch("Momo")
buch2 = Buch("Der Hobbit")

print(buch1.medientyp)
print(buch2.medientyp)
```

Beide erhalten zunächst denselben Klassenwert.

Der grundlegende Unterschied:

```text
self.titel
→ Instanzattribut
→ eigener Wert pro Objekt

Buch.medientyp
→ Klassenattribut
→ gehört zur Klasse und wird gemeinsam verwendet
```

Für Anfängerklassen solltest du den Zustand einzelner Objekte normalerweise über Instanzattribute in `__init__()` speichern.

# 29. Vorsicht mit veränderbaren Klassenattributen

Folgendes wäre für unsere Bibliothek problematisch:

```python
class Bibliothek:
    buecher: list[Buch] = []
```

Diese Liste wäre ein Klassenattribut und würde von allen Instanzen gemeinsam verwendet.

Dann könnten zwei scheinbar unabhängige Bibliotheken versehentlich dieselbe Buchliste verwenden.

Für objektbezogene veränderbare Daten ist daher normalerweise richtig:

```python
class Bibliothek:
    def __init__(self, name: str) -> None:
        self.name: str = name
        self.buecher: list[Buch] = []
```

Jetzt erhält jede Bibliotheksinstanz ihre **eigene Liste**.

# 30. Warum Attribute normalerweise in `__init__()` angelegt werden

Python erlaubt technisch, Attribute auch später hinzuzufügen:

```python
buch = Buch("Momo")
buch.notiz = "Für Klasse 3A reserviert"
```

Das ist zwar möglich, aber für klar strukturierte Klassen meist ungünstig.

Ein Leser der Klasse sollte erkennen können, welchen Zustand ein Objekt besitzt.

Darum ist es sinnvoll, die normalen Instanzattribute bereits in `__init__()` festzulegen.

```python
class Buch:
    def __init__(self, titel: str) -> None:
        self.titel: str = titel
        self.notiz: str | None = None
```

Damit ist die Struktur jedes Objekts klarer.

# 32. Attribute mit führendem Unterstrich

Manchmal sieht man Attribute wie:


Der führende Unterstrich bedeutet in Python konventionell:

> Dieses Attribut ist für die interne Verwendung der Klasse gedacht.

Python verhindert den Zugriff von außen dadurch nicht automatisch.


ist technisch weiterhin möglich.

Der Unterstrich ist also vor allem eine Vereinbarung zwischen Programmierenden.

# 33. Spezielle Methoden: `__str__()`

`__init__()` ist nicht die einzige spezielle Methode mit doppelten Unterstrichen.

Solche Methoden werden oft **Dunder-Methoden** genannt:

```text
double underscore
→ dunder
```

Eine sehr praktische Methode ist `__str__()`.

```python

```

> Mit eigenen Klassen können wir festlegen, wie sich unsere Objekte in Python verhalten.

# 37. Klassen modellieren Begriffe aus einem Problem

# 38. Ein Objekt sollte eine klare Verantwortung haben

# 39. Komplettes Beispiel: Schulbibliothek

Die bisherigen Konzepte können wir zu einem kleinen Programm zusammensetzen.

```python
class Buch:
    def __init__(
        self,
        titel: str,
        autor: str,
        erscheinungsjahr: int
    ) -> None:
        self.titel: str = titel
        self.autor: str = autor
        self.erscheinungsjahr: int = erscheinungsjahr
        self.ausgeliehen_an: str | None = None

    def ist_verfuegbar(self) -> bool:
        return self.ausgeliehen_an is None

    def ausleihen(self, name: str) -> bool:
        if not self.ist_verfuegbar():
            return False

        self.ausgeliehen_an = name
        return True

    def zurueckgeben(self) -> None:
        self.ausgeliehen_an = None

    def __str__(self) -> str:
        if self.ist_verfuegbar():
            status = "verfügbar"
        else:
            status = f"ausgeliehen an {self.ausgeliehen_an}"

        return (
            f"{self.titel} von {self.autor} "
            f"({self.erscheinungsjahr}) – {status}"
        )


class Bibliothek:
    def __init__(self, name: str) -> None:
        self.name: str = name
        self.buecher: list[Buch] = []

    def buch_aufnehmen(self, buch: Buch) -> None:
        self.buecher.append(buch)

    def suche_nach_titel(self, titel: str) -> Buch | None:
        for buch in self.buecher:
            if buch.titel == titel:
                return buch

        return None

    def verfuegbare_buecher(self) -> list[Buch]:
        return [
            buch
            for buch in self.buecher
            if buch.ist_verfuegbar()
        ]

    def zeige_bestand(self) -> None:
        print(f"Bibliothek: {self.name}")

        for buch in self.buecher:
            print(f"- {buch}")
```

Verwendung:

```python
bibliothek = Bibliothek("Schulbibliothek")

buch1 = Buch("Momo", "Michael Ende", 1973)
buch2 = Buch("Der Hobbit", "J. R. R. Tolkien", 1937)
buch3 = Buch("1984", "George Orwell", 1949)

bibliothek.buch_aufnehmen(buch1)
bibliothek.buch_aufnehmen(buch2)
bibliothek.buch_aufnehmen(buch3)

bibliothek.zeige_bestand()

gefunden = bibliothek.suche_nach_titel("Momo")

if gefunden is not None:
    if gefunden.ausleihen("Anna"):
        print("Das Buch wurde ausgeliehen.")
    else:
        print("Das Buch ist bereits ausgeliehen.")

bibliothek.zeige_bestand()
```

Eine mögliche Ausgabe:

```text
Bibliothek: Schulbibliothek
- Momo von Michael Ende (1973) – verfügbar
- Der Hobbit von J. R. R. Tolkien (1937) – verfügbar
- 1984 von George Orwell (1949) – verfügbar
Das Buch wurde ausgeliehen.
Bibliothek: Schulbibliothek
- Momo von Michael Ende (1973) – ausgeliehen an Anna
- Der Hobbit von J. R. R. Tolkien (1937) – verfügbar
- 1984 von George Orwell (1949) – verfügbar
```

# 41. Ein mentales Objektbild

Nach dem Ausleihen könnte man sich den Speicher vereinfacht so vorstellen:

```text
bibliothek
    │
    ▼
Bibliothek-Objekt
    name = "Schulbibliothek"
    buecher ───────┬─────────────────┬─────────────────┐
                   │                 │                 │
                   ▼                 ▼                 ▼
              Buch-Objekt       Buch-Objekt       Buch-Objekt
              "Momo"            "Der Hobbit"      "1984"
              ausgeliehen_an    ausgeliehen_an    ausgeliehen_an
              = "Anna"          = None            = None
                   ▲
                   │
gefunden ──────────┘
```

Beachte:

`gefunden` zeigt nicht auf eine Kopie von `"Momo"`.

Es zeigt auf dasselbe Objekt, das bereits in der Bibliothek gespeichert ist.

# 42. Typische Fehler

## `self` vergessen

Falsch:

```python
class Buch:
    def __init__(titel: str) -> None:
        self.titel = titel
```

Richtig:

```python
class Buch:
    def __init__(self, titel: str) -> None:
        self.titel: str = titel
```

Normale Instanzmethoden benötigen `self` als ersten Parameter.

---

## `self.` beim Attribut vergessen

Falsch:

```python
class Buch:
    def __init__(self, titel: str) -> None:
        titel = titel
```

Damit wird kein Instanzattribut erzeugt.

Richtig:

```python
class Buch:
    def __init__(self, titel: str) -> None:
        self.titel: str = titel
```

---

## Parameter mit Attributen verwechseln

```python
def __init__(self, titel: str) -> None:
    self.titel = titel
```

Rechts:

```text
titel
→ Parameter
```

Links:

```text
self.titel
→ dauerhaftes Attribut des Objekts
```

---

## Eine Methode ohne Klammern verwenden

```python
print(buch.ist_verfuegbar)
```

liefert die Methode selbst.

Für den Aufruf braucht man:

```python
print(buch.ist_verfuegbar())
```

---

## Denken, dass eine Zuweisung ein Objekt kopiert

```python
buch2 = buch1
```

erzeugt keine neue Instanz.

Beide Namen verweisen auf dasselbe Objekt.

---

## Versehentlich ein veränderbares Klassenattribut verwenden

Problematisch:

```python
class Bibliothek:
    buecher: list[Buch] = []
```

Besser:

```python
class Bibliothek:
    def __init__(self) -> None:
        self.buecher: list[Buch] = []
```

Damit besitzt jede Instanz ihre eigene Liste.

---

## Zu viele Verantwortlichkeiten in eine Klasse packen

Eine Klasse sollte nicht alles können.

Günstiger:

```text
Buch
→ Zustand und Verhalten eines Buchs

Bibliothek
→ Verwaltung mehrerer Bücher
```

statt einer einzigen riesigen Klasse, die jede Aufgabe des gesamten Programms erledigt.

## Übung 1 – Eine eigene Klasse entwerfen

Wir möchten Spielfiguren modellieren.

Jede Spielfigur besitzt:

- einen Namen,
- Lebenspunkte,
- maximale Lebenspunkte.

Eine Spielfigur soll:

- prüfen können, ob sie noch lebt,
- Schaden erhalten,
- geheilt werden.

Beim Heilen dürfen die Lebenspunkte nicht über die maximalen Lebenspunkte steigen.

### Lösungsschema

Bestimme zuerst die Struktur.

```text
Klasse:
Spielfigur

Instanzattribute:
name
lebenspunkte
max_lebenspunkte

Methoden:
ist_am_leben()
schaden_erhalten(...)
heilen(...)
```

Nun die Zustände:

```text
lebenspunkte > 0
→ Figur lebt

lebenspunkte == 0
→ Figur ist besiegt
```

Beim Schaden:

```text
neue Lebenspunkte
= bisherige Lebenspunkte - Schaden

aber niemals kleiner als 0
```

Beim Heilen:

```text
neue Lebenspunkte
= bisherige Lebenspunkte + Heilung

aber niemals größer als max_lebenspunkte
```

Die Schnittstellen könnten so aussehen:

```python
def ist_am_leben(self) -> bool:
    ...

def schaden_erhalten(self, schaden: int) -> None:
    ...

def heilen(self, punkte: int) -> None:
    ...
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

```python
class Spielfigur:
    def __init__(
        self,
        name: str,
        max_lebenspunkte: int
    ) -> None:
        self.name: str = name
        self.max_lebenspunkte: int = max_lebenspunkte
        self.lebenspunkte: int = max_lebenspunkte

    def ist_am_leben(self) -> bool:
        return self.lebenspunkte > 0

    def schaden_erhalten(self, schaden: int) -> None:
        self.lebenspunkte = max(
            0,
            self.lebenspunkte - schaden
        )

    def heilen(self, punkte: int) -> None:
        self.lebenspunkte = min(
            self.max_lebenspunkte,
            self.lebenspunkte + punkte
        )


figur = Spielfigur("Nova", 100)

figur.schaden_erhalten(35)

print(figur.lebenspunkte)

figur.heilen(20)

print(figur.lebenspunkte)
print(figur.ist_am_leben())
```

Ausgabe:

```text
65
85
True
```

Die Methoden schützen dabei Regeln des Objektzustands:

```text
Lebenspunkte niemals unter 0
Lebenspunkte niemals über max_lebenspunkte
```

</details>

## Übung 2 – Referenzen verstehen

Gegeben ist folgende Klasse:

```python
class Zaehler:
    def __init__(self) -> None:
        self.wert: int = 0

    def erhoehen(self) -> None:
        self.wert += 1
```

Danach wird ausgeführt:

```python
a = Zaehler()
b = a

b.erhoehen()
b.erhoehen()

print(a.wert)
print(a is b)
```

Bestimme die Ausgabe **ohne den Code zuerst auszuführen**.

### Lösungsschema

Zeichne zuerst die Referenzen:

```text
a ─────► Zaehler-Objekt
```

Nach:

```python
b = a
```

entsteht:

```text
a ──┐
    ├────► Zaehler-Objekt
b ──┘
```

Nun überlege:

```text
b.erhoehen()
```

Welches Objekt wird verändert?

Es gibt nur ein einziges `Zaehler`-Objekt.

Nach zwei Aufrufen besitzt dieses Objekt:

```text
wert = ?
```

Danach bedeutet:

```python
a is b
```

die Frage:

```text
Verweisen a und b auf exakt dasselbe Objekt?
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

Die Ausgabe lautet:

```text
2
True
```

Begründung:

```python
b = a
```

erzeugt keine Kopie.

`a` und `b` verweisen auf dasselbe Objekt.

Darum verändern beide Aufrufe

```python
b.erhoehen()
```

denselben Zustand, den man anschließend auch über `a.wert` sieht.

</details>

## Übung 3 – Zwei Klassen zusammenarbeiten lassen

Wir möchten einen Kurs verwalten.

Eine Person besitzt:

```text
name
```

Ein Kurs besitzt:

```text
titel
teilnehmende
```

Der Kurs soll:

- Personen aufnehmen,
- alle Namen ausgeben,
- nach einer Person suchen.

### Lösungsschema

Zuerst die Objekte:

```text
Person
└── name

Kurs
├── titel
└── teilnehmende
```

Welche Beziehung besteht?

```text
Ein Kurs hat mehrere Person-Objekte.
```

Daher ist ein passendes Attribut:

```python
self.teilnehmende: list[Person] = []
```

Eine Person hinzufügen:

```text
Person-Objekt als Parameter erhalten
→ Referenz in die Liste aufnehmen
```

Suchen:

```text
alle Person-Objekte durchlaufen
→ name vergleichen
→ passendes Person-Objekt zurückgeben
→ sonst None
```

Passender Rückgabetyp:

```python
Person | None
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

```python
class Person:
    def __init__(self, name: str) -> None:
        self.name: str = name


class Kurs:
    def __init__(self, titel: str) -> None:
        self.titel: str = titel
        self.teilnehmende: list[Person] = []

    def aufnehmen(self, person: Person) -> None:
        self.teilnehmende.append(person)

    def zeige_namen(self) -> None:
        for person in self.teilnehmende:
            print(person.name)

    def suche(self, name: str) -> Person | None:
        for person in self.teilnehmende:
            if person.name == name:
                return person

        return None


kurs = Kurs("Python")

anna = Person("Anna")
ben = Person("Ben")

kurs.aufnehmen(anna)
kurs.aufnehmen(ben)

kurs.zeige_namen()

gefunden = kurs.suche("Ben")

if gefunden is not None:
    print(f"Gefunden: {gefunden.name}")
```

Die Liste

```python
self.teilnehmende
```

enthält Referenzen auf die bereits existierenden `Person`-Objekte.

Es werden beim Aufnehmen keine neuen Personen erzeugt.

</details>

# Zusammenfassung

## Klasse

Eine Klasse beschreibt einen eigenen Datentyp.

```python
class Buch:
    ...
```

Sie legt fest, welche Struktur und welches Verhalten ihre Instanzen besitzen.

---

## Objekt / Instanz

Ein Objekt ist ein konkretes Exemplar einer Klasse.

```python
buch = Buch(...)
```

`buch` verweist auf eine Instanz der Klasse `Buch`.

---

## Attribut

Ein Attribut gehört zu einem Objekt und beschreibt dessen Zustand.

```python
self.titel
self.ausgeliehen_an
```

---

## Methode

Eine Methode gehört zu einer Klasse und beschreibt Verhalten.

```python
def ausleihen(self, name: str) -> bool:
    ...
```

---

## `self`

`self` verweist innerhalb einer Instanzmethode auf das aktuelle Objekt.

```python
self.titel
self.ist_verfuegbar()
```

---

## `__init__()`

`__init__()` initialisiert den Anfangszustand einer neu erzeugten Instanz.

```python
def __init__(self, titel: str) -> None:
    self.titel: str = titel
```

---

## Instanzattribut

Ein Instanzattribut gehört zu einer einzelnen Instanz.

```python
self.titel
```

Verschiedene Objekte können unterschiedliche Werte besitzen.

---

## Klassenattribut

Ein Klassenattribut gehört zur Klasse.

```python
class Buch:
    medientyp: str = "Buch"
```

Es wird grundsätzlich von den Instanzen über die Klasse gemeinsam bereitgestellt.

---

## Referenz

Variablen verweisen auf Objekte.

```text
buch ─────► Buch-Objekt
```

Mehrere Variablen können auf dasselbe Objekt verweisen:

```text
a ──┐
    ├────► Objekt
b ──┘
```

---

## Identität

Mit `is` wird geprüft, ob zwei Referenzen auf dasselbe Objekt zeigen.

```python
a is b
```

---

## Objektbeziehung

Objekte können Referenzen auf andere Objekte speichern.

```python
self.buecher: list[Buch] = []
```

Dadurch können mehrere Objekte miteinander zusammenarbeiten.

---

# Die zentrale Idee

Objektorientiertes Programmieren verbindet **Daten und Verhalten**.

```text
Klasse
│
├── beschreibt Attribute
│   └── Zustand
│
└── beschreibt Methoden
    └── Verhalten
```

Aus einer Klasse können mehrere unabhängige Instanzen entstehen:

```text
                 Klasse Buch
                      │
          ┌───────────┼───────────┐
          ▼           ▼           ▼
       Objekt 1    Objekt 2    Objekt 3
        "Momo"     "Hobbit"      "1984"
```

Objekte können wiederum miteinander verbunden sein:

```text
Bibliothek
     │
     └────► Liste von Buch-Objekten
```

Und mehrere Namen können auf dasselbe Objekt verweisen:

```text
bibliothek.buecher[0] ──┐
                        ├────► Buch-Objekt
gefunden ────────────────┘
```

Dieses Zusammenspiel aus

```text
Klassen
Objekten
Attributen
Methoden
Referenzen
Objektbeziehungen
```

bildet die Grundlage für die nächsten Kapitel über objektorientierte Programmierung.
