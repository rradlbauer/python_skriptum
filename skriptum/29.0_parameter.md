# 29.0 Parameter und Argumente

## Lernziele

Nach diesem Kapitel kannst du ...

- den Unterschied zwischen **Parametern** und **Argumenten** erklären.
- erklären, wie Argumente beim Funktionsaufruf an Parameter gebunden werden.
- normale **positional-or-keyword**-Parameter verwenden.
- Funktionen mit **Positionsargumenten** und **Schlüsselwortargumenten** aufrufen.
- Standardwerte für Parameter sinnvoll einsetzen.
- erklären, wann ein Parameter erforderlich und wann er optional ist.
- den typischen Fehler mit **veränderlichen Standardwerten** vermeiden.
- eine variable Anzahl positionaler Argumente mit `*args` verarbeiten.
- eine variable Anzahl benannter Argumente mit `**kwargs` verarbeiten.
- **keyword-only**-Parameter mit `*` definieren.
- **positional-only**-Parameter mit `/` definieren.
- verschiedene Parameterarten in einer Funktionssignatur kombinieren.
- Listen und Tupel beim Aufruf mit `*` entpacken.
- Dictionaries beim Aufruf mit `**` entpacken.
- Type Hints bei `*args` und `**kwargs` sinnvoll verwenden.
- entscheiden, wann ein einzelner Containerparameter und wann `*args` sinnvoller ist.
- typische Fehler bei Funktionsaufrufen erkennen und verstehen.
- erklären, wie `self` bei Methoden in dieses Parameter-Modell passt.

# 1. Parameter und Argumente

Die Begriffe **Parameter** und **Argument** werden im Alltag häufig vermischt.

Für das genaue Verständnis sollten wir sie unterscheiden.

Betrachte:

```python
def begruessen(
    name: str
) -> str:
    return f"Hallo {name}!"
```

Hier ist:

```text
name
```

ein **Parameter**.

Beim Aufruf:

```python
text = begruessen(
    "Anna"
)
```

ist:

```text
"Anna"
```

das **Argument**.

Merksatz:

```text
Parameter
→ steht in der Funktionsdefinition

Argument
→ wird beim Funktionsaufruf übergeben
```

---

# 2. Eine Funktion beschreibt zunächst nur ihre Schnittstelle

Die Definition:

```python
def multipliziere(
    a: int,
    b: int
) -> int:
    return a * b
```

legt unter anderem fest:

```text
Name der Funktion:
multipliziere

Parameter:
a
b

erwartete Typen:
int
int

Rückgabetyp:
int
```

Erst beim Aufruf werden konkrete Argumente gebunden:

```python
ergebnis = multipliziere(
    4,
    5
)
```

Dann gilt für diesen Aufruf:

```text
a → 4
b → 5
```

---

# 3. Argumente werden an lokale Parameternamen gebunden

Aus Kapitel 24 kennst du Referenzen.

Auch bei Funktionsaufrufen gilt:

> Die Parameternamen der Funktion werden beim Aufruf an die übergebenen Objekte gebunden.

Beispiel:

```python
def fuege_hinzu(
    werte: list[int],
    wert: int
) -> None:
    werte.append(
        wert
    )
```

Aufruf:

```python
zahlen = [1, 2]

fuege_hinzu(
    zahlen,
    3
)
```

Während des Aufrufs verweisen:

```text
zahlen
und
werte
```

auf dasselbe Listenobjekt.

Darum ist die Änderung nach dem Funktionsaufruf sichtbar.

---

# 4. Die häufigste Parameterart

Betrachte:

```python
def berechne(
    a: float,
    b: float,
    c: float
) -> float:
    return (
        a - b
    ) * c
```

Diese Parameter werden häufig einfach als „normale Parameter“ bezeichnet.

Technisch genauer heißen sie:

```text
positional-or-keyword parameters
```

also:

```text
Positions- oder Schlüsselwortparameter
```

Warum?

Weil die zugehörigen Argumente auf zwei Arten übergeben werden können.

---

# 5. Aufruf mit Positionsargumenten

```python
ergebnis = berechne(
    5,
    3,
    2
)
```

Die Reihenfolge bestimmt die Zuordnung:

```text
a → 5
b → 3
c → 2
```

Ergebnis:

```text
(5 - 3) * 2
= 4
```

Solche Argumente heißen:

```text
Positionsargumente
```

---

# 6. Aufruf mit Schlüsselwortargumenten

Dieselbe Funktion kann aufgerufen werden mit:

```python
ergebnis = berechne(
    b=3,
    c=2,
    a=5
)
```

Nun erfolgt die Zuordnung über die Parameternamen:

```text
a → 5
b → 3
c → 2
```

Die Reihenfolge der Schlüsselwortargumente ist dabei nicht entscheidend.

---

# 7. Positionsargumente und Schlüsselwortargumente kombinieren

Auch eine Mischung ist möglich:

```python
ergebnis = berechne(
    5,
    b=3,
    c=2
)
```

Dabei gilt:

```text
a → 5
b → 3
c → 2
```

Positionsargumente müssen beim normalen Aufruf vor den Schlüsselwortargumenten stehen.

---

# 8. Ein Parameter darf nicht zweimal einen Wert erhalten

Ungültig:

```python
berechne(
    5,
    a=10,
    b=3,
    c=2
)
```

`a` bekommt hier:

```text
durch Position → 5
durch Schlüsselwort → 10
```

Python kann nicht entscheiden, welcher Wert gelten soll.

Deshalb entsteht ein `TypeError`.

---

# 9. Fehlende Argumente

Auch das ist ungültig:

```python
berechne(
    5,
    3
)
```

Der erforderliche Parameter:

```text
c
```

erhält keinen Wert.

Python löst einen `TypeError` aus.

---

# 10. Unbekannte Schlüsselwortargumente

```python
berechne(
    a=5,
    b=3,
    d=2
)
```

ist ebenfalls ungültig.

Die Funktion besitzt keinen normalen Parameter namens:

```text
d
```

Python meldet daher einen Fehler.

Später sehen wir, wie `**kwargs` beliebige zusätzliche Schlüsselwortargumente aufnehmen kann.

---

# 11. Standardwerte

Parameter können einen Standardwert besitzen.

```python
def berechne(
    a: float,
    b: float = 0,
    c: float = 1
) -> float:
    return (
        a - b
    ) * c
```

Nun ist nur:

```text
a
```

zwingend erforderlich.

Für `b` und `c` existieren Standardwerte.

---

# 12. Aufrufe mit Standardwerten

```python
ergebnis1 = berechne(
    5
)
```

verwendet:

```text
a = 5
b = 0
c = 1
```

Ergebnis:

```text
5
```

---

```python
ergebnis2 = berechne(
    5,
    3
)
```

verwendet:

```text
a = 5
b = 3
c = 1
```

Ergebnis:

```text
2
```

---

```python
ergebnis3 = berechne(
    5,
    c=2
)
```

verwendet:

```text
a = 5
b = 0
c = 2
```

Ergebnis:

```text
10
```

---

# 13. Erforderliche und optionale Parameter

Ein Parameter ohne Standardwert ist normalerweise erforderlich:

```python
a: float
```

Ein Parameter mit Standardwert kann beim Aufruf weggelassen werden:

```python
b: float = 0
```

Solche Parameter werden häufig als **optionale Parameter** bezeichnet.

Dabei bedeutet „optional“:

> Der Aufrufer muss kein eigenes Argument dafür übergeben.

---

# 14. Reihenfolge von Standardwerten

Bei normalen positional-or-keyword-Parametern ist das ungültig:

```text
def funktion(a=1, b):
    ...
```

Warum?

Nach einem Parameter mit Standardwert kann in diesem Bereich nicht einfach wieder ein erforderlicher normaler Parameter folgen.

Richtig:

```python
def funktion(
    b: int,
    a: int = 1
) -> None:
    ...
```

Später sehen wir:

> Keyword-only-Parameter erlauben flexiblere Kombinationen.

---

# 15. Standardwerte werden nur einmal ausgewertet

Dieser Punkt ist besonders wichtig.

Betrachte:

```python
def fuege_hinzu(
    wert: int,
    liste: list[int] = []
) -> list[int]:
    liste.append(
        wert
    )

    return liste
```

Dann:

```python
print(
    fuege_hinzu(1)
)

print(
    fuege_hinzu(2)
)

print(
    fuege_hinzu(3)
)
```

Die Ausgabe ist:

```text
[1]
[1, 2]
[1, 2, 3]
```

Das überrascht viele.

---

# 16. Warum bleibt die Liste erhalten?

Der Standardwert:

```python
[]
```

wird nicht bei jedem Funktionsaufruf neu erzeugt.

Er wird beim Definieren der Funktion erzeugt und anschließend wiederverwendet.

Vereinfacht:

```text
Funktionsdefinition
      │
      ▼
eine Standard-Liste
      │
      ├── Aufruf 1
      ├── Aufruf 2
      └── Aufruf 3
```

Da Listen veränderlich sind, bleiben Änderungen zwischen den Aufrufen erhalten.

---

# 17. Besser: `None` als Standardwert

Wenn bei jedem Aufruf eine neue Liste entstehen soll:

```python
def fuege_hinzu(
    wert: int,
    liste: list[int] | None = None
) -> list[int]:
    if liste is None:
        liste = []

    liste.append(
        wert
    )

    return liste
```

Nun:

```python
print(
    fuege_hinzu(1)
)

print(
    fuege_hinzu(2)
)
```

liefert:

```text
[1]
[2]
```

---

# 18. Wann ist ein veränderlicher Standardwert trotzdem sinnvoll?

Es gibt seltene Fälle, in denen ein gemeinsam verwendetes Objekt ausdrücklich gewünscht ist.

Dann kann ein veränderlicher Standardwert bewusst eingesetzt werden.

Für normalen Anwendungscode gilt aber:

> Verwende veränderliche Objekte wie Listen und Dictionaries nicht unüberlegt als Standardwerte.

Besonders verdächtig sind:

```text
=[]
={}
=set()
```

---

# 19. Variable Anzahl positionaler Argumente

Manchmal wissen wir beim Definieren einer Funktion nicht, wie viele Werte übergeben werden.

Beispiel:

```python
def addiere(
    *zahlen: float
) -> float:
    return sum(
        zahlen
    )
```

Aufrufe:

```python
print(
    addiere(1, 2, 3)
)

print(
    addiere(
        1,
        2,
        3,
        4,
        5
    )
)
```

Ausgabe:

```text
6
15
```

---

# 20. Was bedeutet `*args`?

Häufig sieht man:

```python
def funktion(
    *args
):
    ...
```

`args` ist nur ein üblicher Name.

Man könnte auch schreiben:

```python
def addiere(
    *zahlen: float
) -> float:
    ...
```

Der Stern:

```text
*
```

ist entscheidend.

Alle zusätzlichen positionalen Argumente werden in einem Tupel gesammelt.

---

# 21. `*args` ist ein Tupel

```python
def zeige(
    *werte: object
) -> None:
    print(
        type(werte)
    )

    print(
        werte
    )
```

Aufruf:

```python
zeige(
    10,
    "Hallo",
    True
)
```

liefert sinngemäß:

```text
<class 'tuple'>
(10, 'Hallo', True)
```

---

# 22. Korrektur des ursprünglichen `addiere`-Beispiels

Diese Funktion:

```python
def addiere(
    a: float,
    *args: float
) -> float:
    return sum(
        args
    )
```

würde bei:

```python
addiere(
    1,
    2,
    3
)
```

nicht `6`, sondern:

```text
5
```

liefern.

Warum?

```text
a → 1
args → (2, 3)
```

Aber die Funktion summiert nur:

```python
args
```

Korrekt wäre beispielsweise:

```python
def addiere(
    a: float,
    *args: float
) -> float:
    return (
        a
        + sum(args)
    )
```

---

# 23. Noch einfacher: nur `*args`

Wenn mindestens ein erster Parameter nicht benötigt wird:

```python
def addiere(
    *zahlen: float
) -> float:
    return sum(
        zahlen
    )
```

Das ist für eine beliebige Anzahl von Summanden einfacher.

Auch:

```python
addiere()
```

ist dann erlaubt und liefert:

```text
0
```

weil:

```python
sum(())
```

`0` ergibt.

---

# 24. Mindestens ein Argument verlangen

Wenn mindestens ein Wert verlangt werden soll:

```python
def addiere(
    erster: float,
    *weitere: float
) -> float:
    return (
        erster
        + sum(weitere)
    )
```

Dann ist:

```python
addiere()
```

nicht erlaubt.

Aber:

```python
addiere(5)
```

ist gültig.

---

# 25. Wann `*args` und wann eine Liste?

Vergleiche:

```python
def mittelwert(
    *werte: float
) -> float:
    ...
```

mit:

```python
def mittelwert(
    werte: list[float]
) -> float:
    ...
```

Aufruf mit `*args`:

```python
mittelwert(
    10,
    20,
    30
)
```

Aufruf mit Liste:

```python
mittelwert(
    [10, 20, 30]
)
```

Welche Variante besser ist, hängt von der Schnittstelle ab.

---

# 26. Entscheidungshilfe: Container oder `*args`?

`*args` ist praktisch, wenn:

```text
die Werte beim Aufruf natürlich als einzelne Argumente erscheinen.
```

Beispiel:

```python
max(
    3,
    8,
    2
)
```

Ein Containerparameter ist praktisch, wenn:

```text
die Werte bereits als Sammlung existieren
oder fachlich eine Sammlung darstellen.
```

Beispiel:

```python
notenschnitt(
    noten
)
```

Nicht jede Liste sollte künstlich in `*args` umgewandelt werden.

---

# 27. Variable Anzahl von Schlüsselwortargumenten

Für beliebig viele benannte Argumente gibt es:

```text
**kwargs
```

Beispiel:

```python
def beschreibe_person(
    name: str,
    alter: int,
    **details: object
) -> str:
    beschreibung = (
        f"{name} ist "
        f"{alter} Jahre alt."
    )

    for key, value in details.items():
        beschreibung += (
            f" {key}: {value}."
        )

    return beschreibung
```

---

# 28. Aufruf mit `**kwargs`

```python
text = beschreibe_person(
    "Anna",
    30,
    beruf="Ingenieurin",
    wohnort="Wien",
    aktiv=True
)

print(text)
```

Die zusätzlichen Schlüsselwortargumente landen in:

```text
details
```

---

# 29. `**kwargs` ist ein Dictionary

Vereinfacht entsteht:

```python
details = {
    "beruf": "Ingenieurin",
    "wohnort": "Wien",
    "aktiv": True
}
```

Der Typ ist:

```text
dict
```

Die Schlüssel sind die Namen der übergebenen Schlüsselwortargumente.

---

# 30. `args` und `kwargs` sind nur Konventionen

Diese Namen sind üblich:

```text
*args
**kwargs
```

aber nicht vorgeschrieben.

Zum Beispiel:

```python
def protokolliere(
    *meldungen: str,
    **optionen: object
) -> None:
    ...
```

ist völlig gültig.

Aussagekräftige Namen können sogar verständlicher sein.

---

# 31. Type Hints bei `*args`

```python
def addiere(
    *zahlen: float
) -> float:
    return sum(
        zahlen
    )
```

Die Annotation:

```text
float
```

bezieht sich auf **jedes einzelne zusätzlich übergebene Argument**.

Innerhalb der Funktion kann man sich `zahlen` konzeptionell vorstellen als:

```text
tuple[float, ...]
```

---

# 32. Type Hints bei `**kwargs`

```python
def optionen(
    **werte: str
) -> None:
    ...
```

Die Annotation:

```text
str
```

bezieht sich auf jeden Wert im entstehenden Dictionary.

Konzeptionell:

```text
dict[str, str]
```

Die Schlüssel sind immer die Namen der Schlüsselwortargumente und damit Strings.

---

# 33. `*args` und `**kwargs` kombinieren

```python
def protokolliere(
    titel: str,
    *meldungen: str,
    **optionen: object
) -> None:
    print(
        titel
    )

    for meldung in meldungen:
        print(
            meldung
        )

    print(
        optionen
    )
```

Aufruf:

```python
protokolliere(
    "Import",
    "Datei geöffnet",
    "Daten gelesen",
    level="INFO",
    speichern=True
)
```

Zuordnung:

```text
titel
→ "Import"

meldungen
→ ("Datei geöffnet", "Daten gelesen")

optionen
→ {
    "level": "INFO",
    "speichern": True
}
```

---

# 34. Die fünf wichtigen Parameterarten

Python unterscheidet fünf grundlegende Parameterarten.

| Art | Beispiel |
|---|---|
| positional-only | `a, /` |
| positional-or-keyword | `a` |
| var-positional | `*args` |
| keyword-only | `*, a` |
| var-keyword | `**kwargs` |

Diese Arten beschreiben:

> Auf welche Weise darf ein Argument an den Parameter gebunden werden?

---

# 35. Positional-or-keyword

Das ist der normale Standardfall:

```python
def funktion(
    a: int
) -> None:
    print(a)
```

Beides ist erlaubt:

```python
funktion(5)
```

und:

```python
funktion(
    a=5
)
```

Darum heißt dieser Parameter:

```text
positional-or-keyword
```

---

# 36. Positional-only mit `/`

Manchmal soll ein Parameter nur durch seine Position übergeben werden.

```python
def differenz(
    a: float,
    b: float,
    /
) -> float:
    return a - b
```

Erlaubt:

```python
differenz(
    10,
    3
)
```

Nicht erlaubt:

```text
differenz(
    a=10,
    b=3
)
```

Der Schrägstrich:

```text
/
```

markiert:

> Alle Parameter davor sind positional-only.

---

# 37. Warum positional-only?

Das kann sinnvoll sein, wenn:

- Parameternamen für den Aufrufer unwichtig sein sollen,
- die Reihenfolge die natürliche Bedeutung ausdrückt,
- die Parameternamen später geändert werden können sollen, ohne Aufrufer mit Schlüsselwortargumenten zu brechen,
- eine API bewusst nur Positionsargumente erlauben soll.

Viele eingebaute Python-Funktionen verwenden positional-only-Parameter.

---

# 38. Keyword-only mit `*`

Manchmal soll ein Parameter ausdrücklich benannt werden.

```python
def formatiere(
    text: str,
    *,
    gross: bool = False,
    trimmen: bool = True
) -> str:
    ...
```

Der einzelne Stern:

```text
*
```

markiert:

> Alle folgenden Parameter sind keyword-only.

---

# 39. Keyword-only verwenden

Erlaubt:

```python
formatiere(
    "  Hallo  ",
    gross=True,
    trimmen=True
)
```

Nicht erlaubt:

```text
formatiere(
    "  Hallo  ",
    True,
    True
)
```

Das kann die Lesbarkeit deutlich verbessern.

---

# 40. Warum keyword-only?

Betrachte:

```python
speichere(
    daten,
    True,
    False,
    True
)
```

Was bedeuten diese drei Wahrheitswerte?

Viel klarer:

```python
speichere(
    daten,
    komprimieren=True,
    backup=False,
    ueberschreiben=True
)
```

Keyword-only-Parameter können erzwingen, dass der aufrufende Code selbsterklärender wird.

---

# 41. Keyword-only-Parameter können erforderlich sein

Ein wichtiger Unterschied:

```python
def senden(
    text: str,
    *,
    empfaenger: str
) -> None:
    ...
```

`empfaenger` besitzt keinen Standardwert.

Er ist daher erforderlich.

Aber er muss als Schlüsselwortargument übergeben werden:

```python
senden(
    "Hallo",
    empfaenger="anna@example.com"
)
```

Damit sieht man:

> „Keyword-only“ bedeutet nicht automatisch „optional“.

---

# 42. Standardwert bedeutet optional – nicht Parameterart

Diese Begriffe müssen getrennt werden.

Ein Parameter kann beispielsweise sein:

```text
keyword-only und erforderlich
```

oder:

```text
keyword-only und optional
```

Beispiel erforderlich:

```python
def f(
    *,
    modus: str
) -> None:
    ...
```

Beispiel optional:

```python
def f(
    *,
    modus: str = "standard"
) -> None:
    ...
```

---

# 43. Nach `*args` werden Parameter automatisch keyword-only

Beispiel:

```python
def verbinde(
    *teile: str,
    separator: str = ", "
) -> str:
    return separator.join(
        teile
    )
```

Aufruf:

```python
text = verbinde(
    "Anna",
    "Ben",
    "Clara",
    separator=" | "
)
```

`separator` kann hier nicht als weiteres Positionsargument erkannt werden, weil `*teile` alle restlichen positionalen Argumente einsammelt.

Darum ist `separator` keyword-only.

---

# 44. Alle wichtigen Arten kombinieren

Eine Funktionsdefinition kann so aussehen:

```python
def beispiel(
    pos1: int,
    pos2: int,
    /,
    normal: int,
    *args: int,
    option: bool = False,
    **kwargs: object
) -> None:
    ...
```

Bedeutung:

```text
pos1, pos2
→ positional-only

normal
→ positional-or-keyword

args
→ beliebig viele weitere Positionsargumente

option
→ keyword-only

kwargs
→ beliebig viele weitere Schlüsselwortargumente
```

Solch komplexe Signaturen sollte man nur verwenden, wenn sie die Schnittstelle wirklich verständlicher machen.

---

# 45. Parameter beim Funktionsaufruf entpacken

Bisher haben wir `*` und `**` in Funktionsdefinitionen gesehen.

Sie können auch beim **Aufruf** verwendet werden.

Das ist die umgekehrte Richtung.

---

# 46. Liste oder Tupel mit `*` entpacken

Gegeben:

```python
def berechne(
    a: int,
    b: int,
    c: int
) -> int:
    return (
        a + b
    ) * c
```

Daten:

```python
werte = [
    2,
    3,
    4
]
```

Statt:

```python
berechne(
    werte[0],
    werte[1],
    werte[2]
)
```

kann man schreiben:

```python
ergebnis = berechne(
    *werte
)
```

---

# 47. Was macht `*` beim Aufruf?

```python
berechne(
    *werte
)
```

entspricht hier ungefähr:

```python
berechne(
    2,
    3,
    4
)
```

Die Elemente werden als einzelne Positionsargumente übergeben.

---

# 48. Dictionary mit `**` entpacken

```python
def person_text(
    name: str,
    alter: int
) -> str:
    return (
        f"{name}, {alter}"
    )
```

Dictionary:

```python
daten = {
    "name": "Anna",
    "alter": 17
}
```

Aufruf:

```python
text = person_text(
    **daten
)
```

entspricht:

```python
person_text(
    name="Anna",
    alter=17
)
```

---

# 49. Schlüssel müssen zu Parametern passen

Bei:

```python
person_text(
    **daten
)
```

müssen die Dictionary-Schlüssel zu akzeptierten Parameternamen passen, sofern die Funktion kein passendes `**kwargs` besitzt.

Beispiel:

```python
daten = {
    "vorname": "Anna",
    "alter": 17
}
```

würde hier wegen:

```text
vorname
```

nicht funktionieren.

---

# 50. Sammeln und Entpacken nicht verwechseln

In der Definition:

```python
def f(
    *args,
    **kwargs
):
    ...
```

bedeutet:

```text
sammeln
```

Beim Aufruf:

```python
f(
    *werte,
    **optionen
)
```

bedeutet:

```text
entpacken
```

Merksatz:

```text
Definition:
* und ** sammeln Argumente.

Aufruf:
* und ** entpacken Sammlungen.
```

---

# 51. Argumente weiterreichen

`*args` und `**kwargs` werden oft verwendet, um Argumente an eine andere Funktion weiterzugeben.

```python
def protokolliert(
    *args: object,
    **kwargs: object
) -> None:
    print(
        "Funktion wird aufgerufen."
    )

    ziel(
        *args,
        **kwargs
    )
```

Das Muster ist besonders bei:

- Wrapper-Funktionen,
- Decorators,
- Bibliothekscode

nützlich.

Für normale Schulprogramme sollte es aber nur eingesetzt werden, wenn es einen klaren Nutzen gibt.

---

# 52. Verständliche Signaturen sind wichtiger als maximale Flexibilität

Diese Funktion akzeptiert fast alles:

```python
def speichern(
    *args: object,
    **kwargs: object
) -> None:
    ...
```

Aber ein Leser weiß kaum:

```text
Welche Daten werden erwartet?

Welche Optionen gibt es?

Welche Typen sind gültig?
```

Eine explizite Signatur ist oft besser:

```python
def speichern(
    dateiname: str,
    daten: str,
    *,
    ueberschreiben: bool = False
) -> None:
    ...
```

> Verwende `*args` und `**kwargs` nicht nur, um sich das Nachdenken über eine gute Schnittstelle zu ersparen.

---

# 53. Type Hints machen Parameter verständlicher

Vergleiche:

```python
def berechne(
    a,
    b=0,
    c=1
):
    ...
```

mit:

```python
def berechne(
    a: float,
    b: float = 0,
    c: float = 1
) -> float:
    ...
```

Die zweite Version zeigt sofort:

- erwartete Eingabetypen,
- Standardwerte,
- Rückgabetyp.

Type Hints erzwingen diese Typen zur Laufzeit nicht automatisch, helfen aber Menschen, IDEs und Type Checkern.

---

# 54. Methoden besitzen ebenfalls Parameter

Betrachte:

```python
class Konto:
    def einzahlen(
        self,
        betrag: float
    ) -> None:
        ...
```

Auch:

```text
self
```

ist ein Parameter.

Beim Aufruf:

```python
konto.einzahlen(
    100
)
```

wird das konkrete Kontoobjekt automatisch als erstes Argument für `self` gebunden.

Vereinfacht:

```text
Konto.einzahlen(
    konto,
    100
)
```

---

# 55. `self` ist kein Schlüsselwort

`self` ist kein reserviertes Python-Schlüsselwort.

Man könnte technisch einen anderen Namen verwenden.

Das sollte man aber nicht tun.

Die Konvention:

```python
self
```

ist so etabliert, dass man sie bei normalen Instanzmethoden immer verwenden sollte.

---

# 56. Parameter und lokale Variablen

Ein Parameter ist innerhalb der Funktion ein lokaler Name.

Beispiel:

```python
def verdoppeln(
    zahl: int
) -> int:
    ergebnis = zahl * 2

    return ergebnis
```

Hier sind:

```text
zahl
→ Parameter

ergebnis
→ lokale Variable
```

Beide Namen existieren in diesem Funktionsaufruf lokal.

---

# 57. Gute Parameternamen

Ungünstig:

```python
def f(
    a,
    b,
    c
):
    ...
```

Wenn die Bedeutung nicht mathematisch offensichtlich ist, sind sprechende Namen besser:

```python
def berechne_gesamtpreis(
    einzelpreis: float,
    anzahl: int,
    rabatt: float = 0
) -> float:
    ...
```

Gute Parameternamen sind Teil einer verständlichen Funktionsschnittstelle.

---

# 58. Schlüsselwortargumente machen Aufrufe lesbarer

Vergleiche:

```python
erstelle_benutzer(
    "Anna",
    True,
    False,
    30
)
```

mit:

```python
erstelle_benutzer(
    "Anna",
    aktiv=True,
    admin=False,
    alter=30
)
```

Die zweite Variante ist leichter zu verstehen.

Noch besser kann bei booleschen Optionen keyword-only sein:

```python
def erstelle_benutzer(
    name: str,
    *,
    aktiv: bool = True,
    admin: bool = False,
    alter: int | None = None
) -> None:
    ...
```

# 59. Eine durchdachte Signatur als Dokumentation

Eine gute Funktionssignatur kann bereits viel erklären:

```python
def exportiere(
    daten: list[str],
    dateiname: str,
    /,
    *,
    format: str = "csv",
    kopfzeile: bool = True
) -> None:
    ...
```

Man erkennt:

```text
daten, dateiname
→ müssen positional übergeben werden

format, kopfzeile
→ müssen benannt werden

format
→ Standard "csv"

kopfzeile
→ Standard True
```

Die Signatur ist damit Teil der Dokumentation.

# 60. Typische Fehler und Missverständnisse

## Parameter und Argument verwechseln

```text
Definition
→ Parameter

Aufruf
→ Argument
```

---

## Normale Parameter nur „positional“ nennen

Ein normaler Parameter:

```python
def f(a):
    ...
```

kann normalerweise sowohl so:

```python
f(5)
```

als auch so:

```python
f(a=5)
```

verwendet werden.

Technisch ist er:

```text
positional-or-keyword
```

---

## Bei `*args` einen normalen Parameter vergessen

Wenn:

```python
def addiere(
    a,
    *args
):
    return sum(args)
```

geschrieben wird, wird `a` nicht automatisch Teil von `args`.

---

## Veränderliche Standardwerte verwenden

Problematisch:

```python
def f(
    liste=[]
):
    ...
```

wenn jeder Aufruf eine frische Liste benötigt.

---

## Optional mit keyword-only verwechseln

```python
def f(
    *,
    wert: int
):
    ...
```

`wert` ist keyword-only, aber trotzdem erforderlich.

---

## `*args` und `**kwargs` überall verwenden

Zu flexible Signaturen machen eine API oft schwerer verständlich.

---

## Container und `*args` unnötig vermischen

Wenn eine Liste bereits fachlich eine Sammlung darstellt, muss man sie nicht zwingend entpacken.

---

## Unklare boolesche Positionsargumente

```python
speichern(
    daten,
    True,
    False
)
```

ist schwer lesbar.

Besser:

```python
speichern(
    daten,
    backup=True,
    komprimieren=False
)
```

## Übung 1 – Preisberechnung mit klarer Signatur

Schreibe eine Funktion:

```text
berechne_preis
```

Regeln:

- `einzelpreis` und `anzahl` sind erforderlich.
- `rabatt_prozent` hat den Standardwert `0`.
- `mwst_prozent` hat den Standardwert `20`.
- Rabatt und Mehrwertsteuer sollen **keyword-only** sein.
- Negative Werte sollen mit `ValueError` abgelehnt werden.

Berechnung:

```text
netto = einzelpreis * anzahl
nach_rabatt = netto * (1 - rabatt / 100)
brutto = nach_rabatt * (1 + mwst / 100)
```

### Lösungsschema

Signatur:

```text
einzelpreis
anzahl
*
rabatt_prozent=0
mwst_prozent=20
```

Der einzelne Stern macht die folgenden Parameter keyword-only.

Prüfungen:

```text
einzelpreis >= 0
anzahl >= 0
0 <= rabatt <= 100
mwst >= 0
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

```python
def berechne_preis(
    einzelpreis: float,
    anzahl: int,
    *,
    rabatt_prozent: float = 0,
    mwst_prozent: float = 20
) -> float:
    if einzelpreis < 0:
        raise ValueError(
            "Einzelpreis darf nicht negativ sein."
        )

    if anzahl < 0:
        raise ValueError(
            "Anzahl darf nicht negativ sein."
        )

    if (
        rabatt_prozent < 0
        or rabatt_prozent > 100
    ):
        raise ValueError(
            "Rabatt muss zwischen 0 und 100 liegen."
        )

    if mwst_prozent < 0:
        raise ValueError(
            "Mehrwertsteuer darf nicht negativ sein."
        )

    netto = (
        einzelpreis
        * anzahl
    )

    nach_rabatt = (
        netto
        * (
            1
            - rabatt_prozent / 100
        )
    )

    brutto = (
        nach_rabatt
        * (
            1
            + mwst_prozent / 100
        )
    )

    return brutto
```

Aufruf:

```python
preis = berechne_preis(
    10,
    3,
    rabatt_prozent=10,
    mwst_prozent=20
)

print(
    round(preis, 2)
)
```

</details>

## Übung 2 – Statistik mit `*args`

Schreibe eine Funktion:

```text
statistik
```

Sie soll mindestens einen Zahlenwert verlangen und zusätzlich beliebig viele weitere Werte akzeptieren.

Rückgabe:

```text
Minimum
Maximum
Mittelwert
```

als Tupel:

```text
tuple[float, float, float]
```

### Lösungsschema

Mindestens ein Wert:

```text
erster
```

Beliebig viele weitere:

```text
*weitere
```

Alle Werte zusammenführen:

```python
werte = (
    erster,
    *weitere
)
```

Dann:

```text
min
max
sum / len
```

<details>
<summary>Vollständige Lösung anzeigen</summary>

```python
def statistik(
    erster: float,
    *weitere: float
) -> tuple[
    float,
    float,
    float
]:
    werte = (
        erster,
        *weitere
    )

    minimum = min(
        werte
    )

    maximum = max(
        werte
    )

    mittelwert = (
        sum(werte)
        / len(werte)
    )

    return (
        minimum,
        maximum,
        mittelwert
    )
```

Verwendung:

```python
ergebnis = statistik(
    10,
    15,
    20,
    5
)

print(
    ergebnis
)
```

</details>

# Zusammenfassung

## Parameter

Ein Parameter steht in der Funktionsdefinition.

```python
def begruessen(
    name: str
) -> str:
    ...
```

`name` ist der Parameter.

---

## Argument

Ein Argument wird beim Funktionsaufruf übergeben.

```python
begruessen(
    "Anna"
)
```

`"Anna"` ist das Argument.

---

## Positional-or-keyword

Normale Parameter können meist durch Position oder Namen gebunden werden.

```python
def f(
    a: int
) -> None:
    ...
```

Beides ist möglich:

```text
f(5)
f(a=5)
```

---

## Standardwert

```python
def f(
    a: int = 10
) -> None:
    ...
```

Der Aufrufer kann das Argument weglassen.

---

## Veränderlicher Standardwert

Vorsicht mit:

```text
=[]
={}
=set()
```

Standardwerte werden nur einmal beim Definieren der Funktion ausgewertet.

Für eine neue Liste pro Aufruf ist häufig besser:

```python
liste: list[int] | None = None
```

---

## `*args`

```python
def f(
    *args
):
    ...
```

sammelt zusätzliche Positionsargumente in einem Tupel.

---

## `**kwargs`

```python
def f(
    **kwargs
):
    ...
```

sammelt zusätzliche Schlüsselwortargumente in einem Dictionary.

---

## Positional-only

```python
def f(
    a,
    /
):
    ...
```

`a` darf nur durch Position übergeben werden.

---

## Keyword-only

```python
def f(
    *,
    a
):
    ...
```

`a` muss durch seinen Namen übergeben werden.

---

## Entpacken

Beim Aufruf:

```python
funktion(
    *liste,
    **dictionary
)
```

werden:

```text
*liste
→ Positionsargumente

**dictionary
→ Schlüsselwortargumente
```

entpackt.

# Das sollst du können

Nach diesem Kapitel solltest du ...

- Parameter und Argumente unterscheiden können.
- erklären können, wie Argumente an Parameter gebunden werden.
- normale positional-or-keyword-Parameter definieren können.
- Funktionen mit Positionsargumenten aufrufen können.
- Funktionen mit Schlüsselwortargumenten aufrufen können.
- beide Aufrufarten sinnvoll kombinieren können.
- Standardwerte definieren und überschreiben können.
- erforderliche und optionale Parameter unterscheiden können.
- den Fehler mit veränderlichen Standardwerten erklären und vermeiden können.
- `*args` für eine variable Anzahl positionaler Argumente verwenden können.
- erklären können, dass `*args` innerhalb der Funktion ein Tupel ergibt.
- `**kwargs` für zusätzliche Schlüsselwortargumente verwenden können.
- erklären können, dass `**kwargs` innerhalb der Funktion ein Dictionary ergibt.
- positional-only-Parameter mit `/` definieren können.
- keyword-only-Parameter mit `*` definieren können.
- verstehen können, dass keyword-only nicht automatisch optional bedeutet.
- komplexere Parameterarten lesen können.
- Listen und Tupel mit `*` beim Aufruf entpacken können.
- Dictionaries mit `**` beim Aufruf entpacken können.
- Sammeln und Entpacken unterscheiden können.
- Type Hints für `*args` und `**kwargs` einordnen können.
- Methodenparameter wie `self` in dasselbe Modell einordnen können.

- typische `TypeError`-Situationen bei Funktionsaufrufen erkennen können.

## Merksätze

```text
Parameter
→ Name in der Funktionsdefinition.

Argument
→ konkreter Wert beim Aufruf.

normaler Parameter
→ meist positional-or-keyword.

Standardwert
→ Argument darf beim Aufruf fehlen.

*args in der Definition
→ sammelt Positionsargumente in einem Tupel.

**kwargs in der Definition
→ sammelt Schlüsselwortargumente in einem Dictionary.

/ in der Definition
→ davor positional-only.

* in der Definition
→ danach keyword-only.

* beim Aufruf
→ Liste oder Tupel als Positionsargumente entpacken.

** beim Aufruf
→ Dictionary als Schlüsselwortargumente entpacken.
```

Der wichtigste Gedanke:

> Eine gute Funktionssignatur beschreibt nicht nur, welche Werte eine Funktion benötigt. Sie legt auch fest, **wie** diese Werte übergeben werden sollen. Durch Standardwerte, positional-only-, keyword-only-, `*args`- und `**kwargs`-Parameter kann eine Schnittstelle flexibel gestaltet werden – die beste Lösung ist aber nicht die flexibelste, sondern diejenige, die für den Aufrufer am klarsten und am schwersten falsch zu verwenden ist.
